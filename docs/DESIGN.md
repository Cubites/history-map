# 역사 지도 (History Map) — 설계 문서

> 상태: 초안 v0.1 · 2026-09-25

## 1. 개요

연도를 고르면 그 시기의 세계 지도가 나라 단위 블럭으로 나타나는 웹 서비스다. 나라를 누르면 그 시기의 사건 목록이 나오고, 사건 위에 마우스를 올리면 그 사건에 영향을 준 나라와 영향을 받은 나라를 화살표로 보여준다.

- **최종 목표**: 전 세계 역사 지도
- **1차 목표**: 지도 틀은 전 세계로 만들고, 데이터는 한국사부터 채운다
- **확장 계획**: 나라 단위에서 지역 단위(도, 주 등)로 내려간다

## 3. 기술 스택

| 영역 | 선택 | 이유 |
|------|------|------|
| 앱 | Vite + React + TypeScript | 정적 빌드, 생태계 |
| 지도 렌더링 | **d3-geo + SVG** (확대/이동은 d3-zoom) | 블럭마다 hover 확대, 화살표 오버레이 같은 자유로운 표현이 쉬움. MapLibre 같은 타일 엔진은 폴리곤 하나만 확대하기가 어려움 |
| 투영법 | Equal Earth, 중앙 경선 동경 120°(태평양 중심), 동아시아 초기 뷰포트 | 면적이 왜곡되지 않아 "국가 크기" 비교가 정확함. 중앙 경선에서 멀수록 지형이 기울어지므로 한국 교과서 세계지도처럼 동아시아를 가운데 둠 |
| 상태 관리 | Zustand | 가벼움. 연도, 선택 나라, hover 사건 정도만 관리 |
| 스키마 검증 | zod | 데이터 빌드와 런타임에서 같은 스키마 사용 |
| 지오 처리 (빌드) | mapshaper, @turf/turf, topojson-server, polylabel | 해안선 클리핑, 단순화, 위상 공유, 화살표 기준점 계산 |
| 국경 작도 도구 | QGIS (무료) | 스냅과 위상 편집으로 이웃 나라 간 틈과 겹침을 방지 |

**성능 전략**: 나라 단위는 한 화면에 폴리곤이 수백 개 이하라 SVG로 충분하다. 지역 단위로 내려가면 폴리곤이 수천 개가 되므로 (1) 확대 수준에 따라 선택된 나라의 지역만 불러오고 (2) 그래도 부족하면 배경 레이어만 Canvas로 옮긴다. 렌더러는 `MapRenderer` 인터페이스 뒤에 둬서 교체할 수 있게 한다.

## 4. 데이터 모델

### 4.1 핵심 개념

```
Entity (나라·지역)  ──1:N──  Territory (기간별 영토 폴리곤)
   │
   ├──N:M── Relation (기간별 관계: part_of, occupied_by, vassal_of, successor_of)
   │
Event (사건) ── subjects / influencedBy / influences ──> Entity
```

**Entity**라는 하나의 개념을 `level`로 나눈다. 나라와 지역을 같은 구조로 다루기 때문에 지역 단위로 확장할 때 모델을 바꿀 필요가 없다.

### 4.2 스키마 (TypeScript 표기)

```ts
type Year = number; // 천문 연도: 기원전 1년 = 0, 기원전 57년 = -56. 표시할 때만 변환한다.

interface Entity {
  id: string;                    // 'silla', 'goguryeo', 'tang', 'gyeonggi-do'
  level: 'polity' | 'region';    // 앞으로 'subregion' 등 추가 가능
  names: { ko: string; en?: string; hanja?: string; [lang: string]: string | undefined };
  from: Year;                    // 존속 첫해 (포함)
  to: Year | null;               // 존속 마지막 해 (포함, 예: 고구려 668). null이면 현재까지
  color?: string;                // 없으면 빌드에서 이웃과 겹치지 않게 자동 배정
  summary?: string;
  basis: {                       // 수록 근거 (D9). level이 'polity'면 필수
    type: 'primary_source' | 'national_institution';  // 사료로 확인 / 그 나라 역사기관이 인정
    refs: string[];              // 예: '삼국유사 권1 기이편', '국사편찬위원회 우리역사넷'
    foundingNote?: string;       // 건국 연대가 전승에 기반한 경우 설명 (예: 고조선 BC 2333)
  };
}

interface Territory {            // GeoJSON Feature의 properties
  entityId: string;
  from: Year;                    // 구간 [from, to)
  to: Year | null;
  certainty: 'confirmed' | 'estimated' | 'disputed';  // 경계 표시 스타일(실선/점선)에 사용
  source: string;                // 출처 (도서, 지도집 등)
}

interface Relation {
  type: 'part_of' | 'occupied_by' | 'vassal_of' | 'successor_of';
  subject: string;               // entityId
  object: string;                // entityId
  from: Year;
  to: Year | null;
}

interface Event {
  id: string;
  year: Year;
  endYear?: Year;                // 전쟁처럼 기간이 있는 사건
  precision: 'year' | 'decade' | 'century';
  title: { ko: string; en?: string };
  summary: { ko: string; en?: string };
  subjects: string[];            // 이 사건이 목록에 나오는 나라·지역
  links: EventLink[];            // 영향 관계 (방향이 있는 화살표)
  location?: { entityId?: string; point?: [lon: number, lat: number] };  // (예정)
  tags?: string[];               // 'war', 'diplomacy', 'culture', ...
  sources: string[];             // 필수
}

interface EventLink {
  from: string;                  // 영향을 준 나라
  to: string;                    // 영향을 받은 나라
  note?: string;                 // "김춘추의 외교" 같은 화살표 라벨
}
```

**`subjects`가 배열인 이유**: 백강 전투처럼 여러 나라에 걸친 사건을 한 번만 작성하고 여러 나라의 목록에 나오게 하기 위해서다.

**영향 관계를 `from → to` 쌍으로 적는 이유**: 처음 설계는 `influencedBy`/`influences` 두 목록이었는데, 이 방식은 "누구 입장에서" 들어오고 나가는지가 사건마다 하나로 고정된다. 여러 나라가 얽힌 사건(예: 백강 전투의 왜·당·신라)에서는 선택한 나라마다 방향이 달라야 하므로, 방향이 있는 쌍으로 적고 화면에서 선택한 나라 기준으로 나눈다.
- 선택한 나라가 `to`인 link → 들어오는 화살표 (파랑 실선)
- 선택한 나라가 `from`인 link → 나가는 화살표 (주황 점선)
- 선택한 나라와 무관한 link → 화살표 없이 목록에만 회색으로 표시

### 4.3 관계와 렌더링 규칙

| Relation | 의미 | 렌더링 |
|----------|------|--------|
| `part_of` | 지역이 나라에 속함 (기간 한정) | 지역 레이어의 계층 구성, 사건 집계 |
| `occupied_by` | 점령·강점 (예: 일제강점기 한국 → 일본) | 자체 색 위에 지배국 색 빗금 |
| `vassal_of` | 종속·책봉 관계 (원 간섭기 등) | 테두리를 지배국 색으로 표시 (빗금보다 약한 표현) |
| `successor_of` | 계승 (고구려 → 발해) | 선택한 나라가 사라진 연도로 이동하면 "후계 국가로 이동" 링크 제공 |

### 4.4 시간 처리

- 모든 데이터는 1년 단위로, 구간 `[from, to)`로 저장한다.
- 연도 Y의 지도는 `from ≤ Y < to`인 Territory들의 모음이다. 국경은 다음 변화가 있을 때까지 유지된다 (스냅샷 + 유효기간).
- 슬라이더는 10년 단위로 움직이지만 내부 상태는 1년 단위다. "다음 변화" 버튼은 빌드 시 계산한 변경 연도 목록으로 이동한다.
- 10년 구간은 `floor(Y / 10) * 10`부터 9년 뒤까지다 (예: 660–669).

## 5. 데이터 제작과 빌드 파이프라인

### 5.1 저장소의 원본 데이터 구조

```
data/
  entities/        # 나라·지역 정의 (YAML, 권역별 파일)
    korea.yaml
    china.yaml
    japan.yaml
    steppe.yaml
  relations.yaml
  events/          # 사건 (YAML, 시대별 파일)
    gojoseon.yaml
    three-kingdoms.yaml
    ...
  geo/             # 영토 폴리곤 (Entity 하나당 GeoJSON 파일 하나, feature마다 기간 속성)
    silla.geojson
    goguryeo.geojson
    ...
  base/            # Natural Earth 해안선·육지 (퍼블릭 도메인)
```

GeoJSON은 QGIS에서 바로 열고 편집할 수 있고, 텍스트 파일이라 git에서 변경 내용을 비교할 수 있다.

### 5.2 국경 작도 방식 (D2 작업량 줄이기)

1. **바다 쪽은 대충 그린다**: 나라 폴리곤을 해안선 바깥 바다까지 넉넉하게 그리면, 빌드 단계에서 Natural Earth 육지와 교차시켜 해안선을 자동으로 정확하게 맞춘다. 사람이 신경 쓸 부분은 **육상 국경선**뿐이다.
2. **이웃 나라와는 스냅으로 공유한다**: QGIS의 위상 편집을 켜서 국경을 공유하게 한다.
3. **변화가 있을 때만 새 버전을 만든다**: 이전 버전을 복사해 바뀐 부분만 고친다.
4. **빌드 검증기가 실수를 잡는다** (§5.3).

### 5.3 빌드 단계 (`npm run build:data`)

```
원본 YAML/GeoJSON
  → ① 스키마 검증 (zod)
  → ② 참조 무결성 검사
        - 사건의 subjects와 links가 가리키는 Entity가 사건 연도에 존재하는가
        - 같은 Entity의 Territory 기간이 서로 겹치지 않는가
        - 존속 기간 안에 영토가 비어 있는 구간이 없는가 (경고)
  → ③ 지오 처리
        - 해안선 클리핑
        - 서로 다른 나라 폴리곤의 겹침 검사 (면적 임계값을 넘으면 오류)
        - 지역이 모든 영토를 덮으면 나라 폴리곤은 지역 폴리곤을 합쳐서 만듦 (§7)
        - 단순화 (확대 수준별 LOD 2~3단계)                      (예정)
        - 화살표 기준점 계산: polylabel (오목한 모양에서도 영토 안쪽에 찍힘)
        - 색상 자동 배정 (이웃 나라끼리 다른 색이 되도록 그래프 채색)   (예정: 지금은 color 미지정 시 기본 팔레트 순환)
  → ④ 출력 (public/data/)
        - timeline.json          : 변경 연도 목록, 구간 → 파일 매핑
        - map/<from>_<to>.topo.json : 구간별 TopoJSON (이웃 국경선을 공유해 용량 감소)
        - entities.json          : 이름, 색, 존속 기간
        - relations.json
        - anchors.json           : 나라별·영토 버전별 화살표 기준점
        - events.json            : 전체 사건 (커지면 시대별 파일로 나눔)
        - base-land-50m.topo.json : Natural Earth 육지
```

- 클라이언트는 현재 연도의 구간 파일을 불러오고, 앞뒤 구간은 미리 불러온다.
- 해안선 클리핑은 화면의 기본 지도와 같은 Natural Earth 1:50m을 쓴다. 해안선이 정확히 겹쳐야 영토와 회색 육지 사이에 틈이 보이지 않기 때문이다.
- 빌드 스크립트는 TypeScript로 작성하고 Node 24의 타입 제거 기능으로 바로 실행한다. 앱과 같은 zod 스키마(`src/schema`)를 쓴다.

### 6.1 블럭 hover
- 해당 path를 1.05배 확대 (`transform-box: fill-box; transform-origin: center`)하고 그림자와 테두리 강조를 더한다. 150ms 전환.
- SVG는 뒤에 그린 요소가 위에 보이므로, 확대한 블럭이 이웃에 가려지지 않게 **최상단 오버레이 레이어에 `<use>`로 복제**해서 보여준다. 원본 순서를 바꾸지 않으므로 다시 그릴 필요가 없다.
- 툴팁으로 국호와 존속 기간을 보여준다.
- `certainty = estimated`인 영토는 점선 테두리로 그린다.

### 6.2 블럭 클릭 → 사건 패널
- 오른쪽 패널에 국호, 존속 기간, 현재 10년 구간의 사건을 보여준다 (D6).
- 사건이 없으면 "이 구간에 등록된 사건 없음"과 함께 가장 가까운 사건으로 가는 링크를 보여준다.
- "이 나라 전체 사건 보기"를 누르면 존속 기간 전체를 연도순으로 보여주고, 현재 구간은 강조한다.
- 연도를 바꿨을 때 선택한 나라가 사라지면 패널에 "이 시기에는 존재하지 않음"을 표시하고 `successor_of` 링크를 보여준다.

### 6.3 사건 hover → 화살표
- **들어오는 화살표** (`to`가 선택한 나라인 link): 영향을 준 나라의 기준점 → 선택한 나라의 기준점. 색 A (파랑 계열)
- **나가는 화살표** (`from`이 선택한 나라인 link): 선택한 나라 → 영향을 받은 나라. 색 B (주황 계열)
- 색만으로 구분하지 않고 **선 모양도 다르게** 한다 (실선과 점선). 색각이상 사용자를 위한 것이다.
- 같은 두 나라 사이에 양방향 화살표가 생기면 서로 반대쪽으로 휜 곡선(2차 베지어)으로 그려 겹치지 않게 한다.
- 화살표 중간에 `note` 라벨을 붙인다.
- 상대 나라가 화면 밖에 있으면 화면 가장자리까지 그리고 국호 라벨을 붙인다.
- 기준점은 **사건 연도 기준**으로 정한다. 현재 화면 연도가 아니라 그 사건이 일어난 해의 영토를 쓴다. 그 해에 영토가 없으면(예: 멸망한 해의 고구려) 시간상 가장 가까운 영토 버전을 쓴다.
- 화살표와 이름표는 확대된 지도 레이어 밖의 화면 좌표로 그린다. 확대해도 선 굵기와 화살촉, 글자 크기가 변하지 않는다.
- 화면 밖 상대 나라를 가장자리 라벨로 표시하는 기능은 아직 없음 (예정).

### 6.4 기타
- **URL 상태**: `?year=668&entity=silla&event=baekgang-663` 형태로 링크 공유
- **모바일**: hover가 없으므로 첫 탭은 hover처럼 확대와 툴팁, 두 번째 탭은 선택. 사건 패널은 하단 시트. 1차 목표는 데스크톱 우선.
- **다국어**: 데이터에 `names`와 `title`의 언어별 필드를 두고, UI 문자열은 i18n 키로 관리. 처음에는 한국어만.

## 7. 지역 단위 확장 설계

처음부터 아래 원칙을 지켜서 나중에 모델을 바꾸지 않게 한다.

1. **지역도 Entity다**: `level: 'region'`으로 두고, `part_of` 관계로 기간별 소속 나라를 지정한다. 역사적 행정구역은 시대마다 다르다 (신라 9주, 고려 5도 양계, 조선 8도, 현대 도). 그래서 "현대 경기도"를 과거로 늘려 쓰지 않고 **시대별 지역 Entity를 따로 만든다**.
2. **나라 폴리곤은 가능하면 지역 폴리곤에서 만든다**: 어떤 기간에 지역이 나라 영토를 모두 덮으면 빌드에서 합쳐서 나라 폴리곤을 만든다. 원본을 하나로 유지해서 둘이 어긋나는 일이 없게 한다. 지역 데이터가 없는 기간에는 직접 그린 나라 폴리곤을 쓴다.
3. **사건은 어느 단위에든 붙일 수 있다**: `subjects`에 지역 id를 넣으면 그 해의 `part_of`를 따라 상위 나라의 목록에도 자동으로 올라간다.
4. **화면 전환**: 선택한 나라를 확대하거나 더블클릭하면 그 나라의 지역 레이어를 불러와 드릴다운한다. 출력 파일도 `map/<level>/<from>_<to>.topo.json` 형태로 단위별로 나눈다.
5. **화살표도 단위를 따른다**: 지역 단위 보기에서는 지역 기준점을 쓴다.

## 11. 수록 기준과 제보 절차

### 11.1 수록 기준 (D9)
- 타임라인은 **BC 2333(천문 연도 -2332)** 부터 시작한다.
- 나라(Entity)는 다음 중 하나를 만족할 때만 추가한다.
  - `primary_source`: 사료로 존재가 확인됨
  - `national_institution`: 그 나라의 공식 역사기관(한국은 국사편찬위원회 등)이 인정함
- 고조선의 건국 연대처럼 전승에 근거한 연대는 `foundingNote`에 그 사실을 적고, 패널에 "건국 연대는 『삼국유사』의 기록에 따름"처럼 보여준다. 초기 영토는 `certainty: 'estimated'`로 점선 표시한다.
- 빌드 검증기는 `basis.refs`가 비어 있는 나라를 오류로 처리한다.

### 11.2 제보 절차 (D10)
- 외부 기여자는 저장소를 직접 수정하지 않는다. **GitHub Issue 양식**으로만 제보를 받는다.
- 이슈 양식의 필수 항목: 대상 연도와 나라, 제보 내용, **증거 사료(서명, 권·쪽 또는 기관 자료 링크)**
- 운영자가 사료를 확인한 뒤 **자기 문장으로 새로 작성해** 반영한다. 제보자의 글을 그대로 복사하지 않는다. 이렇게 하면 모든 데이터의 저작권이 운영자 한 명에게 남아서 나중에 라이선스를 바꿀 수 있다 (§12).
- 반영된 항목의 `sources`에 사료를 적고, 원하면 제보자를 `CREDITS.md`에 기록한다.

## 12. 라이선스 (D11)

| 대상 | 라이선스 | 파일 |
|------|----------|------|
| 소스 코드 (`src/`, `scripts/`) | MIT | `LICENSE` |
| 직접 만든 데이터 (`data/entities`, `data/events`, `data/geo`, `relations.yaml`) | CC BY-NC-SA 4.0 | `data/LICENSE` |
| Natural Earth 해안선 (`data/base`) | 퍼블릭 도메인 | 출처만 표기 |

**데이터에 CC BY-NC-SA 4.0을 고른 이유**
- **BY (출처 표시)**: 다른 곳에서 쓸 때 이 프로젝트를 출처로 밝혀야 한다.
- **NC (비영리)**: 다른 사람이 운영자의 작업물로 상업 서비스를 만들 수 없다. 운영자 본인은 저작권자이므로 이 제한을 받지 않는다.
- **SA (동일 조건)**: 수정해서 배포하면 같은 라이선스를 따라야 하므로 폐쇄된 파생본이 생기지 않는다.
- **나중에 풀 수 있다**: 모든 데이터를 운영자 혼자 작성하므로(§11.2) 나중에 CC BY-SA나 CC BY처럼 더 개방적인 라이선스로 바꿀 수 있다. 반대로 한 번 개방한 버전은 되돌릴 수 없으므로 제한이 있는 쪽에서 시작한다.
- 역사적 사실 자체는 저작권 보호 대상이 아니다. 보호되는 것은 운영자가 쓴 서술 문장과 직접 그린 국경 폴리곤이다.

코드에 MIT를 쓰는 이유는 지도 렌더링 코드는 보호할 가치보다 공개해서 얻는 이점이 크고, 데이터와 분리해 두면 코드만 가져가도 데이터는 따라가지 않기 때문이다.

## 13. 배포 (D12)

- **GitHub Pages + GitHub Actions**: `main`에 push하면 `build:data` → `vite build` → Pages에 배포한다. 빌드 결과물(`public/data/`)은 저장소에 커밋하지 않는다.
- **경로**: 프로젝트 페이지는 `https://<사용자명>.github.io/history-map/`이므로 Vite의 `base`를 `/history-map/`로 설정하고, 데이터 요청도 이 경로 기준으로 만든다.
- **라우팅**: Pages는 SPA 경로 재작성을 지원하지 않으므로 화면 상태는 쿼리 문자열(`?year=668&entity=silla`)만 쓴다 (§6.4와 일치).
- **저장소 공개 여부**: 무료 계정에서 Pages를 쓰려면 저장소가 공개여야 한다. 데이터는 CC BY-NC-SA로 보호된다.
- 빌드 검증(§5.3)이 실패하면 배포하지 않는다.
