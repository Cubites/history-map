# 역사 지도 (History Map) — 설계 문서

> 상태: 초안 v0.1 · 2026-09-25

## 1. 개요

연도를 고르면 그 시기의 세계 지도가 나라 단위 블럭으로 나타나는 웹 서비스다. 나라를 누르면 그 시기의 사건 목록이 나오고, 사건 위에 마우스를 올리거나 사건을 누르면 그 사건에 영향을 준 나라와 영향을 받은 나라를 화살표로 보여준다.

- **최종 목표**: 전 세계 역사 지도
- **1차 목표**: 지도 틀은 전 세계로 만들고, 데이터는 한국사부터 채운다
- **확장 계획**: 나라 단위에서 지역 단위(도, 주 등)로 내려간다

### 3.1 도법을 정한 과정 (D13)

- **처음(P0~P2)**: Equal Earth에 중앙 경선을 동경 120°로 고정했다. 동아시아는 괜찮았지만 유럽·아메리카가 가장자리에서 비스듬히 기울어졌다.
- **지구본**: 모양은 정확하지만 한 번에 지구 절반만 보여서, 나라 사이의 관계를 한눈에 보기 어려워 제외했다.
- **메르카토르(좌우 이어짐)**: 모양이 정확하고 가볍지만, 위도가 높을수록 면적이 크게 부풀려진다(북위 50°에서 약 2.4배, 65°에서 약 5.6배). 북방 유목 제국과 중원 왕조처럼 위도가 다른 세력의 크기를 비교할 수 없게 되어 역사 지도에 맞지 않아 제외했다.
- **채택**: 면적 보존 도법을 유지하되 중앙 경선을 화면 가운데로 계속 옮긴다. 크기는 정확하고, 보는 곳의 모양도 정확하다. 대신 움직일 때마다 지도 전체를 다시 계산해야 해서 아래 성능 대책이 필요하다.
- **위아래 회전(사축)**: 위아래도 도법 회전으로 이으면 극지방까지 왜곡이 줄지만, 고위도에서 북쪽이 기울고 극을 넘으면 뒤집혀 가시성과 조작감이 나빴다 (테스트 후 운영자 판단으로 제외).
- **확대하면 지역 도법으로 (2026-09-26 적용)**: Equal Earth는 위도가 높을수록 모양이 가로로 눌려 유럽·북방 지역이 왜곡된다. 그래서 확대할수록 **람베르트 정적 방위 도법**(보는 곳 중심, 유럽연합 공식 지도 표준 ETRS89-LAEA와 같은 도법)으로 두 도법의 좌표를 섞어 부드럽게 바꾼다 (Jenny 2012, "Adaptive Composite Map Projections"의 방식을 단순화).
  - 두 도법 모두 면적을 보존하므로 나라 크기 비교 원칙이 유지되고, 확대 상태에서도 북쪽은 항상 위다.
  - 바뀌는 시점: 지도 축척(s0·k)이 화면 긴 변의 **0.45배에서 섞기 시작해 0.65배에서 완료** (PC 2096×1102에서 대략 배율 2.5~3.5). 배율 고정값으로 정하면 좁은 모바일 화면에서 지구 반대편 가장자리가 보여서 화면 크기에 대한 비율로 정한다.
  - 자르기: 지역 도법이 절반 넘게 섞이면 경도 180° 선 대신 **중심에서 170° 떨어진 원**으로 자른다 (방위 도법에서는 경도 180° 선이 한 줄로 겹쳐 지도가 사라지기 때문).
  - 섞은 도법은 역변환 공식이 없어 **뉴턴법**으로 화면 좌표 → 경위도를 구한다 (나라 클릭, 끌기, 화면 밖 판정). 되돌리기 오차 0px로 검증.
  - 휠·핀치 확대는 기준점(포인터) 아래의 땅이 제자리에 남도록 시점을 보정한다 (`zoomAround`). 보정 전에는 1.25배 확대마다 11~60px 밀렸고, 보정 후 1px 이내.
  - 시점 저장 방식(중심 경도, 배율, Equal Earth 기준 적도의 화면 y)은 그대로 두고 투영을 만들 때만 섞는다. 그래서 축소 시 지도 끝 붙이기(§6.6)와 버튼 이동은 바뀌지 않았다.

### 3.2 성능 측정과 대책

GDP 상위 50개국 역사를 모두 넣은 상황을 가정한 가짜 데이터(나라 300개, 공유 국경 포함)로, 옆으로 1.5°씩 120프레임을 돌리며 측정했다 (Ryzen 7 5700G, 60Hz, 2096×1102).

| 방식 | 그리는 점 | 한 프레임 계산 | 결과 |
|------|-----------|----------------|------|
| SVG · 1:50m 원본 | 약 16.9만 | 119ms | 7.9fps |
| Canvas · 1:50m 원본 | 약 16.9만 | 117ms | 8.5fps (병목은 그리기가 아니라 도법 계산) |
| Canvas · 1:50m 원본 · 곡선 보정 끔 | 약 16.9만 | 100ms | 9.9fps |
| Canvas · 간략(1:110m + 단순화) | 약 2.1만 | 12.6ms | 60fps |
| Canvas · 간략 · 곡선 보정 끔 | 약 2.1만 | 7.7ms | 60fps |
| Canvas · 초간략 · 곡선 보정 끔 | 약 1.3만 | 5.8ms | 60fps (모바일 예상 35~60fps) |
| SVG · 초간략 · 곡선 보정 끔 | 약 1.3만 | 8.7ms | 60fps |

**대책**
1. **곡선 보정(적응형 재표본화) 끔**: 데이터 점이 이미 촘촘해서 화질 차이가 없고 계산이 약 40% 준다.
2. **정밀도 단계(LOD) 3단계**를 빌드에서 미리 만든다 (`low`: 1:110m + 강한 단순화, `mid`: 1:50m + 약한 단순화, `high`: 1:50m 원본).
   - 움직이는 중: 배율 4 미만 `low`, 12 미만 `mid`, 그 이상 `high`
   - 멈춘 뒤(150ms): 배율 2 미만 `mid`, 그 이상 `high`
3. **화면 밖 도형은 계산하지 않는다**: 영토와 육지 조각마다 경위도 범위를 두고, 화면에 보이는 범위와 겹치는 것만 그린다.
4. **Canvas + SVG 혼합**: 같은 조건에서 Canvas가 SVG보다 약 1.5배 빠르다. 모바일 여유를 위해 무거운 층만 Canvas로 둔다.
5. **확대했을 때는 격자 조각으로 그린다 (2026-09-26 적용)**: 3번만으로는 유라시아처럼 큰 도형이 조금만 보여도 통째로 계산된다. 그래서 `mid`·`high` 단계의 육지와 영토를 10°×10° 조각(칠하기용)과 64점 선 조각(테두리용)으로도 만들어 둔다.
   - 빌드: `land-tiled-<lod>.topo.json`, `geo-tiled/<lod>/<entityId>.topo.json`. 조각과 선 조각을 한 토폴로지로 묶어 용량 증가를 줄인다(정밀 단계 육지 547KB → 965KB). 자르기는 축에 나란한 사각형 전용 알고리즘(Sutherland–Hodgman)으로 해서 빌드 시간이 약 10초 → 18초로 늘어나는 데 그친다 (일반 폴리곤 연산으로는 240초).
   - 앱: 화면에 보이는 경위도 넓이(경도 폭 × 위도 폭)가 **3000도² 이하**일 때만 조각을 불러와 보이는 조각만 그린다. 조각은 자른 면과 따로 그리는 테두리 때문에 점이 약 2배라, 넓게 볼 때는 오히려 느리다(테스트에서 배율 3에서 10 → 21ms). 경도 폭만 기준으로 하면 세로로 긴 화면에서 너무 일찍 켜져서 넓이로 판단한다.
   - 같은 나라의 조각은 한 경로로 칠해 조각 사이 이음매가 보이지 않게 하고, 테두리는 선 조각으로 그려 격자 칸 경계가 드러나지 않게 한다. 클릭 판정과 hover 테두리는 원래 도형을 쓴다.
   - 오목한 도형을 칸으로 자르면 떨어진 부분이 칸 경계 위의 폭 0인 "다리"로 이어진다. 가는 변과 오는 변의 끝점이 다르면 위도선이 휘는 지역 도법에서 두 변이 어긋나 바다 위에 가는 선이 보였다(1946년 발해의 중화민국). 칸 경계를 따라가는 변에 0.5° 눈금마다 점을 넣어 두 변이 겹치게 한다 (격자 파일 약 11% 증가).
   - 측정 (실제 1280년 데이터, 움직이는 중, 370×417 화면): 배율 2·6은 차이 없음(조각 미사용), 배율 9에서 21.0 → 5.1ms, 12에서 25.3 → 5.1ms, 20에서 26.0 → 4.3ms. 가짜 300개국 데이터(2096×1102)에서는 배율 6에서 68.3 → 20.0ms.
6. **확대하면 지역 도법 (2026-09-26 적용, §3.1)의 성능 비용**: 테스트(가짜 300개국, 격자 조각 사용)에서 지역 도법은 Equal Earth보다 약 33% 무거웠다 (배율 6에서 20.0 → 26.7ms). 섞는 구간은 두 도법을 모두 계산해 약 60% 무겁지만 구간을 좁혀 지나는 시간을 줄였다.

## 4. 데이터 모델

### 4.1 핵심 개념

```
Entity (나라·지역)  ──1:N──  Territory (기간별 영토 폴리곤)
   │
   ├──N:M── Relation (기간별 관계: part_of, occupied_by, vassal_of, successor_of)
   │
Event (사건) ── subjects / influencedBy / influences ──> Entity
```

**Entity**라는 하나의 개념을 `level`로 나눈다. 나라와 지역을 같은 구조로 다루기 때문에 지역 단위로 확장할 때 모델을 바꿀 필요가 없다.

### 4.2 스키마 (TypeScript 표기)

```ts
type Year = number; // 천문 연도: 기원전 1년 = 0, 기원전 57년 = -56. 표시할 때만 변환한다.

interface Entity {
  id: string;                    // 'silla', 'goguryeo', 'tang', 'gyeonggi-do'
  level: 'polity' | 'region';    // 앞으로 'subregion' 등 추가 가능
  names: { ko: string; en?: string; hanja?: string; native?: string };  // native: 원어 표기(2026-10-02, 한자 이름이 없으면 그 자리에 보임)
  from: Year;                    // 존속 첫해 (포함)
  to: Year | null;               // 존속 마지막 해 (포함, 예: 고구려 668). null이면 현재까지
  color?: string;                // 없으면 빌드에서 이웃과 겹치지 않게 자동 배정
  summary?: string;
  basis: {                       // 수록 근거 (D9). level이 'polity'면 필수
    type: 'primary_source' | 'national_institution';  // 사료로 확인 / 그 나라 역사기관이 인정
    refs: string[];              // 예: '삼국유사 권1 기이편', '국사편찬위원회 우리역사넷'
    foundingNote?: string;       // 건국 연대가 전승에 기반한 경우 설명 (예: 고조선 BC 2333)
  };
}

interface Territory {            // GeoJSON Feature의 properties
  entityId: string;
  from: Year;                    // 구간 [from, to)
  to: Year | null;
  certainty: 'confirmed' | 'estimated' | 'disputed';  // 경계 표시 스타일(실선/점선)에 사용
  source: string;                // 출처 (도서, 지도집 등)
}

interface Relation {
  type: 'part_of' | 'occupied_by' | 'vassal_of' | 'successor_of';
  subject: string;               // entityId
  object: string;                // entityId
  from: Year;
  to: Year | null;
}

interface Event {
  id: string;
  year: Year;
  endYear?: Year;                // 전쟁처럼 기간이 있는 사건
  precision: 'year' | 'decade' | 'century';
  title: { ko: string; en?: string };
  summary: { ko: string; en?: string };
  subjects: string[];            // 이 사건이 목록에 나오는 나라·지역
  links: EventLink[];            // 영향 관계 (방향이 있는 화살표)
  location?: { entityId?: string; point?: [lon: number, lat: number] };  // (예정)
  tags?: string[];               // 'war', 'diplomacy', 'culture', ...
  sources: string[];             // 필수
}

interface EventLink {
  from: string;                  // 영향을 준 나라
  to: string;                    // 영향을 받은 나라
  note?: string;                 // "김춘추의 외교" 같은 화살표 라벨
}
```

**`subjects`가 배열인 이유**: 백강 전투처럼 여러 나라에 걸친 사건을 한 번만 작성하고 여러 나라의 목록에 나오게 하기 위해서다.

**영향 관계를 `from → to` 쌍으로 적는 이유**: 처음 설계는 `influencedBy`/`influences` 두 목록이었는데, 이 방식은 "누구 입장에서" 들어오고 나가는지가 사건마다 하나로 고정된다. 여러 나라가 얽힌 사건(예: 백강 전투의 왜·당·신라)에서는 선택한 나라마다 방향이 달라야 하므로, 방향이 있는 쌍으로 적고 화면에서 선택한 나라 기준으로 나눈다.
- 선택한 나라가 `to`인 link → 들어오는 화살표 (파랑 실선)
- 선택한 나라가 `from`인 link → 나가는 화살표 (주황 점선)
- 선택한 나라와 무관한 link → 화살표 없이 목록에만 회색으로 표시

### 4.3 관계와 렌더링 규칙

| Relation | 의미 | 렌더링 |
|----------|------|--------|
| `part_of` | 지역이 나라에 속함 (기간 한정) | 지역 레이어의 계층 구성, 사건 집계 |
| `occupied_by` | 점령·강점 (예: 웅진도독부·안동도호부 → 당, 일제강점기 한국 → 일본) | 자체 색 위에 지배국 색 빗금 (구현됨, 화면 기준 7px 간격 대각선). 패널에 "○○의 점령지" 표시 |
| `vassal_of` | 종속·간섭 관계 (원 간섭기 등) | 테두리를 지배국 색으로 굵게 표시 (빗금보다 약한 표현, 구현됨). 패널에 "○○의 간섭·종속" 표시 |
| `successor_of` | 계승 (고구려 → 발해) | 선택한 나라가 사라진 연도로 이동하면 "후계 국가로 이동" 링크 제공 |
| `claimed_by` (2026-09-27) | 귀속 논쟁: 그 지역을 그 나라 땅으로 보는 견해가 있음 (예: 756~926년 요동 → 발해·당·요) | 후보 나라 색을 번갈아 빗금으로 칠함(후보가 하나면 그 나라 색과 주인 없는 땅 색을 번갈아). 후보 나라를 고르면 선택 테두리가 그 나라 영토와 논쟁 지역을 합친 바깥선으로 그려짐. 논쟁 지역 패널에는 "학설에 따라 ○○ 또는 △△의 땅으로 봄", 후보 나라 패널에는 "귀속 논쟁 지역 포함" 링크 |

- 선택·hover 강조 테두리는 같은 두께끼리 모아 **합친 바깥선**으로 그린다: 화면 밖 캔버스에 두 배 두께로 테두리를 그린 뒤 도형 안쪽을 지우면 바깥쪽 절반만 남고, 맞닿은 안쪽 경계는 양쪽에서 지워진다. 논쟁 지역을 포함한 선택, 여러 조각·격자 조각으로 된 영토 모두 안쪽 선 없이 보인다.

### 4.4 시간 처리

- 모든 데이터는 1년 단위로, 구간 `[from, to)`로 저장한다.
- 연도 Y의 지도는 `from ≤ Y < to`인 Territory들의 모음이다. 국경은 다음 변화가 있을 때까지 유지된다 (스냅샷 + 유효기간).
- 슬라이더는 10년 단위로 움직이지만 내부 상태는 1년 단위다. "다음 변화" 버튼은 빌드 시 계산한 변경 연도 목록으로 이동한다.
- 10년 구간은 `floor(Y / 10) * 10`부터 9년 뒤까지다 (예: 660–669).
- **선사 시대** (2026-09-28): 구석기(약 70만 년 전, 연도 -699999)·신석기(기원전 8000년, -7999) 두 단계를 연도 막대 왼쪽에 버튼으로 압축해 둔다(`src/lib/year.ts`의 `PREHISTORY`). 70만 년을 막대에 그대로 붙이면 역사 시대가 한쪽 끝에 몰리기 때문이다. 기원전 2333년에서 −10년·◀을 누르면 신석기 → 구석기로, 반대로 +10년·▶은 다음 단계 → 기원전 2333년으로 간다. 영토는 없고, 사건(`prehistory` 지역)의 `places`에 적은 유적을 점(●)으로 보여 준다(전투 ⊗와 구별). 청동기 시대는 고조선과 겹치므로 연도 막대 안에서 다루고, 고인돌·송국리 등을 같은 점으로 표시한다. 2만 년보다 먼 연도는 "약 70만 년 전"처럼 쓴다.

### 4.5 전쟁 중 전선 (2026-09-27 추가)

연 단위 영토로는 전쟁 중 전선의 움직임이 보이지 않는다 (예: 6·25 전쟁 1950~1953년이 모두 38도선). 그래서 전쟁마다 **날짜별 전선 스냅샷**을 따로 둔다. 네 가지 표현 방법을 시험 페이지로 비교한 뒤, "날짜별 전선 + 단계별 작전 화살표"를 골랐다.

- **데이터** (2026-09-27 2단계에서 일반화): `data/wars/<전쟁 id>.yaml` → 빌드(`scripts/build-data/wars.ts`) → `public/data/wars.json`
  - 전쟁 → 진영(`factions`) · 참전국(`participants`) · 전역(`theaters`) → 전역마다 날짜 스냅샷(`snapshots`)
  - **진영**: `id`, `name`, 대표 나라 `entity`(색·이름표·클릭 대상), 선택 `color`. 두 편으로 고정하지 않는다 (30년 전쟁, 나폴레옹 전쟁처럼 여러 진영).
  - **참전국**: `entity`, `faction`, 선택 `from`/`to`(날짜). 편을 바꾼 나라는 기간을 나눠 두 번 적는다. 사건 패널의 "이 시기의 전쟁"에 쓰인다.
  - **전역**: `id`, `name`, `replaces`(전쟁 보기에서 영토 대신 점령 지역으로 칠할 나라), 선택 `marker`(평소 지도 표시 위치), `bounds`(확대 범위). 세계 대전처럼 동시에 여러 곳에서 싸운 전쟁은 전역을 나눈다.
  - **스냅샷**: `date`, `title`, `summary`와 점령 지역·전선·작전 화살표
    - `split`: 선으로 가르기. 전역 `replaces` 나라들의 (전역 시작 해) 영토를 선의 북·서쪽(`north` 진영)과 남·동쪽(`south` 진영)으로 나눈다. 6·25 전쟁처럼 전선 하나가 움직이는 전쟁에 쓴다.
    - `areas`: 진영별 점령 지역. `entities`(그 나라들의 그 해 영토 전체) 또는 `geojson`(`data/wars/` 기준 경로, QGIS로 그린 폴리곤, 빌드가 해안선으로 자름). 뒤에 적은 지역이 앞의 지역(split 포함)을 덮는다. 백년 전쟁·세계 대전처럼 점령지가 흩어진 전쟁에 쓴다.
    - `lines`: 따로 그을 전선 (split의 선은 자동 포함). `arrows`: `faction`, `path`, `label`.
    - `holds` (3단계): 그 시점의 도시·요새 소속 (`name`, `at`, `faction`). 점령 지역으로 나타내기 어려운 도시 국가의 동맹 소속 등. 진영 색 점으로 그린다.
  - **전역의 진군 경로·전투** (3단계, 2026-09-27)
    - `routes`: `name`, `faction`, `points[]`(`at`, 선택 `date`·`label`). 전쟁 보기에서 고른 날짜까지 지나온 길은 굵게, 남은 길은 흐린 점선, 가장 최근 도착 지점에 화살촉. 날짜 없는 지점은 앞 지점의 날짜를 따른다. 직전 날짜보다 먼저 끝난 경로는 흐리게 그린다(후퇴 뒤의 지난 진격로). 지점 이름은 화면에서 가까우면 건너뛴다. 한니발·알렉산드로스·나폴레옹 1812 같은 원정에 쓴다.
    - `battles`: `name`, `at`, `date`, 선택 `winner`(진영)·`summary`. 고른 날짜까지 일어난 전투만 보이고, 직전 날짜 이후의 전투는 크게 이름과 함께, 지난 전투는 작고 흐리게. 마우스를 올리면 날짜·승리 진영·설명.
    - 경로·전투 색은 화살표와 같은 규칙(첫째·둘째 진영 전용 색, 셋째부터 진영 색).
  - 빌드는 진영마다 점령 지역을 한 덩어리로 합치고, `replaces` 나라의 이름표 위치(그 나라 진영 점령 지역 안쪽)를 계산한다.
  - 작전 화살표 모양: 첫 진영 실선(붉은색), 둘째 긴 점선(남색), 셋째부터 진영 색의 짧은 점선.
- **사건 연결**: 사건의 `front: { war, theater?, date }` (theater가 없으면 첫 전역). 전쟁 보기 중 사건에 마우스를 올리면 그 날짜의 점령 지역과 작전 화살표를 보여 주고, 누르면 그 날짜로 옮긴다.
- **화면 (2026-09-27 개정: 자동 표시 → 골라서 들어가는 "전쟁 보기")**
  - 처음에는 연도가 전쟁 기간에 들어가면 전선을 자동으로 띄웠으나, 같은 해에 전쟁이 여럿이거나(세계 대전, 30년 전쟁) 긴 전쟁(백년 전쟁)이 수십 년 동안 지도를 덮는 문제가 있어 바꿨다. 유명한 전쟁 10개로 점검한 결과는 아래 "확장 계획" 참고.
  - **진입 ① 지도 표시**: 평소 지도에는 그 해에 진행 중인 전쟁마다 교차한 칼 표시와 이름만 둔다(`marker`, 없으면 전선 범위 가운데). 누르면 전쟁 보기가 열린다.
  - **진입 ② 사건 패널**: 고른 나라가 참전한(`participants`, region·sides 나라 자동 포함) 전쟁 중 보고 있는 10년 구간과 겹치는 것을 "이 시기의 전쟁"으로 보여 준다. 전선에 연결된 사건에는 "○○ 전쟁 · 날짜 전선 보기" 링크를 둔다.
  - **전쟁 보기 ③**: 지도 위에 "전쟁 보기 · 이름 / 닫기" 띠가 뜨고, 지도가 `bounds`(없으면 전선 범위 + 여백)로 확대된다. 연도 타임라인은 그 전쟁의 날짜 축으로 바뀐다. `region` 나라의 영토 대신 두 편의 점령 지역·전선·작전 화살표를 그리고, 이름표는 각 편 점령 지역 안쪽에 둔다.
  - 보여 줄 스냅샷: 마우스를 올린 사건의 날짜 → 고른 날짜 → 그 해의 첫 스냅샷(없으면 그 해 이전의 마지막).
  - 닫으면 들어오기 전의 연도와 지도 위치로 돌아간다. 사건 목록의 이동 등으로 전쟁 기간 밖의 연도로 가면 전쟁 보기가 저절로 닫힌다.
  - 주소: `war=korean-war&theater=korea&front=1950-08-31` (theater는 생략 가능).
  - **전투 장소 표시** (2026-09-27): 전쟁 보기를 만들 만큼 전선이 움직이지 않은 전쟁·전투(관산성, 병인·신미양요, 청일 전쟁 등)는 사건의 `places`로 싸운 곳만 적는다. 평소 지도에서 사건 기간(장소에 `year`가 있으면 그 해, 2026-10-06)에 작은 ⊗로 보이고, 누르면 그 해에 있던 나라 가운데 사건의 첫 주체를 골라(그런 주체가 없으면 사건 기간과 주체의 존재 기간이 겹치는 구간에서 가장 가까운 해로 옮겨, `src/lib/events.ts`의 `focusTarget`) 패널에서 그 사건을 보여 준다(영향 화살표 포함). ⚔(전쟁 보기로 들어감)와 구별되게 작게 그리고, 전쟁 보기 안에서는 숨긴다. 같은 ⚔를 쓰면 "누르면 전쟁 보기가 열린다"는 약속이 깨지고, 회색 ⚔ 같은 변형은 구분이 약하며, 전쟁 전체를 한 점에 찍으면 싸운 곳이 여러 군데인 전쟁을 나타낼 수 없어 이 방식을 골랐다.
  - 수십 년에 걸친 전쟁(고구려–수·당, 몽골의 침입)은 다음 해 이후에 시작하는 진군로와 3년보다 오래전에 끝난 진군로·전투를 숨긴다.
- **확장 계획** (유명한 전쟁 10개 점검, 2026-09-27): 펠로폰네소스·포에니·알렉산드로스 원정·몽골 정복·백년 전쟁·30년 전쟁·나폴레옹 전쟁·1·2차 세계 대전·6·25 전쟁
  1. 진입 방식(위) ✅
  2. 데이터 일반화 ✅: 진영(이름·색)과 참전국(참전 기간), 전역(전역마다 지도 표시와 확대 범위), 진영별 점령 지역(면: 나라 영토 또는 GeoJSON). "선으로 가르기"(split)는 보조 기능으로 남김
  3. 진군 경로(날짜 붙은 선)와 전투·거점(점) ✅
- 다른 전쟁(임진왜란, 병자호란 등)도 같은 형식으로 추가할 수 있다.

GeoJSON은 QGIS에서 바로 열어 볼 수 있고, 텍스트 파일이라 git에서 변경 내용을 비교할 수 있다. 지금 `data/geo`는 모두 국경 생성기가 만들므로, 영토를 고칠 때는 geojson이 아니라 생성기의 권역 파일을 고친다(§5.2 5번).

### 5.2 국경 작도 방식 (D2 작업량 줄이기)

1. **바다 쪽은 대충 그린다**: 나라 폴리곤을 해안선 바깥 바다까지 넉넉하게 그리면, 빌드 단계에서 Natural Earth 육지와 교차시켜 해안선을 자동으로 정확하게 맞춘다. 사람이 신경 쓸 부분은 **육상 국경선**뿐이다.
2. **이웃 나라와는 경계를 공유한다**: 처음에는 QGIS의 위상 편집으로 스냅하려 했고, 지금은 국경 생성기에서 이웃 나라가 같은 이름 붙은 선(상수)을 함께 쓴다(5번).
3. **변화가 있을 때만 새 버전을 만든다**: 이전 버전의 도형에서 바뀐 부분만 합집합·차집합으로 고친다.
4. **빌드 검증기가 실수를 잡는다** (§5.3).
5. **국경 생성기** (2026-09-28): 지금의 `data/geo/*.geojson`은 모두 국경 생성기가 만든다(`npm run gen:geo`, 실행할 때마다 `data/geo`의 geojson을 지우고 다시 씀). 이름 붙인 경계선(상수)을 이웃 나라가 함께 쓰고, 합집합·차집합으로 시기별 영토를 조립한다. 임시 폴더에서 쓰던 것을 프로젝트로 옮겼으며, 옮긴 뒤 출력이 이전 `data/geo` 114개 파일과 바이트 단위로 같음을 확인했다. **물을 건너는 선은 바다 점을 거쳐 돌린다**: 직선이 만·반도·해협을 가로지르면 선 반대편 해안이 본토와 떨어진 조각으로 남는다(§5.5).
   - **권역별 파일** (2026-09-29): 한 파일(1,024줄)이던 생성기를 권역별 파일로 나눴다. 식과 계산 순서는 그대로 옮겨 `data/geo` 118개가 바이트 단위로 같고, `check:data`·`check:gaps`·`check:exclaves` 출력도 같다.
     - `scripts/generate-geo.mjs`: 진입 파일. 명령줄 처리만 두고, 권역 목록을 가져와 합치기·채우기·쓰기를 부른다.
     - `scripts/geo/area-list.mjs`: 권역 목록 `AREAS`(2026-09-29 진입 파일에서 옮김). 생성기·빈 땅 검사(`check:gaps`, §5.4)·`check:generator`가 함께 쓴다. `.ts` 스크립트가 가져올 때 tsc가 쓰는 타입 선언은 `area-list.d.mts`에 있다.
     - `scripts/geo/lib.mjs`: polyclip 불러오기와 도형 도우미(`ring`·`P`·`U`·`D`·`I`·`box` 등). 명령줄 인자를 모르므로 다른 스크립트도 권역 파일을 가져다 쓸 수 있다. `polyclip.setPrecision`은 부르지 않는다(0.16.8의 `precision.reset()`이 아무 일도 하지 않아 한 번 켜면 계산 순서에 따라 결과가 달라진다).
     - `scripts/geo/shared.mjs`: 두 권역 이상이 함께 쓰는 경계선과 기본 도형(요하 `L_LIAO`, 중국 `CHINA`, 요동 `LIAODONG`, 연해주 `PRIMORYE`, 흑룡강 `L_AMUR` 등).
     - `scripts/geo/areas/<권역>.mjs`: 권역마다 도형과 나라별 기간 영토(`versions`), 필요하면 빈 땅 채우기(`fillSpecs`)와 빈 땅 검사 구역(`gapZones`, §5.4). 권역 파일은 `data/entities`의 YAML과 짝이다: `korea`·`inner-asia`·`west`·`japan`·`southeast-asia`·`europe`은 같은 이름 YAML, `china`는 `china-early.yaml`·`china.yaml` 두 파일. 예외로 `korea.yaml`의 간도(`gando-disputed`)는 청 도형에서 잘라 만들어 `china.mjs`에 있고, `prehistory`는 영토가 없다.
     - `scripts/geo/engine.mjs`: 모든 권역을 합친 뒤 도는 단계(권역 합치기와 검사, 빈 땅 채우기, 틈새 구멍 메우기, 쓰기)와 빈 땅 검사 구역 모으기(`collectGapZones`). `.ts`가 쓰는 export의 타입 선언은 `engine.d.mts`에 있다.
   - **'권역'과 '지역'**: 권역(area)은 생성기 파일과 `data/entities` 파일을 묶는 단위다. 지역(region)은 §7의 `level: 'region'` Entity(시대별 행정구역, 귀속 논쟁 지역)다. 두 뜻이 섞이지 않게 폴더·목록·함수 이름도 `areas/`·`AREAS`·`mergeAreas`로 쓴다.
   - **층 규칙**: 가져오는 방향은 `lib` < `shared` < 권역이고, 권역 사이 순서는 `AREAS` 순서(`korea` < `inner-asia` < `china` < `west` < `japan` < `southeast-asia` < `europe`)다. 권역 파일은 `lib`·`shared`와 `AREAS`에서 자기보다 앞에 있는 권역 파일만 가져온다(여진·금·몽골·청이 한반도 도형을, 중국 왕조가 초원·만주 도형을, 러시아(2026-10-01부터 `europe`)가 청·조선·외몽골 도형을 빼서 쓴다). `engine`은 `lib`만 가져온다. `area-list`는 등록된 권역 파일만 가져오고, `scripts/geo`의 다른 파일은 `area-list`를 가져오지 않는다(권역 파일이 가져오면 순환). 거꾸로 가져오면 순환이 되어 시작할 때 '초기화 전 접근' 오류로 멈춘다. 아래층이 위층 도형을 써야 하게 되면 그 도형을 `shared`로 내린다. 두 권역이 함께 쓰는 선은 아래쪽 파일(`shared` 또는 앞 권역 파일)에 두고 export해 위쪽 권역이 가져다 쓴다.
   - **`areas/` 폴더 규칙**: 바로 아래에는 권역 파일만 두고, 파일을 두면 `AREAS`에도 등록한다(빠뜨리면 멈춤). 한 권역만 쓰는 도우미 모듈은 `areas/<권역>/` 하위 폴더(폴더 이름 = 등록된 권역 이름)에 두고 그 권역 파일이 가져온다. 도우미 모듈은 그 권역 파일과 같은 층 규칙을 따르고, 도형·선만 둔다(`versions`·`fillSpecs`·`source`·`gapZones`는 권역 파일에만). 두 권역 이상이 쓰는 것은 도우미 모듈이 아니라 앞 권역 파일(export)이나 `shared.mjs`에 둔다. 권역 이름이 아닌 하위 폴더가 있으면 멈춘다.
   - **권역 파일이 내보내는 것**: `versions`(필수, `{ 나라 id: [[from, to, 멀티폴리곤, 확실성?], …] }`, 끝 없음은 `to: null`), `fillSpecs`(선택, 빈 땅 채우기 `[{ id, zone, from, to }]`, 끝 없음은 `to: 3000`), `source`(선택, geojson feature의 출처 문구), `gapZones`(선택, 빈 땅 검사 구역 `[{ name, zone, minus?, from?, to? }]`, §5.4)와 위층 권역이 쓰는 도형. `source`를 내보내지 않으면 지금 문구('중고등학교 한국사 교과서 시대별 지도의 일반적인 경계를 따른 대략적인 추정. 운영자 검수 필요')를 쓴다. `europe`만 `source`(행정구역 조각 기반 근사라는 문구)를 내보내고, 나머지 여섯 권역은 내보내지 않는다. 채우기로 새로 생기는 나라는 그 spec을 가진 권역의 `source`를 받는다. `fill`·`version`·`source`·`gap`으로 시작하는 다른 이름(대소문자 무시, 예: `fillSpec`·`SOURCE`·`FILL_ZONE`·`gapZone`)은 오타로 보고 멈추므로 export하지 않는다.
   - **빈 땅 채우기와 순서**: specs는 `AREAS` 순서로 이어 붙고, 순서가 땅 배분을 정한다(앞 spec이 먼저 채움, 순서를 바꾸면 13~14개 파일이 바뀐 실험이 있음). 지금은 `inner-asia`의 28개(나라 id 20개 가운데 17개는 채우기로만 만들고, 읍루·물길·말갈은 덧붙임)뿐이다. 새 권역의 specs는 끝에 온다. 채우기는 기간마다 그때 살아 있는 나라 가운데 구역의 범위 상자와 겹치는 나라만 빼고, 거른 뒤의 뺄 목록이 같은 기간은 한 번만 계산한다(2026-09-30. 전에는 세계의 모든 나라를 빼서 가짜 나라 100·300개를 유럽에 더하면 채우기가 28.6초·113.8초였고, 지금은 1.7초·2.2초이며 결과 바이트는 같다).
   - **실패해도 지우지 않는다(지우기 전 대조, `--prune`)**: 권역 등록 빠뜨림, `versions`·`fillSpecs`·`source`·`gapZones` 오타, 같은 나라 id가 두 권역에 있음, 다른 권역 나라를 채우는 spec, 같은 채우기 id를 두 권역이 채움, spec 모양 오류, 빈 땅 검사 구역(`gapZones`) 모양 오류, 인자 오타(`--prune` 말고 `-`로 시작하는 인자, 폴더 둘 이상, `package.json`·`data/entities`가 없는 폴더. 예: 줄표를 빠뜨린 `npm run gen:geo prune`)는 `data/geo`를 지우기 전에, 다른 폴더에도 쓰지 않고 멈춘다. 쓰기 직전에는 이번에 쓰지 않을 geojson(권역 파일째 빠짐, 없앤 나라, id를 바꾼 나라의 옛 파일, 생성기 밖에서 손으로 그린 파일)이 있는지 대조해 있으면 멈춘다. 나라를 일부러 없애거나 id를 바꿀 때만 `npm run gen:geo -- --prune`으로 지운다. `--prune`은 손으로 그린 파일도 지우므로 그런 파일은 먼저 권역 파일로 옮긴다(DATA_GUIDE §5). 이 대조는 '지금 있는 파일' 기준이라, 새 권역에서 아직 한 번도 만들지 않은 나라를 빠뜨린 경우는 잡지 못한다(`check:data`의 '영토 데이터 없음' 경고가 잡는다).
   - **파일 사이에서 맞물리는 점** (2026-09-29 정리): 한쪽만 옮기면 틈이나 겹침이 생기는 점은 좌표를 되풀이하지 않고 이름(공유 상수·배열 조각)으로 가져다 쓴다. 나눈 직후에는 다른 파일의 이름과 같은 좌표를 이름 없이 되풀이한 곳이 24묶음 있었고, 그 가운데 맞물리는 19묶음을 이름 참조로 바꿨다(값이 같아 `data/geo` 118개와 세 검사 출력이 바이트 단위로 같다). 새로 둔 이름은 `shared`의 방천 3국 접경 `TUMEN_TRIPOINT`·우수리강 `L_USSURI`·두만강 하구 앞바다 점 `TUMEN_SEA`(간도·압록강 두만강선·연해주·러시아), 흑룡강 띠 남쪽 변 `L_KHITAN_N`·`L_BALHAE_N`(거란·발해 북쪽 경계), 연운 16주 북쪽 끝 `YANYUN_N`(거란), 북위 33°선 `L33`(금·남송 상자), `korea`의 쌍성총관부·동녕부 경계 `L_SSANGSEONG_W`(동하), `inner-asia`의 몽골 초원 북쪽 변 `ET_NORTH`(러시아)이고, 이미 있던 `HEXI_W`·`L_YALU_TUMEN`·`MN_SW`는 export해 신장 동쪽 경계·간도·동만주 링·러시아가 가져다 쓴다. 남은 5묶음(발해 앞바다↔러시아, 요동 앞바다↔고조선 초기·연, 화북 상자↔요하 서쪽 초원 상자, 동돌궐↔4군 상자, 만주 동북부↔연해주)은 값만 같고 맞물리지 않은 점(바다 쪽 점, 결과에 드러나지 않는 자르기 상자 모서리)이라 이름으로 묶지 않고 '값만 같은 점' 주석을 달았다(따로 옮겨도 틈·겹침이 생기지 않음). 맞물리는데 이름으로 바꾸면 바이트가 달라져 값으로 둔 점('값으로 맞춘 점')은 없다. 새 선을 그을 때도 다른 파일의 좌표를 베끼지 말고 이름을 가져다 쓴다. 이 규칙은 `check:generator`가 지키는지 본다: `scripts/geo`의 `.mjs`에서 `[수, 수]` 좌표 리터럴을 최상위 이름별로 모아(주석은 빼고), 서로 다른 파일의 이름이 같은 좌표를 되풀이하는 묶음이 허용 목록(`scripts/check-generator.mjs`의 `ALLOWED_REPEATS`, 지금은 위 5묶음을 좌표와 이름으로 적음) 밖에 있으면 실패한다. 새 권역이 다른 파일의 좌표를 베끼거나, 목록의 점을 다른 이름이 또 쓰면 실패하고, 목록에 있는데 사라진 묶음도 실패로 알린다(목록과 이 문단에서 지운다). 맞물리지 않는 점을 새로 두면 양쪽 이름 위에 '값만 같은 점' 주석을 달고 목록과 이 문단에 더한다.

   - **검사 도구**: `npm run check:generator`는 구조(층 규칙, `polyclip-ts`는 `lib`에서만, `scripts/geo`는 명령줄 인자를 모름, 권역 등록, `data/geo` 평면 폴더, 타입 선언(`.d.mts`)과 export가 맞음, `check-gaps.ts`에 좌표 복사가 없음, 파일 사이 좌표 되풀이가 허용 목록뿐이고 가짜 파일이 다른 파일 좌표를 베끼면 잡는지)와 위의 멈춤 경우·`--prune`·권역 `source`·빈 땅 검사 구역(`AREAS` 순서로 모임, 새 권역의 구역이 끝에 붙음, 모양 오류에서 멈춤)을 `data/geo`를 임시 폴더에 복사해 시험한다(`gen:geo` 뒤 약 15초, 프로젝트의 `data/geo`는 건드리지 않음). 생성기를 고친 뒤와 권역을 더한 뒤에 돌린다. `npm run compare:geo [-- 기준 폴더]`는 git HEAD(또는 기준 폴더)의 geojson과 지금 `data/geo`를 나라·기간별 대칭차 면적으로 비교한다.
   - **새 권역 더하기** (예: 유럽). 작업 순서·조각 쓰는 법·라이선스 규칙·남은 위험을 묶은 안내는 `docs/REGION_GUIDE.md`(2026-09-30)에 있다:
     1. `data/entities/europe.yaml`과 `scripts/geo/areas/europe.mjs`를 짝 짓는다. 처음에는 `lib`·`shared`만 가져오는 잎으로 시작하고, 근거가 한국사 교과서가 아니면 `export const source = '…'`를 둔다. 비어 있으면 안 되는 지역은 `export const gapZones = [{ name: '유럽', zone: P(링) }]`로 내보내면 2단계의 `AREAS` 등록만으로 `check:gaps`가 검사한다(`check-gaps.ts`는 고치지 않음, §5.4). 유럽 안의 시대별 행정구역(§7의 지역)도 이 권역 파일에서 만든다(단 §7 6번의 배타 가정을 먼저 볼 것).
     2. `scripts/geo/area-list.mjs`에 import 한 줄을 넣고 `AREAS` 끝에 `['europe', europeArea]`를 더한다(생성기·`check:gaps`·`check:generator`가 이 목록을 함께 쓴다). 나라를 더하기만 하므로 `--prune`은 필요 없다.
     3. 두 권역 이상이 쓸 선은 먼저 값이 같은 이름 붙은 선으로 아래쪽 파일(`shared.mjs`, 또는 앞 권역 파일에서 export)에 빼는 단계를 따로 하고 바이트가 같은지 확인한다. 러시아·소련·러시아 연방은 2026-10-01에 `west`에서 `europe`로 옮겨, 손 도형(`RUSSIA_RAW` 등)과 조각이 한 파일에 있다(그래서 `domain`은 `shared`로 내리지 않았다). 다른 파일의 좌표를 베껴 적으면 `check:generator`가 '파일 사이 좌표 되풀이'로 실패한다.
     4. `npm run gen:geo` 뒤 `git status data/geo`로 기존 118개 파일이 그대로인지 본다(새 파일만 늘어야 함). **기존 파일이 바뀌었으면** `npm run compare:geo`로 기간마다 대칭차 면적이 0인지 확인한다. polyclip 차집합은 결과의 꼭짓점을 다시 정리하므로(가까운 꼭짓점 합치기, 일직선 위 점 빼기), 빈 땅 채우기가 새 나라를 빼는 것만으로 도형은 같은데 바이트가 바뀔 수 있다. 바뀔 수 있는 것은 채우기로 만들거나 덧붙이는 나라의 파일이다. 채우기는 구역의 범위 상자와 겹치는 나라만 빼므로(2026-09-30) 채우기 구역과 범위가 겹치는 나라를 더할 때만 해당하고, 구역에서 먼 나라는 채우기 결과에 영향이 없다. 면적이 모두 0이면 새 기준으로 받아들이고, 0이 아니면 새 나라가 실제로 기존 영토와 겹치는지 조사한다. 이 받아들이기는 나라를 더하는 커밋과 나눈다.
     5. `npm run check:generator`, `npm run check:data`, `npm run check:gaps`, `npm run check:exclaves`를 돌린다. 조각 파일을 다시 만들었으면 `npm run check:fragments`(조각 겹침·빈틈·해안 맞춤·현대 나라와의 대칭차, 약 100초)도, 근현대 버전은 `npm run compare:cshapes`(`.cache/`의 CShapes 2.0과 대칭차 비교, 좌표는 저장소에 쓰지 않음)도 돌린다.
     - 채우기 비용 대책은 유럽보다 먼저 따로 넣었다(2026-09-30, `engine.mjs`): 채우기에서 빼는 나라를 구역 범위 상자로 거르고, 거른 뒤의 뺄 목록이 같은 기간은 결과를 다시 쓰며, 틈새 구멍 메우기도 구멍 범위 상자와 떨어진 나라는 교집합을 구하지 않는다. 먼 나라를 빼던 차집합이 하던 꼭짓점 정리를 뺄셈 끝에 한 번(`D(gap)`) 해서 `data/geo` 118개와 `check:data`·`check:gaps`·`check:exclaves` 출력이 바이트 단위로 같다(정리 없이 거르면 `mongolia.geojson` 1921~ 한 버전이 1921~1946·1946~ 둘로 나뉘어 `check:data`의 영토 수가 바뀐다. 도형은 같음).
   - **연산 메모와 병렬 미리 계산** (2026-10-03, `lib.mjs`): polyclip 합집합·차집합·교집합 결과를 입력 열쇠(연산 결과는 연산 이름 + 입력 열쇠, 조각 합치기는 조각 파일 해시 + 조각 id, 그 밖의 배열은 내용 해시)로 `.cache/geo-ops/`에 두고 같은 입력이면 읽는다. 열쇠에는 코드 판(`lib.mjs` 원문, polyclip-ts·bignumber.js·topojson-client의 판과 파일 해시, Node 판)이 들어가 코드가 바뀌면 다시 계산하고, 캐시 파일 머리의 내용 해시가 맞지 않으면(깨진 파일) 다시 계산한다. 무거운 연산은 worker_threads로 미리 계산해 메모에 넣고(유럽의 단위 목록 합치기·러시아 바깥 자르기·빈 땅 검사 구역, 틈새 구멍 판정), 생성기는 원래 순서대로 같은 연산을 불러 메모에서 읽는다(worker 수는 환경 변수 `HISTORY_MAP_WORKERS`, 0이면 worker 없이, 없으면 min(8, 논리 프로세서 수). worker가 오류·exit로 멈추거나 3분 동안 끝난 일이 없으면 stderr에 알리고 오류로 멈춘다). polyclip-ts는 같은 입력에 같은 결과를 내므로 캐시가 없을 때와 `data/geo`·검사 출력이 바이트 단위로 같다. 진입 파일은 인자를 본 뒤 권역 목록을 동적 import로 불러온다(인자 오타로 멈출 때 권역 계산을 기다리지 않음). `gen:geo` 약 75초 → 캐시 없이 약 27초, 캐시가 있으면 약 5초(권역 파일 하나를 고치면 영향받는 연산만 다시 계산, 탕드 점 하나를 옮긴 시험에서 약 6초). 도형은 만든 뒤 고치지 않는다(열쇠가 객체마다 한 번 정해짐). 캐시는 지워도 결과가 같고, 오래된 항목은 지우지 않으므로 커지면 `.cache/`를 지운다.

### 5.3 빌드 단계 (`npm run build:data`)

```
원본 YAML/GeoJSON
  → ① 스키마 검증 (zod)
  → ② 참조 무결성 검사
        - 사건의 subjects와 links가 가리키는 Entity의 존재 기간이 사건 기간(year~endYear)과 겹치는가 (2026-10-06에 '사건 연도에 존재'에서 넓힘, DATA_GUIDE.md §3)
        - 같은 Entity의 Territory 기간이 서로 겹치지 않는가
        - 존속 기간 안에 영토가 비어 있는 구간이 없는가 (경고)
  → ③ 지오 처리
        - 해안선 클리핑
        - 서로 다른 나라 폴리곤의 겹침 검사 (면적 임계값을 넘으면 오류)
        - 지역이 모든 영토를 덮으면 나라 폴리곤은 지역 폴리곤을 합쳐서 만듦 (§7)   (예정: 아직 없음, §7 6번)
        - 정밀도 단계(low/mid/high)별로 육지와 모든 영토 버전을 **하나의 토폴로지**로 묶어 단순화 (§3.2)
        - 화살표 기준점 계산: polylabel (오목한 모양에서도 영토 안쪽에 찍힘)
        - 색상 자동 배정 (이웃 나라끼리 다른 색이 되도록 그래프 채색)   (예정: 지금은 color 미지정 시 기본 팔레트 순환)
  → ④ 출력 (public/data/)
        - timeline.json              : 타임라인 범위, 지도가 바뀌는 연도 목록
        - territories.json           : 영토 버전 목록 (나라, 기간, 확실성, 기준점, 경위도 범위)
        - geo/<lod>/<entityId>.topo.json : 나라별 영토 도형 (버전마다 한 번씩만 저장)
        - land-<lod>.topo.json       : Natural Earth 육지
        - entities.json, relations.json
        - events.json                : 전체 사건 (커지면 시대별 파일로 나눔)
```

- **영토는 나라별로 한 번씩만 저장한다.** 처음에는 국경이 바뀔 때마다 세계 전체 지도를 파일 하나로 만들었는데, 50개국 규모에서는 바뀌지 않은 나라까지 수천 번 반복 저장되어 0.3~1.2GB(GitHub Pages 한도 1GB)가 될 것으로 추정됐다. 지금은 브라우저가 `territories.json`에서 그 해의 버전을 골라 나라별 파일을 모아 그린다. 한 번 받은 파일은 다른 연도에서도 다시 쓴다.
- **단계마다 하나의 토폴로지로 묶는 이유**: 이웃 나라가 공유하는 국경과 버전 사이에 바뀌지 않은 국경이 한 번만 저장되고, 단순화해도 공유 경계가 양쪽에서 똑같이 바뀌어 틈이나 겹침이 생기지 않는다. 나라별 파일은 이 토폴로지에서 필요한 선만 골라 나눈 것이라 좌표가 정확히 일치한다.
- 해안선 클리핑은 화면의 육지와 같은 Natural Earth를 쓴다(`low`는 1:110m, 나머지는 1:50m). 해안선이 정확히 겹쳐야 영토와 회색 육지 사이에 틈이 보이지 않기 때문이다.
- 빌드 스크립트는 TypeScript로 작성하고 Node 24의 타입 제거 기능으로 바로 실행한다. 앱과 같은 zod 스키마(`src/schema`)를 쓴다.
- **계산 캐시와 병렬 처리** (2026-10-03, `scripts/build-data/cache.ts`·`tasks.ts`·`worker.ts`): 해안선 자르기(1:50m·1:110m), 겹침 넓이, 빈 땅 검사의 연도별 줄을 worker_threads(기본 min(8, 논리 프로세서 수), 환경 변수 `HISTORY_MAP_WORKERS`, 0이면 worker 없이)로 나눠 계산하고 결과를 입력 해시 열쇠(계산 코드 원문·패키지 판과 파일 해시·육지 파일·Node 판·숫자 표기 로캘 포함)로 `.cache/build-data/`에 둔다. 결과 없이 끝난 worker는 오류로 멈춘다. `build:data`·`check:data`·`check:exclaves`는 같은 자르기를 함께 쓰고, `gen:geo`가 바꾼 나라만 다시 계산한다. 결과는 입력 순서대로 모으므로 캐시·worker 수와 상관없이 출력이 바이트 단위로 같다. 16스레드 PC에서 캐시 없이 `build:data` 약 280초 → 약 85초, `check:gaps` 약 260초 → 약 65초(`gen:geo` 뒤), `check:exclaves` 약 140초 → 약 2초(`build:data` 뒤), 캐시가 있으면 `build:data` 약 16초. worker 8개일 때 최대 메모리는 약 3GB다(worker 2개면 약 1.2GB).
  - 2026-10-05 보강: 빈 땅 검사를 연도별 줄(`gapsYear`)에서 (구역, 해) 칸(`gapsZone`)으로 나눴다(§5.4). 코드 판에 polyclip-ts가 쓰는 splaytree-ts의 판과 파일 해시를 더하고 형식 번호를 올려(`build-data cache 3`) 기존 캐시는 한 번 다시 계산한다. 환경 변수 `HISTORY_MAP_CACHE=0`이면 캐시를 읽지도 쓰지도 않는다(결과는 같고 느릴 뿐). worker 하나가 오류·exit로 멈추면 나머지 worker도 바로 끝내고 오류로 멈추며(전에는 남은 worker가 남은 계산을 다 할 때까지 기다렸다), 3분 동안 끝난 계산이 없으면(메모리 부족 등) 기다림을 그만두고 오류로 멈춘다(`lib.mjs`의 병렬 미리 계산과 같은 3분). 캐시 파일은 임시 이름으로 쓴 뒤 옮기므로 쓰다가 죽어도 반쯤 쓴 파일을 읽지 않고, 머리의 내용 해시가 맞지 않는 파일은 없는 것으로 보고 다시 계산한다.

### 5.x 데이터 파일 캐시 (2026-09-27 추가)

`public/data/`의 파일은 이름에 해시가 없어 브라우저가 이전 배포본을 잠시(GitHub Pages 기본 약 10분) 저장해 쓴다. 그래서 배포 직후 새 프로그램이 이전 데이터를 읽어 오류가 나거나(전선 이름표 위치가 없어 화면이 멈춤), 새 나라가 칠해지지 않았다. 빌드 시각으로 만든 버전을 데이터 주소 뒤에 붙여(`?v=…`, `vite.config.ts`의 `__DATA_VERSION__`) 프로그램과 데이터가 늘 같은 빌드끼리 쓰이게 한다.

그래도 배포 전에 열어 둔 화면은 예전 프로그램이 그대로 남아, 새로 받는 데이터와 맞지 않을 수 있다(`?v=`는 쿼리라 서버가 무시하고 새 파일을 준다). 그래서 창으로 돌아올 때와 5분마다 `index.html`의 프로그램 파일 이름을 비교해, 바뀌었으면 머리글 아래에 "새 버전이 나왔습니다 · 새로 고침" 알림을 띄운다(`src/UpdateNotice.tsx`, 2026-09-28).

### 5.5 월경지 검사 (2026-09-28 추가)

생성기 좌표에서는 바다를 통해 본토와 이어져 보이던 조각이, 빌드에서 해안선으로 자를 때 떨어져 나와 "월경지"처럼 보이는 문제가 있었다(56조각). 27곳을 조사해 보니 실제 근거가 있는 것은 4곳뿐이었다(1592년 조선의 전라도, 러시아의 관동주 1898~1905, 1938년 광둥 점령지, 미국의 알래스카). 나머지는 직선 경계가 만·반도를 가로지르거나, 이웃 도형이 경계선을 따로 그어 쐐기가 남거나, 빈 땅 채우기가 자투리를 넘긴 부산물이었다. 뒤에 중일 전쟁 점령지의 1937년 도형을 더하면서 1937년 말 화중 점령지(상하이~난징~항저우, 쉬저우를 사이에 두고 화북 점령지와 떨어짐)를 넣어 허용 목록은 5곳이 되었다(2026-09-28).

- **검사** (`scripts/build-data/exclaves.ts`): 해안선으로 자른 영토를 조각으로 나눠, 대표점이 들어 있는 육지 덩어리별로 묶는다. 덩어리마다 가장 큰 조각을 본토로 보고 나머지(5km² 이상)를 떨어진 조각으로 본다. 섬 조각은 떨어진 조각이 아니다.
- **허용 목록** (`data/exclaves.yaml`): 실제로 떨어져 있던 영토를 나라·기간·위치(`at`, 그 조각 안의 한 점)·근거와 함께 적는다. 면적이 아니라 위치로 허용한다.
- **빌드**: 허용 목록에 없는 30km² 이상 조각을 알린다. 부산물을 모두 고칠 때까지는 경고로 두고(`EXCLAVES_ARE_ERRORS = false`), 다 고치면 오류로 바꾼다. 어떤 조각에도 맞지 않는 허용 항목도 경고한다.
- **목록**: `npm run check:exclaves [-- 최소넓이]`가 허용된 것까지 모든 떨어진 조각을 보여 준다.
- **자동으로 이웃 나라에 붙이거나 버리지 않는다**: 이웃이 지도에 없는 곳(알래스카 팬핸들)은 실제 영토가 사라지고, 경계가 틀린 곳(하산)은 오히려 반대 나라에 붙는다. 빌드는 잡아내기만 하고 고치는 것은 생성기에서 한다.

### 5.4 영토 공백 검사 (2026-09-27 추가)

`npm run check:gaps [-- 최소넓이]`: 연도마다 검사 구역에서 어느 나라에도 속하지 않은 육지를 찾는다. 공백이 모두 오류는 아니므로 사람이 판단한다.

- **검사 구역은 생성기 권역 파일이 내보낸다** (2026-09-29): 권역 파일의 `export const gapZones = [{ name, zone, minus? }]`를 권역 목록(`scripts/geo/area-list.mjs`의 `AREAS`) 순서대로 모아(`engine.mjs`의 `collectGapZones`) 그 순서로 검사하고 출력한다. `name`은 출력에 나오는 구역 이름, `zone`은 멀티폴리곤(링 하나면 `P(링)`, 해안선으로 잘라 씀), `minus`는 앞에 모은 구역 이름의 배열(검사 범위에서 그 구역을 뺌)이다. 전에는 `check-gaps.ts`가 생성기 링(`KOREA`·`EASTERN_TURKS`·`ALXA`·`QH_N`)을 좌표로 복사해 두어, 생성기 경계를 고치면 손으로 맞춰야 했고 어긋나도 결과만 조용히 달라졌다. 옮긴 뒤에도 출력은 바이트 단위로 같다.
  - `korea`: 한반도(압록강·두만강 이남, 제주 포함, `KOREA`)
  - `inner-asia`: 만주(요서~흑룡강 이남 상자에서 한반도를 뺀 곳), 몽골(동돌궐 영역 `EASTERN_TURKS`에서 만주를 뺀 곳), 알라산·칭하이(`ALXA`·`QH_N`, 2026-09-29 추가)
  - `europe`: 유럽(권역 바깥선 `domain`, 2026-10-01 추가). 아직 나라가 없는 시대가 대량으로 보고되지 않게 구역의 `from`·`to`(검사하는 해 [from, to), 없으면 모든 해)로 뼈대를 채운 1200년부터 지금까지만 검사한다(2026-10-02, 작업 E2에서 1815~1914, 작업 E3에서 1789년까지, 2026-10-03 작업 B1에서 1945년까지, 같은 날 작업 B2에서 1991년까지, 2026-10-04 작업 A에서 지금까지, 2026-10-06 작업 D1에서 1700년까지, 같은 날 작업 D2에서 1600년까지, 같은 날 작업 D3에서 1526년까지, 같은 날 작업 D4에서 1453년까지, 2026-10-07 작업 M1에서 1400년까지, 같은 날 작업 M2에서 1300년까지, 같은 날 작업 M3에서 1200년까지. 시작 해는 가장 이른 소유표의 첫 해, 마지막 구역은 끝이 없음). 구역은 조각 소유표에서 주인 없는 땅(스발바르·얀마옌·프란츠요제프 제도, 1828년 전 에리반·나흐치반, 러시아에 합쳐지기 전의 조지아·아제르바이잔·다게스탄(1724~1734년은 오스만·러시아), 1773년까지 카바르다·체첸·잉구시·북오세티야, 1742년까지 오렌부르크주의 우랄강 남쪽·동쪽 초원, 1612년부터 페르시아령 아르메니아·아제르바이잔, 1799년까지 몰타, 1918~1938 하타이)을 뺀 것이라 그 땅이 바뀌는 해마다 나뉜다('유럽 1600~1611' … '유럽 1929~1938', 주인 없는 땅이 없는 1939년부터는 권역 바깥선 전체인 '유럽 1939~'). 2026-10-04 운영자 승인으로 영국 식민지(지브롤터·몰타·키프로스·영국 주권 기지 지역)를 영국 땅으로 칠해 더는 비우지 않는다
- **새 권역**: 비어 있으면 안 되는 지역은 그 권역 파일이 `gapZones`만 내보내면 된다. `AREAS`에 등록하기만 하면(§5.2 새 권역 더하기 2단계) `check-gaps.ts`를 고치지 않아도 `AREAS` 순서대로 끝에 붙어 검사된다. `AREAS`에 등록하지 않은 권역 파일은 `check:gaps`가 보지 못해 조용히 빠지므로, 등록 누락은 `gen:geo`와 `check:generator`가 멈춰 잡는다. 앞 구역과 겹치면 `minus`로 뺀다. 구역 이름이 겹치거나, `zone`이 닫힌 링의 멀티폴리곤이 아니거나, `minus`가 앞에 없는 구역을 가리키거나, `gapZone` 같은 이름 오타가 있으면 `check:gaps`와 생성기가 멈춘다(생성기는 `data/geo`를 지우기 전에). `check-gaps.ts`는 `.mjs`를 타입 선언(`area-list.d.mts`·`engine.d.mts`)을 거쳐 가져오고, `npm run check:generator`가 선언과 export가 맞는지, `check-gaps.ts`에 좌표 복사가 없는지, 새 권역의 구역이 끝에 모이는지를 본다.
- **칸 단위 계산과 캐시** (2026-10-05): 검사를 (구역, 해) 칸마다 하고(`tasks.ts`의 `gapsZone`) 결과를 §5.3의 계산 캐시(`.cache/build-data/`)에 둔다. 칸의 입력은 구역 이름, 구역 도형(해안선으로 자르고 `minus`를 뺀 것)의 내용 해시, 그해 그 구역과 범위 상자가 겹치는 영토(파일 순서)의 내용 해시, 최소 넓이다. 열쇠에는 여기에 코드 판(§5.3: `tasks.ts` 등 계산 코드 원문, polyclip-ts·bignumber.js·splaytree-ts·world-atlas 육지의 판과 파일 해시, Node 판, 숫자 표기 로캘)과 `check-gaps.ts` 원문이 더해진다. 해안선·구역 모양·`minus`는 구역 도형의 내용 해시에 들어 있다. 그래서 나라 하나를 고치면 그 나라가 걸친 구역의 그 나라가 있는 해만 다시 계산하고, 한 구역에서 걸친 영토가 같은 해들은 한 번만 계산한다(253개 해, 칸 1,112개, 서로 다른 계산 643개). 범위 상자가 떨어진 영토는 구역 안을 덮지 못하므로 빼도 공백이 같다. 전에는 해 단위로 캐시해(그해 세계의 모든 영토를 합쳐 모든 구역을 검사) 북한을 고쳐도 1946년부터의 해마다 유럽 나라까지 합치기를 다시 했고, 유럽 나라를 고쳐도 그해 한반도·만주까지 다시 계산했다. 출력은 연도 순서, 한 해 안에서는 구역 순서이고 2026-10-04까지와 바이트 단위로 같다(캐시 없음·있음·일부 깨짐, 나라 하나를 조금 옮김·버전 하나를 지워 공백을 만듦, worker 0개에서 확인). stderr에 칸 수와 캐시에서 읽은 수를 한 줄 적는다. 16스레드 PC에서 계산 캐시 없이 약 108초 → 약 61초(`.cache` 전체가 없으면 약 131초 → 약 83초, 대부분 유럽 칸 83개로 칸 하나 약 4초), 바뀐 것이 없으면 전과 같이 약 5초다. 나라 하나를 고치면: 북한 약 35초 → 약 6초(칸 12개), 치살피나 공화국 약 12초 → 약 9초(유럽 칸 5개), 고구려 약 6초 그대로(칸 91개), 1789년부터 지금까지 있는 스위스는 유럽 칸 83개를 모두 다시 해 약 98초 → 약 49초. worker 없이(`HISTORY_MAP_WORKERS=0`) 캐시도 없으면 약 228초다.

### 6.1 블럭 hover
- 마우스 아래의 나라는 화면 좌표를 경위도로 되돌린 뒤, 그려진 영토 중 경위도 범위가 맞는 것만 골라 포함 여부를 검사해 찾는다 (Canvas에는 요소별 이벤트가 없으므로).
- 찾은 영토의 **경계선을 진하게** 그린다. 모든 영토를 칠한 뒤 맨 위에 그리므로 이웃 영토에 가려지지 않는다.
- 처음에는 SVG 레이어에 그렸으나, React가 다시 그리는 시점이 지도(Canvas)보다 늦고 정밀 도형으로 매번 경로를 만들어 무거워서, 움직이는 동안 테두리가 지도에서 몇 프레임씩 밀렸다 (2026-09-27 수정). 지금은 Canvas에서 지도와 같은 프레임·같은 도형(확대 시 격자 선 조각)으로 그린다. 이름표·화살표(SVG)도 지도를 그린 직후 같은 프레임에 반영한다(`flushSync`).
- 처음에는 영토를 1.05배 키우는 효과도 있었으나, 운영자 요청으로 없애고 경계선 강조만 남겼다 (2026-09-25).
- 툴팁으로 국호와 존속 기간을 보여준다 (마우스일 때만).
- `certainty`가 `estimated`·`disputed`인 영토는 점선 테두리로 그린다.

### 6.2 블럭 클릭 → 사건 패널
- 오른쪽 패널에 국호, 존속 기간, 현재 10년 구간의 사건을 보여준다 (D6).
- 사건이 없으면 "이 구간에 등록된 사건 없음"과 함께 가장 가까운 사건으로 가는 링크를 보여준다.
- "이 나라 전체 사건 보기"를 누르면 존속 기간 전체를 연도순으로 보여주고, 현재 구간은 강조한다.
- 연도를 바꿨을 때 선택한 나라가 사라지면 패널에 "이 시기에는 존재하지 않음"을 표시하고 `successor_of` 링크를 보여준다.

### 6.3 사건 hover → 화살표
- **누르면 고정** (2026-10-05): 사건을 누르면 마우스가 떠나도 화살표가 남는다(`pinnedEventId`). 그 사건을 다시 누르거나 사건 밖(지도·패널의 다른 곳)을 누르면 사라지고, 다른 사건을 누르면 그 사건으로 바뀐다. 고정한 동안 다른 사건에 마우스를 올리면 잠시 그 사건의 화살표를 보여 주고, 떠나면 고정한 사건으로 돌아간다(`activeEventId` = 마우스를 올린 사건 ?? 고정한 사건). 연도·나라·전쟁 보기가 바뀌면 고정이 풀린다. 키보드로는 사건에 초점을 두고 Enter·Space로 같은 동작을 한다. 고정한 사건은 테두리가 더 굵다.
- **들어오는 화살표** (`to`가 선택한 나라인 link): 영향을 준 나라의 기준점 → 선택한 나라의 기준점. 색 A (파랑 계열)
- **나가는 화살표** (`from`이 선택한 나라인 link): 선택한 나라 → 영향을 받은 나라. 색 B (주황 계열)
- 색만으로 구분하지 않고 **선 모양도 다르게** 한다 (실선과 점선). 색각이상 사용자를 위한 것이다.
- 같은 두 나라 사이에 양방향 화살표가 생기면 서로 반대쪽으로 휜 곡선(2차 베지어)으로 그려 겹치지 않게 한다.
- 화살표 중간에 `note` 라벨을 붙인다.
- 상대 나라가 화면 밖에 있으면 화면 가장자리까지 그리고 국호 라벨을 붙인다.
- 기준점은 **사건 연도 기준**으로 정한다. 현재 화면 연도가 아니라 그 사건이 일어난 해의 영토를 쓴다. 그 해에 영토가 없으면(예: 멸망한 해의 고구려) 시간상 가장 가까운 영토 버전을 쓴다.
- 화살표와 이름표는 Canvas 위의 SVG에 화면 좌표로 그린다. 확대해도 선 굵기와 화살촉, 글자 크기가 변하지 않는다.
- 화면 밖 상대 나라를 가장자리 라벨로 표시하는 기능은 아직 없음 (예정).

| 지도의 전투 표시(⊗)·유적 표시(●)·전쟁 표시(⚔) | 고른 권역의 사건·전쟁만. 다만 검색이나 전투 표시로 고른 사건(`focusedEventId`)은 권역과 상관없이 보인다 |
| 검색 결과 | 고른 권역의 결과를 먼저 보여 준다. 다른 권역 결과가 있으면 8칸 가운데 **끝의 2칸은 다른 권역 결과에 남겨 두어** 숨기지 않는다(고른 권역 결과가 6개보다 적으면 남는 칸도 다른 권역 결과로 채운다) |
| 지도 시점 | 권역 단추를 누르면(이미 고른 단추를 다시 눌러도) 그 권역 범위로 한 번 옮긴다(`fitBounds`·`animateTo` 재사용). 전체는 옮기지 않는다. 전쟁 보기 중에는 옮기지 않는다 |
| 연도 | 지금 연도에 그 권역 나라의 영토가 하나도 없으면(예: 300년에 유럽) 그 권역의 자료가 있는 가장 가까운 연도(앞 시대이면 첫 영토 연도, 유럽은 지금 476년. 데이터에서 계산)로 옮기고, 단추 아래에 "유럽 자료가 있는 476년으로 옮겼습니다"를 4초 동안 보여 준다(`role="status"`, 화면 낭독기도 읽음). 전쟁 보기 중이면 먼저 닫는다. 영토가 있는 연도와, 영토는 없어도 그 권역 사건이 있는 연도(선사 시대의 한국)에서는 연도를 바꾸지 않는다 |

- **걸리지 않는 것**: 나라 영토 그리기(모두 계속 그린다. 숨기면 지도가 비어 혼란스럽다), 고른 나라의 사건 패널(그 나라 사건은 다 보인다), 전쟁 보기 안의 전선·전투.
- **권역 값은 YAML에 적지 않는다.** 빌드(`build:data`)가 파일 이름에서 정해 `entities.json`·`events.json`·`wars.json`의 각 항목 끝에 `region`으로 넣는다. 이 `region`은 지리적 권역(korea·europe 등)이고, 나라 항목의 `level: region`(나라가 아닌 지역 항목)과는 다른 것이다.

| 파일 | 권역 | 빌드가 멈추는 경우 |
|---|---|---|
| `data/entities/<권역>.yaml` | `<권역>` | `<권역>`이 대응표 `REGION_FILTER_OF`에 없음 |
| `data/events/*.yaml` | 알려진 앞머리(`STORY_FILE_PREFIXES`, 지금 `eu-` → europe)로 시작하면 그 권역, 두 자리 수로 시작하면(`01-gojoseon.yaml`~`08-contemporary.yaml`) korea | 둘 다 아님(예: `me-01-test.yaml`, `notes.yaml`) |
| `data/wars/*.yaml` | 알려진 앞머리로 시작하면 그 권역, 그 밖(`imjin-war.yaml` 등)은 korea | `<영문자>-<두 자리 수>-` 꼴인데 앞머리를 모름(예: `me-01-test.yaml`) |

- **권역과 필터 단위의 대응표는 `src/schema/regions.ts` 한 곳**에 있다(빌드와 앱이 함께 쓴다). `REGION_FILTER_OF`: korea·china-early·china·inner-asia·japan·southeast-asia·west → 한국·동아시아, europe → 유럽. `STORY_FILE_PREFIXES`: 사건·전쟁 파일 앞머리 → 권역. 새 권역은 여기에 한 줄씩 더한다(`docs/REGION_GUIDE.md` 2절 3번).
- **지도 범위**(`REGION_FILTER_INFO`): 한국·동아시아는 첫 화면과 같은 [[88, 18], [146, 54]](`view.ts`의 `EAST_ASIA_BOUNDS`가 이 값을 쓴다), 유럽은 [[-11, 34], [48, 71]](아일랜드·포르투갈 ~ 볼가강의 스탈린그라드, 크레타·키프로스 ~ 노르웨이 북단).
- **상태 보존**: 다른 화면 상태처럼 쿼리 문자열에 둔다(`?region=europe`, 전체이면 적지 않음). 권역을 적은 주소로 들어오면 첫 화면도 그 권역 범위로 맞춘다. localStorage는 쓰지 않는다.
- **접근성**: 묶음은 `role="group"`(이름 "권역 필터"), 단추마다 `aria-pressed`와 긴 이름의 `aria-label`. Tab 말고 ←·→·Home·End로도 단추 사이를 옮겨 다니고(Alt·Ctrl·Meta를 함께 누르면 건드리지 않음) Enter·Space로 고른다. 고른 단추는 색만이 아니라 굵기와 밑줄로도 구분한다. 색은 기존 색 토큰만 써서 다크 모드를 따른다.
- **휴대폰(767px 이하)**: 제목·권역·검색창을 한 줄에 두고, 권역은 짧은 이름(전체·동아시아·유럽)으로, 단추 높이는 손가락으로 누르기 좋게 32px로 둔다. 검색창이 좁아지므로(375px에서 약 120px, 320px에서 약 64px) 검색 결과 목록과 연도 알림은 머리글 폭에 맞춘다. 375px·320px 너비에서 겹치지 않고 가로 스크롤이 없다.
- 필터 단위를 늘리려면 `REGION_FILTERS`에 id를, `REGION_FILTER_INFO`에 이름·짧은 이름·지도 범위를 더하고 대응표의 해당 권역을 그 id로 바꾼다.

- **hover가 없으므로**: 나라를 누르면 바로 선택하고 선택 테두리를 보여준다. 사건을 누르면 그 사건의 화살표를 보여준다(그 사건을 다시 누르거나 다른 곳을 누를 때까지 유지, §6.3).

- 첫 화면의 동아시아 범위는 화면 비율에 맞춰 배율을 계산한다 (PC 가로 화면과 모바일 세로 화면 모두 꽉 차게).

### 6.6 축소할 때 지도 끝을 화면 경계에 붙이기

축소해서 지도 밖 빈 곳이 보이려 하면 지도 끝을 화면 경계에 붙인다 (`view.ts`의 `constrain`).

| 상황 | 동작 |
|------|------|
| 위(또는 아래) 끝이 화면 안으로 들어오려 함 | 그 끝을 화면 위(아래) 경계에 붙인 채 축소 |
| 지도 높이가 화면보다 작아짐 | 세로 가운데에 고정 |
| 세계 폭이 화면보다 좁을 때 축소하다 왼쪽(오른쪽) 끝이 화면 경계에 닿음 | 그 끝을 경계에 붙인 채 축소 (빈 곳은 반대쪽에만) |
| 세계 폭이 화면보다 넓음 | 좌우는 도법 회전으로 끝없이 이어지므로 끝이 없음 |

- **끌기는 항상 도법 회전**이다. 회전은 지도(타원) 위치를 바꾸지 않으므로 빈 곳을 만들지 않는다. 세계 전체가 보일 만큼 축소해도 좌우로 끌면 지구가 제자리에서 돈다.
- 세계 폭이 화면보다 좁을 때 **확대·축소만** 지도를 가로로 옮긴다(포인터 기준 확대). 다시 확대해서 세계 폭이 화면보다 넓어지면, 남은 가로 어긋남은 도법 회전으로 넘겨 화면이 튀지 않게 한다.
- 이 계산을 픽셀 단위로 정확히 하려고 시점을 `{ 중앙 경선의 경도, 배율, 적도의 화면 y, 가로 어긋남 px }`로 저장한다.
- 최대로 축소하면(배율 1) 세계가 화면 가로나 세로 한쪽에 여백 없이 꼭 맞는다.
- **확대해서 지역 도법(§3.1)이 섞이면 위·아래 끝 제한을 푼다** (2026-09-26 수정). 끝 제한은 Equal Earth 기준인데, Equal Earth는 극지방을 세로로 누르므로 그대로 두면 확대할수록 극점이 화면 밖으로 밀려났다 (1400×800, 배율 10에서 북극이 화면 위로 약 680px 밖). 지금은 섞인 정도(t)에 비례해 화면 높이의 절반까지 더 끌 수 있어서, 완전히 바뀌면(t=1) 극점을 화면 가운데까지 옮길 수 있다. 끝 붙이기는 세계 도법으로 보는 축소 상태에서만 원래대로 동작한다.
- 극점을 넘어 반대편을 잡고 끌면 중심 경도가 180° 뒤집혀 지도가 갑자기 돌아가므로, 극점에서 멈춘다 (`recenter`).
- 극점이 화면 안에 있으면 화면 격자 점만으로는 보이는 경도 범위를 놓치므로, 그리기 대상 판정(`visibleBounds`)에서 모든 경도를 그린다.

## 7. 지역 단위 확장 설계

처음부터 아래 원칙을 지켜서 나중에 모델을 바꾸지 않게 한다.

1. **지역도 Entity다**: `level: 'region'`으로 두고, `part_of` 관계로 기간별 소속 나라를 지정한다. 역사적 행정구역은 시대마다 다르다 (신라 9주, 고려 5도 양계, 조선 8도, 현대 도). 그래서 "현대 경기도"를 과거로 늘려 쓰지 않고 **시대별 지역 Entity를 따로 만든다**.
2. **나라 폴리곤은 가능하면 지역 폴리곤에서 만든다**: 어떤 기간에 지역이 나라 영토를 모두 덮으면 빌드에서 합쳐서 나라 폴리곤을 만든다. 원본을 하나로 유지해서 둘이 어긋나는 일이 없게 한다. 지역 데이터가 없는 기간에는 직접 그린 나라 폴리곤을 쓴다.
3. **사건은 어느 단위에든 붙일 수 있다**: `subjects`에 지역 id를 넣으면 그 해의 `part_of`를 따라 상위 나라의 목록에도 자동으로 올라간다.
4. **화면 전환**: 선택한 나라를 확대하거나 더블클릭하면 그 나라의 지역 레이어를 불러와 드릴다운한다. 출력 파일도 `map/<level>/<from>_<to>.topo.json` 형태로 단위별로 나눈다.
5. **화살표도 단위를 따른다**: 지역 단위 보기에서는 지역 기준점을 쓴다.
6. **지역 폴리곤과 국경 생성기** (2026-09-29): 지역 폴리곤도 국경 생성기가 만든다. 그 지역이 속한 나라의 권역 파일(§5.2 5번, 예: 조선 8도 → `scripts/geo/areas/korea.mjs`)에서 이웃과 같은 이름 붙은 선으로 조립해 `data/geo/<지역 id>.geojson`에 평면으로 쓴다(빌드와 검사 스크립트는 하위 폴더를 읽지 않는다). 다만 **지금 생성기와 빌드는 한 기간의 모든 영토가 서로 배타라고 본다.**
   - 생성기의 빈 땅 채우기는 구역에서 그 기간의 다른 모든 영토를 빼고, 틈새 구멍 메우기는 다른 영토가 들어 있는 구멍을 남긴다. 빌드의 겹침 검사(`scripts/build-data/index.ts`의 `checkOverlaps`)는 level을 가리지 않고 모든 영토 쌍이 5km²를 넘게 겹치면 오류를 낸다.
   - 지금 있는 `level: region` 항목(한 군현, 당의 도독부·도호부, 원의 총관부, 점령지·군정, 귀속 논쟁 지역)은 모두 나라 영토와 겹치지 않는 배타 구역이라 이 가정에 맞는다.
   - 그래서 나라 영토와 겹치는 행정구역(신라 9주, 조선 8도 등)은 지금 구조로는 같은 기간의 나라 폴리곤과 함께 쓸 수 없고, 지역이 나라 영토를 일부만 덮는 경우도 지원하지 않는다. 2번처럼 행정구역을 넣는 기간에는 나라 폴리곤 대신 지역 폴리곤만 쓰고 나라 폴리곤은 build-data가 합쳐 만들어야 하는데, 이 조립과 level별 겹침 예외는 아직 빌드에 없다.
   - 행정구역을 넣기 전에 빌드의 지역 조립·level별 겹침 예외와, 생성기의 채우기·구멍 메우기에서 같은 나라의 지역을 어떻게 다룰지(따로 내보내 배타 계산에서 뺄지 등)를 먼저 설계한다.

## 11. 수록 기준과 제보 절차

### 11.1 수록 기준 (D9)
- 타임라인은 **BC 2333(천문 연도 -2332)** 부터 시작한다.
- 나라(Entity)는 다음 중 하나를 만족할 때만 추가한다.
  - `primary_source`: 사료로 존재가 확인됨
  - `national_institution`: 그 나라의 공식 역사기관(한국은 국사편찬위원회 등)이 인정함
- 고조선의 건국 연대처럼 전승에 근거한 연대는 `foundingNote`에 그 사실을 적고, 패널에 "건국 연대는 『삼국유사』의 기록에 따름"처럼 보여준다. 초기 영토는 `certainty: 'estimated'`로 점선 표시한다.
- 빌드 검증기는 `basis.refs`가 비어 있는 나라를 오류로 처리한다.

### 11.2 제보 절차 (D10)
- 외부 기여자는 저장소를 직접 수정하지 않는다. **GitHub Issue 양식**으로만 제보를 받는다.
- 이슈 양식의 필수 항목: 대상 연도와 나라, 제보 내용, **증거 사료(서명, 권·쪽 또는 기관 자료 링크)**
- 운영자가 사료를 확인한 뒤 **자기 문장으로 새로 작성해** 반영한다. 제보자의 글을 그대로 복사하지 않는다. 이렇게 하면 모든 데이터의 저작권이 운영자 한 명에게 남아서 나중에 라이선스를 바꿀 수 있다 (§12).
- 반영된 항목의 `sources`에 사료를 적고, 원하면 제보자를 `CREDITS.md`에 기록한다.

### 11.3 사실 검수 (2026-09-28 추가)
- 입력한 데이터는 묶음 단위로 자료와 대조한다. 대조 자료는 우리역사넷(『신편 한국사』·교과서 용어 해설), 한국민족문화대백과사전, 조선왕조실록, 한국사데이터베이스의 사료 원문을 우선한다.
- 한 검수자가 "수정 필요"로 본 곳은 다른 검수자가 반박을 시도하며 다시 확인하고, 둘 다 틀렸다고 본 곳만 고친다. 자료마다 다르거나 확인하지 못한 곳은 "불확실"로 남기고 고치지 않는다.
- 결과는 `docs/REVIEW.md`에 항목마다 ✔(맞음)·✎(고침)·?(불확실)로 적고, 고친 곳에는 무엇이 틀렸는지와 근거를 남긴다.

## 12. 라이선스 (D11)

| 대상 | 라이선스 | 파일 |
|------|----------|------|
| 소스 코드 (`src/`, `scripts/`) | MIT | `LICENSE` |
| 직접 만든 데이터 (`data/entities`, `data/events`, `data/geo`, `relations.yaml`) | CC BY-NC-SA 4.0 | `data/LICENSE` |
| Natural Earth 해안선 (`data/base`) | 퍼블릭 도메인 | 출처만 표기 |
| 유럽 행정구역 조각 (`data/base/fragments`) | 퍼블릭 도메인 (Natural Earth 파생) | 출처만 표기 |

**데이터에 CC BY-NC-SA 4.0을 고른 이유**
- **BY (출처 표시)**: 다른 곳에서 쓸 때 이 프로젝트를 출처로 밝혀야 한다.
- **NC (비영리)**: 다른 사람이 운영자의 작업물로 상업 서비스를 만들 수 없다. 운영자 본인은 저작권자이므로 이 제한을 받지 않는다.
- **SA (동일 조건)**: 수정해서 배포하면 같은 라이선스를 따라야 하므로 폐쇄된 파생본이 생기지 않는다.
- **나중에 풀 수 있다**: 모든 데이터를 운영자 혼자 작성하므로(§11.2) 나중에 CC BY-SA나 CC BY처럼 더 개방적인 라이선스로 바꿀 수 있다. 반대로 한 번 개방한 버전은 되돌릴 수 없으므로 제한이 있는 쪽에서 시작한다.
- 역사적 사실 자체는 저작권 보호 대상이 아니다. 보호되는 것은 운영자가 쓴 서술 문장과 직접 그린 국경 폴리곤이다.

코드에 MIT를 쓰는 이유는 지도 렌더링 코드는 보호할 가치보다 공개해서 얻는 이점이 크고, 데이터와 분리해 두면 코드만 가져가도 데이터는 따라가지 않기 때문이다.

## 13. 배포 (D12)

- **GitHub Pages + GitHub Actions**: `main`에 push하면 `build:data` → `vite build` → Pages에 배포한다. 빌드 결과물(`public/data/`)은 저장소에 커밋하지 않는다.
- **경로**: 프로젝트 페이지는 `https://<사용자명>.github.io/history-map/`이므로 Vite의 `base`를 `/history-map/`로 설정하고, 데이터 요청도 이 경로 기준으로 만든다.
- **라우팅**: Pages는 SPA 경로 재작성을 지원하지 않으므로 화면 상태는 쿼리 문자열(`?year=668&entity=silla`)만 쓴다 (§6.4와 일치).
- **저장소 공개 여부**: 무료 계정에서 Pages를 쓰려면 저장소가 공개여야 한다. 그래서 워크플로(`.github/workflows/deploy.yml`)는 저장소 공개 여부에 따라 동작이 달라진다.
  - 비공개일 때: push와 PR마다 빌드와 데이터 검증만 실행하고 배포 단계는 건너뛴다.
  - 공개일 때: `main`에 push하면 배포까지 한다.
  - 공개로 전환한 직후 **Settings → Pages → Source를 "GitHub Actions"로 한 번 설정**해야 한다. 이 설정은 무료 계정의 비공개 저장소에서는 열리지 않고 워크플로가 대신 켤 수도 없다.
  - 공개 후에도 데이터는 CC BY-NC-SA로 보호된다.
- 빌드 검증(§5.3)이 실패하면 배포하지 않는다.
