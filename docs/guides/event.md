# 안내서: 사건 작업 (`data/events`)

> 대상: 사건 초안·사실 대조·반영 에이전트(Sonnet), 독립 검토(Opus), 메인. 형식의 정식 설명은 `docs/DATA_GUIDE.md` §3, 스키마는 `src/schema/index.ts`의 `EventSchema`, 검증은 `scripts/build-data/index.ts`. 공통 기준(깊이 등급·파일 이름·머리 주석·달력·이름 표기)은 [standards.md](standards.md) 4·5·7절, 공통 함정은 [common-pitfalls.md](common-pitfalls.md).

## 1. 언제 쓰나, 흐름, 모델

새 사건을 쓰거나, 기존 사건의 `subjects`·기간·글을 고치거나, 지도의 항목·버전 해와 사건을 잇는다. 국경을 고쳤으면 먼저 [border.md](border.md), 전쟁 보기 연결이면 [war.md](war.md)의 `front` 한 줄.

```
메인: 지시문(범위·미연결 목록·되풀이하지 말 것) → 초안 (Sonnet) : 새 사건 파일 + patch.mjs
  → 사실 대조 3묶음 (Sonnet, 읽기만, 웹 검색 필수, 지적마다 유형 꼬리표) → fcN.md
  → 반영 (새 Sonnet 반영 에이전트 — 초안 에이전트는 그 대화가 약 30만 미만일 때만 이어 부름) → 독립 검토 (Opus) : review1.md
  → 반영 + 적용 묶음 (같은 반영 에이전트, 한 번) → 메인 적용 (사건 파일만이면 gen:geo·지점 판정 불필요) → 커밋·배포
```

반복·연쇄를 막는 규칙(2026-10-26 운영자 지시): 독립 검토 뒤 반영은 한 번이고, 그 뒤 남은 지적은 끝 기준 위 오류·검사 실패만 메인이 확인하며 고친다. 같은 유형 지적(`[사이 군주]`·`[해 어긋남]`·`[표기]`·`[달력]`·`[주어]`·`[subjects]` 등)이 두 묶음 연속 5건을 넘으면, 메인이 다음 묶음 지시문 전에 검사로 만들기를 제안하거나 4절 맨 위에 실제 예 2개와 함께 올린다. 지도·다른 파일에서 새로 찾은 후보는 고치지 않고 [후보 장부](../candidates.md)에 적고(메인), 장부 '닫음' 표의 일은 다시 지적하지 않는다. 진행 표 줄은 그 사건 커밋에 함께(커밋 칸 `(이 커밋)`, 해시는 다음 커밋 때).

모델: 초안·사실 대조·반영 **Sonnet**, 독립 검토·재검토·메인 적용 Opus(2026-10-07 결정, 사건은 Sonnet 유지). 측정: 한 묶음(35~45개) 초안 40분~1시간·40~65만 토큰, 사실 대조 3묶음 각 5~12분·합 33~63만, 독립 검토 9~16분·17~32만(세션 H는 세 묶음 함께 29분), 반영 5~14분. 묶음 하나 1시간 30분~2시간. 앞 묶음 초안이 끝나면 다음 묶음 초안을 겹쳐 띄운다.

## 2. 고칠 파일과 진입점

- 파일: `data/events/`. 한국사는 시대별 `01-gojoseon.yaml`~`08-contemporary.yaml`, 다른 권역은 `<머리글자>-<번호>-<이름>.yaml`(유럽 `eu-`, 중세 `eu-m1~m6`, 고대 `eu-an1~an4`, 근세 `eu-00a~d`, 근대 이후 `eu-01~03`). 새 지역의 파일 이름·머리 주석 규칙은 [standards.md](standards.md) 7절(새 앞머리는 `src/schema/regions.ts`의 `STORY_FILE_PREFIXES`에 한 줄, 머리 주석 본보기: `eu-an4-…yaml` 머리).
- 사건 한 개:

```yaml
- id: shelon-novgorod-1471      # (모양을 보이는 예시) 소문자·숫자·하이픈, 전체에서 유일
  year: 1471                    # 천문 연도 (기원전 N년 = 1−N)
  endYear: 1478                 # 선택. 기간이 있으면
  title: { ko: … }
  summary: { ko: "…" }          # 새로 쓴 글. 사이 군주·공동 통치까지, 길이는 깊이 등급대로(유럽 실측 약 1,400~1,600자, standards.md 7절)
  subjects: [grand-duchy-of-moscow, novgorod-republic]   # 본문에 이름이 나오는 항목만, 사건 기간과 존재 기간이 겹쳐야 함
  links:                        # 화살표. from = 노트 동사의 주어
    - { from: grand-duchy-of-moscow, to: novgorod-republic, note: "셸론강 전투와 코로스틴 조약 (1471)" }
  tags: [war, politics]         # politics·war·diplomacy·culture·society·economy·religion
  sources: ["저자, 서명(『』) …"]  # 필수
  places: [{ name: 셸론강 전투, at: [30.77, 58.2], year: 1471 }]  # 전쟁 보기가 없는 싸움. 장소 year는 사건 기간 안
  front: { war: 전쟁id, theater: 전역id, date: 1914-09-05 }       # 전쟁 보기가 있으면
```

- 연도 규칙(2026-10-06 넓힘): `subjects`·`links`의 나라는 **사건 기간(`year`~`endYear`)과 존재 기간이 겹치면** 된다. 영토가 없는 기간의 항목은 `subjects`에만 두고 `links`에는 쓰지 않는다(화살표를 그릴 수 없음). 영토 없는 귀속 후보(코소보 등)도 `subjects`만.
- **links 방향**: 정복·획득·병합은 얻은 쪽이 `from`, 조약의 할양·넘김·양도는 내준 쪽이 `from`이고 노트의 동사를 그에 맞춘다('반환'은 내준 쪽 동사). 사건 한 개 안에서 두 방식이 섞이면 노트 동사로 구분되게.
- 다른 사건을 가리킬 때는 「제목」(앞의 사건)/(뒤의 사건) 꼴(**파일 이름을 본문에 쓰지 않음**, 방향은 해 순서). 한국사 파일에 이미 있는 사건은 다시 만들지 않고 서술에서 이름만 말한다.
- 자동 점검 도구(인계 폴더 `tools/`, repo는 Windows 절대 경로): `lifecycle.mjs <repo> <시작> <끝>`(항목의 성립·소멸 해 ±2년에 걸친 사건이 있는지), `versions2.mjs <repo> <시작> <끝> [최소 km²]`(버전 해마다 앞뒤 대칭차 면적과 ±2년 사건). 옛 작업의 `terr.mjs`(영토 없는 subjects)·`val.mjs`·`subjtext.mjs`(본문에 안 나오는 subjects)는 세션별 작업 폴더 `work/`에 있다.
- 적용: 새 사건은 새 파일 + `work/patch.mjs`. patch는 **앵커 문자열**(앵커 사건 id의 앞/뒤, `#@before`)로 넣고, 앵커가 없거나 여럿이면 아무것도 쓰지 않고 멈추며, 줄바꿈(CRLF/LF)을 유지하고, 두 번 돌려도 같고, `--check`를 지원한다. 문서(`docs/*`)는 에이전트가 고치지 않고 메인이 마지막에 쓴다 — 결과 노트 1절 끝에 문서에 넣을 한두 문장을 적는다.

## 3. 기준 (승인된 것)

- **잇기 규칙**: 지도에서 항목이 생기거나 끝나는 해, 1만 km² 넘게 바뀐 버전 해마다 **±2년 안에 그 항목을 subjects에 둔 사건**이 있어야 한다(EV5·EVD2에서 정해 중세·고대에 적용). 사건 기간을 항목의 시작·끝 해 ±2년에 걸치게 짜는 것이 요령. 지도의 해가 사료와 어긋나 보이거나 이을 근거가 없으면 억지로 잇지 말고 결과 노트에 **'지도 FIX 후보'**(항목·해·넓이·근거)로 남긴다. (EUROPE_DRAFT 7.3-⑥, 8.5, REGION_GUIDE §6)
- 기존 사건을 넓히는 쪽을 먼저, 없으면 새 사건. 넓힐 때는 본문에 그 항목 이름과 그 해의 일이 나오게 문장을 더하고, 기간을 넓힌 사건은 목록으로 보고.
- 한국사와 닿는 점은 한두 문장으로 견주어 subjects로 잇는다(강요하지 않음). 한국사 파일을 고칠 때는 한능검(심화) 문체로 짧게.
- 글: 새로 작성(복사 금지). 날짜·달력은 [standards.md](standards.md) 4절. 숫자·추산은 범위와 출처, 병력·사상자는 '추산'. 조약은 이름·조건·서명 해와 비준 해를 구분. 나이는 만 나이. 확실하지 않은 날짜는 '무렵'. 원주민·피정복민 서술을 정복자 시각만으로 쓰지 않음. 낡은 말('야만') 금지(사료 인용 제외).
- 서지: 저장소 기존 표기를 그대로, 새 책은 **웹에서 제목·저자(옮긴이)·출판사·연도를 확인한 경우만**(아니면 원서). 책 『』, 글·조약문·지도 이름 「」.
- 표기: 한 인물·지명은 저장소 기존 표기 하나(`names.ko`와 맞춤, 표기 원칙은 standards.md 5절). 표기가 갈리는 이름은 메인이 정해 지시문에 적는다.

## 4. 되풀이하지 말 것 (EVM·EVA·G·H 검토 지적에서)

1. **사이 군주 누락(가장 많음)**: 군주가 이어지는 서술은 군주 목록(위키 List of …)과 맞춰 짧은 재위·공동 통치·섭정까지 이름·재위만이라도 넣거나 '…를 거쳐'로 건너뜀이 드러나게(소제 424, 클레프 572~574, 아가토클레스 뒤 히케타스, 레카레드 2세).
2. **지도와 글의 해 어긋남**: '지도는 ~년부터 ~로 그린다' 문장을 `europe.mjs`의 실제 해로 확인. 항목 `to`는 포함, 영토 `to`는 미포함이라 "206년에 끝낸다"는 "206년까지 그리고 207년부터"로. 천문 연도 변환(year −346은 기원전 347).
3. **본문에 없는 subjects**, 영토 없는 항목을 links에 씀, 주어가 사람이 아닌 나라("송은 즉위하자…"), 직함의 시점(신성 로마 황제로서 승격).
4. **표기 섞임**: 드니스테르강(드니스터·드니스트르 아님), 아흐메트, 슐레지엔(실레지아 아님), 키이우(중세 '키예프 루스'만 키예프), 킬리아, 구스타브, 게오르기옙스크, 프레드릭스함, 옐리자베타, 파즐, 볼시니, 부크강(남부흐강), 동로마 인물은 그리스식(니케포로스·유스티노스·파트리키오스), 테무라즈. 새 이름은 표기 사전 `data/tests/spelling.yaml`을 먼저 보고, 없으면 `grep`으로 저장소 기존 표기를 확인한 뒤 사전에 더한다([standards.md](standards.md) 5절). 이 줄의 표기도 사전에 있다(키이우·키예프는 시대로 갈려 사전에서 뺐으니 이 줄대로).
5. **링크 노트 오류**: 노트의 전쟁 이름이 틀림(대튀르크 전쟁 1683~1699를 1788에), 동사와 방향 불일치, 문장 순서가 시간 순서와 어긋남, 가리킨 "뒤의 사건"이 실제로는 없음, 같은 일을 다른 사건이 다르게 씀.
6. **서지**: 우리말로 지은 설명을 제목처럼 씀(원서 제목으로), 본문이 인용한 책이 sources에 없음, `Geographika`/`Geographica`처럼 파일마다 다른 표기, 숫자의 출처가 틀림(아리아노스에 없는 숫자는 디오도로스), 근거 URL에 그 내용이 없음.
7. **문서 줄**: 줄 끝 '같은 날 사실 대조(3개 묶음)·독립 검토 반영' 빠짐, 6절 '다음' 줄에 끝난 단계 문구 남김, 결과 노트 경로의 역슬래시가 깨짐.
8. 억지로 이은 흔적: 지도 안의 일을 설명하는 메타 문장, 장식처럼 붙인 subjects.

## 5. 검사

사본에서(새 사본: 원본 clone, node_modules 정션, `.cache` 복사):
```
node work/patch.mjs --check   →  node work/patch.mjs   →  다시 돌려 '바뀐 파일 0개'
(앵커 id를 바꿔 exit 1·'멈춤(아무 파일도 쓰지 않음)' 확인, CRLF로 바꾼 사본에 적용해 줄바꿈 유지 확인)
npm run check:data     # 사건 수 = 기준 + 새 사건 수, 경고 52 그대로 — 경고 수는 bash: grep -c '^  경고'
npm run typecheck ; npm run build
node …/tools/lifecycle.mjs <repo 절대경로> 476 2026 > after.txt ; node …/tools/versions2.mjs <repo> 476 2026 10000 > after-v.txt   # 작업 전 파일과 diff
```
### 5.1 사건 잇기 `npm run test:geo`

`lifecycle.mjs`·`versions2.mjs`를 저장소 안으로 옮긴 검사다. 같은 두 범위(476~2026, −2400~475)에서 두 도구와 줄 단위로 같은 결과가 나온다.
```
npm run test:geo -- --only events                       # 전 범위: 처음 1분 반 안팎(대칭차 계산), 캐시가 있으면 약 2초
npm run test:geo -- --only events --years 1500-1600     # 시대를 좁힘
npm run test:geo -- --only events --region europe       # 권역을 좁힘
```
- 출력: `통과 events 검사 3,452 · 성립·소멸 978줄 · 버전 해 2474줄(1만 km² 이상 1769) · … · 알려진 예외 10`. 새 실패는 `✗ events 해 id 성립|소멸|버전` 꼴로 나오고 열쇠는 `<해> <id> 성립|소멸|버전`이다. `계산실패`는 대칭차 계산이 예외를 던진 것(항목별로 알림).
- 규칙은 [3절](#3-기준-승인된-것)과 같다: 성립·소멸 해와 1만 km² 넘는 버전 해 ±2년 안에 그 항목을 `subjects`에 둔 사건이 있어야 한다. 옛 도구의 직접 실행도 된다: `node scripts/test-geo/checks/events.ts life|versions <시작> <끝> [최소 km²]`.
- 의도한 미연결은 `data/tests/allow/events.yaml`(`key`·`reason`·`decided`). 지금 10건: 운영자 결정 4건(초원 부족 935 소멸, 탐라 1104 소멸, 몽골 1509 버전, 미국 1848 버전)과 476년 앞 6건(선사 −2333, 연 −1043, 프리기아 −899, 우라르투 −859, 진국 −199, 탐라 200). 새 항목은 허용하지 말고 사건으로 잇는다.
- 사건·나라 YAML만 고친 뒤 화면용 JSON이 필요하면 `npm run build:data -- --events-only`(약 2초). 읽기·스키마 검사만 하려면 `-- --check --events-only`. 전체 `check:data`는 캐시가 따뜻하면 약 18초, 처음엔 6~18분이라 단계 끝에 한 번.
- **글 검사** `npm run test:geo -- --only years,spelling`(약 5초, 도형 안 읽음): `years`는 글 속 지도 해("지도는 N년부터")가 그 나라 지도 해와 맞는지와 기원전 사건의 제목·id 해가 `year`와 천문 연도로 맞는지(기원전 N년 = 1−N), `spelling`은 표기 사전의 쓰지 않을 표기. 새 실패가 나면 글을 고친다. 지금 있는 것은 기준선이라 실패로 세지 않고, 글을 고쳐 줄었으면 `npm run test:geo -- --only years --update-baseline years`(`spelling`도 같은 꼴). 사건 초안·반영 뒤와 지도 해를 고친 뒤 돌린다.
- 전체 사용법(출력 읽는 법, 허용·기준선 고치는 법): [border.md](border.md) 5.1.

lifecycle/versions2는 범위 밖(다른 시대·동아시아)이 늘지 않았는지 **전체 목록을 전후 diff**로 본다. 기준(2026-10-13): 성립·소멸 미연결 2(초원 부족 935·탐라 1104), 버전 해 2(몽골 1509·미국 1848) — 운영자 결정으로 남김. 독립 검토는 새 사본에 patch를 정순·역순으로 적용해 바이트가 같은지(묶음끼리 파일이 겹치지 않으면 같아야 함)도 본다.

## 6. 비용 줄이기

- 초안 에이전트 대화는 20만 안: 한 묶음 35~45개를 넘기지 말고 범위를 시대로 쪼갠다. 지시문에 '되풀이하지 말 것'을 박아 검토 지적을 줄인다(국경 M6에서 이 목록을 넣자 1만 km² 넘는 지적이 4건에서 1건으로 줄었다).
- 사실 대조는 사건을 셋으로 나눠 각 에이전트에게(웹 검색을 꼭 쓰게 — EVM3 대조 1은 웹 없이 해서 놓침), 웹 페이지 열기 15번 안팎, 먼저 볼 출처(위키백과 해당 언어판·공식 전사 한두 곳)를 정해 주고 겹쳐 열지 않게 메모 공유.
- 검토는 표본 감사: patch·check:data·잇기 대조 결과를 믿고 사실 대조와 의심 문장 재확인에 집중. 글·주석만 고친 반영은 재검토 없이 메인이 `grep`으로 확인.
- 문서·결과 노트는 파일로 쓰고 메인에는 경로와 건수만 보고(10줄 안팎).
