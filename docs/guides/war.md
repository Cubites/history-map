# 안내서: 전쟁 보기 작업 (`data/wars`)

> 대상: 전쟁 보기(날짜별 전선 스냅샷) 구현·독립 검토·반영 에이전트와 메인. 형식의 정식 설명은 `docs/DESIGN.md` §4.5와 `docs/DATA_GUIDE.md` §5.6, 스키마는 `src/schema/index.ts`(WarSchema~TheaterSchema), 계산은 `scripts/build-data/wars.ts`. 공통 함정은 [common-pitfalls.md](common-pitfalls.md).

## 1. 언제 쓰나, 흐름, 모델

전쟁 중 전선·점령 지역이 연 단위 영토로는 안 보이는 전쟁에 쓴다(6·25, 임진왜란, 세계 대전 등). 연 단위 국경이 틀렸으면 [border.md](border.md), 사건 글이면 [event.md](event.md).

```
메인: 지시문(운영자 결정·진영 설계·묶음 나눔) → 묶음마다 구현 에이전트 (Opus, 병렬 가능: 서로 다른 파일만 고침)
  → 구현 : 사본에서 전쟁 YAML + geojson + 생성 스크립트 → build:data(전쟁 오류 0) → 조각·도시 판정표 → 적용 묶음 + 결과 노트
  → 독립 검토 (Opus) : 새 사본에 적용, 스냅샷마다 전선 도시·강 5곳 이상 웹으로 대조 (수 km인지), wars.json 조각 점검
  → 반영 (구현 에이전트 또는 새 작은 에이전트) → 재검토 (처음 검토 에이전트, 고친 곳만) → 메인 적용·배포
```

모델: 구현·검토 모두 Opus. 측정(세계 대전): 구현 W1 1시간 35분·51만 토큰, W2 약 3시간·140~160만(보조 조사 4건 포함), W3 1시간 50분·50만; 독립 검토 25~30분·25~31만; 반영 20~60분; 재검토 5~9분. 첫 `build:data`는 캐시가 없으면 약 18분이라 원본 `.cache`를 사본에 복사한다.

## 2. 고칠 파일과 진입점

| 무엇 | 어디 |
|---|---|
| 전쟁 정의 | `data/wars/<파일>.yaml` — 한국사는 `imjin-war.yaml`처럼 이름만, 다른 권역은 `<머리글자>-<두 자리 수>-<이름>.yaml`(`eu-02-world-war-1.yaml`). 머리글자는 `src/schema/regions.ts`의 `STORY_FILE_PREFIXES`에 있어야 함 |
| 손으로 그린 점령 지역 | `data/wars/<이름>/<날짜>-<진영>.geojson`(EPSG:4326, 바다로 넉넉히 나가게; 빌드가 해안선으로 자름) |
| 사건에서 전쟁 보기로 | `data/events/*.yaml`의 사건에 `front: { war: 전쟁id, theater: 전역id, date: YYYY-MM-DD }` 한 줄. `date`는 스냅샷 날짜와 정확히 같아야 함 |
| 빌드 출력(손대지 않음) | `public/data/wars.json`(전쟁 목록·진영·전투) + `public/data/wars/<전쟁id>.json`(점령 지역 도형, 전쟁 보기를 열 때만 받음) |
| 생성 스크립트 | 저장소 밖 인계 폴더 `ww-generators/w1~w3`(경유점 `fronts*.mjs`, 장면 구성 `spec*.mjs`, 생성 `gen.mjs`, 검사 `check.mjs`). W2는 `HISTORY_MAP_REPO=<저장소> node gen.mjs`로 YAML과 geojson을 **바이트까지 같게** 다시 만든다 |

YAML 뼈대(실제 파일은 `data/wars/eu-02-world-war-2.yaml` 머리를 본다):

```yaml
id: world-war-2
name: 제2차 세계 대전
factions:                      # 진영: 지도에서 한 색. entity = 색·이름표·클릭 대상 대표 나라
  - { id: allies, name: 연합국, entity: uk, color: "#4a72b8" }
participants:                  # 참전국. 편을 바꾼 나라는 기간을 나눠 두 번
  - { entity: italy, faction: axis, from: 1940-06-10, to: 1943-09-08 }
theaters:
  - id: europe
    name: 유럽·북아프리카
    region: japan              # 선택: 전쟁 파일 권역과 다른 필터에 보이게 (아시아·태평양)
    replaces: [france, poland] # 전쟁 보기에서 영토 대신 진영 색으로 칠할 나라
    marker: [8.0, 50.2]        # 평소 지도의 전쟁 표시 위치
    bounds: [[-6, 35], [46, 61]]   # 확대 범위 [[서,남],[동,북]] (경도 ≤180)
    simplify: 4                # 선택: 장면 도형 단순화 허용 오차(km). 한 장면의 진영 덩어리를 한 토폴로지로 묶어 줄임(맞닿은 경계는 같이 줄어 틈·겹침 없음). 세계 개관처럼 거친 전역용. 4km에 크기 약 35~45%
    hideMarker: true           # 선택: 평소 지도에 전쟁 표시를 두지 않음(전쟁 보기 안의 전역 버튼으로만 들어감). wars.json에는 true일 때만 나감
    battles: [ { name: 마른 전투, at: [3.38, 49.02], date: 1914-09-05, winner: entente, summary: "…했습니다." } ]
    snapshots:
      - date: 1914-09-05
        title: …
        summary: "2~3문장, '~했습니다' 꼴"
        areas:                 # 뒤에 적은 지역이 앞 지역을 덮는다
          - { faction: entente, entities: [france] }
          - { faction: central, geojson: ww1/1914-09-05-central.geojson }
        arrows: [ { faction: entente, path: [[…],[…]], label: … } ]
        holds: [ { name: 웨이크, at: [166.6, 19.3], faction: japan } ]   # 육지 자료에 없는 섬·포위된 거점
        labelAs: [ { entity: german-empire, instead: [weimar-republic] } ]   # 선택: 장면 때 있던 나라의 이름표로 바꿔 달기(연 단위 영토가 전쟁 뒤 모습일 때)
```

빌드 동작(wars.ts, 화면 코드에서 찾지 말 것): 진영마다 점령 지역을 한 덩어리로 합침 · 손그림 geojson은 **먼저 칠한 지역 안에서는 그 지역의 해안선으로, 밖은 육지로** 자름 · 반올림 뒤 넓이 0 조각은 뺌 · 진영 덩어리는 전역 `bounds` + 폭의 1/4 여백으로 자름 · 전역 `simplify`가 있으면 그다음 진영 덩어리를 함께 줄임(경계 꼭짓점 맞추기 → 토폴로지 → arc마다 더글러스-포이커 → 퇴화 고리 빼기 → 남은 겹침은 뒤 진영이 이김; 이름표도 줄인 도형으로) · 이름표는 그 나라 자기 영토에 두되 전역 범위 밖이면 진영 지역 안쪽 · 전쟁 중 생긴 점령 항목은 경계·이름표를 뺌 · 강조선은 다른 진영이 덮은 곳을 뺀 화면의 바깥선.

## 3. 기준 (승인된 것만)

- **세계 대전 운영자 결정(2026-10-12)**: 1차 대전은 유럽 전역 하나, 2차 대전은 유럽·북아프리카 + 아시아·태평양(1937-07-07 루거우차오부터), **핵심 국면만**(장면 12 / 16 / 12), **실제 전선 지도에 가깝게(수 km)**. 비시 프랑스는 추축 색, 이탈리아는 1940-06-10 참전 전에는 칠하지 않음.
- **2차 대전 진영 id 고정**: `allies`(entity `uk`), `axis`(`nazi-germany`), `soviet`(`soviet-union`, 독소 불가침 시기와 동부 전선을 따로 보이려 연합국과 분리), `japan`(`japan`), `china`(`roc`). 색은 #4a72b8 · #62666e · #c2453b · #c77a9e · #d9a43a.
- **전쟁 보기는 날짜별 실제 점령을 그린다**(연 단위 국경의 '원정은 칠하지 않음'과 다름). 다만 참전 전 중립 기간은 칠하지 않고(평소 영토로 보임), `replaces`에는 1차 대전처럼 연 단위 영토가 전쟁 뒤 모습인 나라·점령지 항목만 넣는다.
- 날짜는 그레고리력 `YYYY-MM-DD`, 기록에 날이 없으면 `00`. 전근대 전쟁은 음력으로 적고 이름에 "(날짜는 음력)".
- 스냅샷당 화살표 2~5개, 전투는 전역마다 15~30개(summary 한두 문장, 교과서·개설서에 나오는 것), 진군로는 꼭 필요할 때만. 글체 '~했습니다', 책 『』, 표기는 저장소 기존 표기(리비우(렘베르크)처럼 병기).
- 정밀도: 서부 전선 참호선은 10~20km 간격 경유점, 경유점은 실제 위치(OSM·위키백과 좌표) 5km 안, 강을 따라가는 전선은 강줄기에 맞춤. 바다 쪽은 **넉넉히 바깥으로**(해안 쪽 가장자리가 해안선 안쪽에 머물면 가는 띠가 남음).
- 공개 전선 GIS 자료는 라이선스가 저장소(데이터 CC BY-NC-SA, 출처 표기)와 맞을 때만, 불분명하면 경유점 방식. CShapes 좌표는 저장소에 넣지 않음. 출처는 `CREDITS.md`/README.
- 연합국 식민지(동남아·태평양)는 1941-12-08 장면부터 칠함, 타이는 1942년부터 일본 진영 색, 몽강은 1937-12-13부터 일본 쪽(W3-②③, 검토 반영).

## 4. 되풀이하지 말 것 (W1~W3 검토 지적)

- **선 위의 도시**: 전선이 지나는 도시는 경유점을 2~5km 바깥으로 옮겨 어느 진영인지 분명히(플젠·린츠·트루아·오를레앙, 즐로빈·크로스노). 도시 판정표를 스냅샷×도시로 만들어 기대값과 대조한다(W1 판정 422줄 중 '맞음' 360).
- **빠진 점령지**: 동아나톨리아 러시아 점령(1914~1916), 툴라 돌출부, 포즈난·슈나이데뮐·글로가우 같은 포위지, 몽강, 필리핀 잔존 지역. 포위·고립 거점은 `holds`나 포위 다각형으로.
- **움직이는 전선을 한 날짜로 끊은 구간**과 이름 없는 점 사이 어림은 가장 오차가 크다 → 결과 노트 '검토에서 먼저 볼 곳'에 구간·오차 km를 적고, 가능하면 이름 붙은 경유점으로 채운다.
- **진영 덩어리 하나로**: 나라 영토(entities) 위에 geojson을 여러 겹 덮으면 빌드의 polyclip-ts가 해안·경계의 가는 조각에서 깨진다. W2는 스냅샷·진영마다 한 덩어리 geojson(48개, 3.7MB)으로 만들었다. 반올림 뒤 자기 접촉이 생긴 링은 자기 자신과 합집합을 3번 반복해 정리(W3 `round`).
- **육지 자료에 없는 섬**(Natural Earth 50m: 람페두사·레로스·예니칼레·웨이크·미드웨이·마킨 등)은 칠할 수 없다 → `holds`.
- **'칠하지 않음' 층이 없다**: 항목이 잘못 덮은 땅(예전 `roc`의 마카오·통킹)을 전쟁 보기에서 지울 수 없다. 저장소 국경 문제는 전쟁 보기 geojson으로 때우지 말고 국경 FIX 후보로 올리고, 우회 파일에는 표시한다(윈난 서부를 때우던 `ww2-asia/yunnan-west.geojson`은 세션 K에서 중화민국 국경을 고치고 지웠다).
- **좌표 자릿수**: 빌드는 나라 영토 좌표를 소수 넷째 자리로 반올림한다. 손그림 geojson이 나라 국경과 같은 선을 다섯째 자리로 쓰면 몇 m 차이로 엇갈려 polyclip이 깨질 수 있다(세션 K, 1942-06-07 장면). 국경에 맞출 때는 손그림을 넷째 자리로 줄이거나 선을 조금 떨어뜨린다.
- **가는 띠·넓이 0 조각**: 해안 앞에 앞 지역이 띠로 남아 강조선이 해안을 따라 그려진다. 빌드 뒤 `wars.json`에서 스냅샷×진영 조각 수·넓이를 뽑아 점검.
- **국경을 고쳐도 geojson은 따라오지 않는다**(나라 영토를 깔고 만든 덩어리라). 국경 단계 뒤에는 인계 폴더 `gen.mjs`로 전쟁 geojson을 다시 만든다. 같은 차례로 `ww-generators`의 w1(1차 대전) → w2(2차 대전 유럽) → w3(아시아·태평양) → w4(세계 개관)를 돌리고(w4가 w2·w3 결과를 읽음), 같은 입력에서 바이트까지 같은지는 `data/wars` 파일 해시로 견준다. `areas`의 `entities: [...]`는 빌드가 영토를 그때그때 읽어 저절로 따라오고, `geojson:`만 다시 만들어야 한다(예: 1차 대전 러시아 제국, 2차 대전 아시아·태평양의 소련·중화민국은 `entities`라 자동, 2차 대전 유럽과 세계 개관은 전부 geojson). 세션 M2에서 이렇게 한 번 다시 만들었다(투르크메니스탄 남단·이란·아프가니스탄·동파미르·중화민국 서남 국경·홍콩·마카오).
- 경유점 이름과 좌표는 기억에서 옮기지 말고 위키백과 API로 대조(W2: 이름 붙은 255개 중 43개를 1~8km 고침).
- 날짜·참전 기간 오류(만주국 끝 1945-08-18, 루마니아·불가리아 1944 편 바꿈), 진영 이름('일본' 진영이 타이·만주국까지 덮음, 정할 점 W3-⑤).

## 5. 검사

- 사건 `front:` 한 줄은 적용 스크립트가 **앵커**(`- id:` 블록의 `sources:` 뒤)로 넣고, 사건 파일의 다른 곳은 건드리지 않는다. 줄바꿈 유지, 두 번 돌려도 같음, 기준 HEAD 확인.
- 현재 명령: `npm run build:data -- --war <id>`(이 전쟁만, 아래 5.1) → 단계 끝에 한 번 전체 `npm run build:data`(전쟁 오류 0, 전체 6~18분) → `npm run check:data`(경고 수 bash `grep -c '^  경고'`, 기준 52 — 늘면 이유) → `typecheck` → `build`. 작업 중에는 인계 폴더 `w2/check.mjs mini`(빌드와 같은 계산을 스냅샷마다 돌림)와 `check.mjs built`(빌드 뒤 조각·도시 판정표), 미리보기 `png.mjs`(스크린샷 대신).
- 결과 노트에 넣을 표: 스냅샷×진영 조각 수·넓이(넓이 0·가는 띠 없음), 도시×날짜 판정, 전투·화살표 좌표 5km, 사건 연결 표.

### 5.1 전쟁 하나만 빌드하고 지점 검사하기

전체 `build:data`가 길었던 것은 전쟁 계산(세계 대전 2 하나가 캐시 없이 4~5분)이 매번 돌았기 때문이다. 이제 장면(스냅샷)마다 결과를 `.cache/build-data-wars/`에 저장하므로, 고친 장면만 다시 계산한다.
```
npm run build:data -- --war world-war-2            # 이 전쟁만: wars/<id>.json과 wars.json의 그 항목만 갱신 (캐시 적중 때 약 6초)
npm run build:data -- --war imjin-war,korean-war   # 쉼표나 여러 번 (없는 id는 오류)
npm run build:data -- --check --war world-war-2    # 쓰지 않고 장면이 오류 없이 계산되는지만 (약 6초)
npm run build:data -- --no-wars                    # 전쟁 빼고 전부 (약 30초)
```
- 끝 줄에 `전쟁 장면 캐시: 적중 a · 계산 b`가 나온다. 캐시 없이 처음 계산하면 세계 대전 1 약 1분, 세계 대전 2 약 4분 20초(5분 안이지만 여유가 적으니 다른 명령과 같이 돌리지 않는다), 작은 전쟁 10개는 합쳐 20초 안팎이다. 장면 열쇠에는 설명글·화살표·전투가 들어가지 않으므로 글만 고치면 모두 적중한다.
- 전쟁 계산 코드(`wars.ts`·`geo.ts`·`war-cache.ts`)를 고치면 장면 캐시 전체가 무효가 된다(의도된 동작).
- `--war`는 `public/data`가 이미 있을 때 쓴다(없으면 고른 전쟁만 담아 새로 쓰고 경고). 한 번은 전체 `npm run build:data`가 필요하다.

**지점 검사**: `npm run test:geo -- --only places`(전쟁 지점은 `data/tests/places/war-*.yaml`, 약 6초). 전쟁 지점 한 줄은 `war`·`date`(장면 날짜와 똑같이)·`theater`(전역이 여럿일 때)·`at`·`expect`(진영 id, `none`, 또는 전선 위를 뜻하는 `front` — 어느 진영 경계든 `tolerance` km 안, 기본 5)를 적는다. 겹치는 곳은 마지막 진영이 이긴다(빌드와 같음).
- 새 장면·도시를 더하면 그 도시를 정답표에 한 줄씩 보탠다(도시×날짜 판정표를 대신한다). 새 지점은 `url`이 필수다(`필요`+`legacy: true`는 옛 지점만).
- 전쟁 도형이 지금 입력(전쟁 YAML·손그림 geojson·쓰는 나라의 `data/geo`·빌드 코드)으로 만든 것이 아니면(입력 해시가 `.cache/build-data-wars/built.json`의 기록과 다름) 그 전쟁 지점은 `건너뜀`이고 머리 줄에 `건너뜀 N`이 붙는다. `--ci`에서는 실패다. 위 `--war`로 다시 만든다(파일 시각은 보지 않으므로 `gen:geo`로 시각만 바뀐 것은 문제 없음).
- 전쟁 지점 정답표(`war-*.yaml` 1,242점)는 모두 `legacy`이고, 정답표 전체가 지금 지도와 같은 점만 넣은 회귀 시험이다(지도가 맞다는 사실 확인이 아님). `url: 필요`+`legacy: true` 지점은 근거 확인 전이고, 근거 URL은 그 절의 대표 근거일 수 있어 지점마다의 근거가 아닐 수 있다. 지금 지도와 다른 지점은 `_review-needed.yaml`에 있다(러너가 읽지 않음).
- 실패 줄 예: `✗ places 1943-07-10 world-war-2/europe 시라쿠사 [15.29,37.07] 기대 allies, 실제 axis (경계까지 3.1km)`. 전선을 고쳐야 하면 고치고, 일부러 그렇게 둔 것은 `data/tests/allow/places.yaml`에 `key`(열쇠 그대로)·`reason`·`decided`로 적는다. 아직 판단 못 한 지점은 `data/tests/places/_review-needed.yaml`(러너가 읽지 않음)에 둔다.
- 가는 띠·넓이 0 조각은 `strips`·`zero` 검사가 data/geo 쪽을 본다(전쟁 도형의 조각 수·넓이는 빌드 뒤 `wars.json`에서 따로 뽑아 점검). 자세한 사용법: [border.md](border.md) 5.1.

## 6. 비용 줄이기

- 전쟁 16장면을 4장면씩 구현 에이전트 넷에 나눈다(에이전트 하나 20만 안). 진영 id·색·경계 규칙은 지시문에 박고, 이음매는 마지막에 한 에이전트가 맞춘다.
- 웹 조사는 에이전트당 15번 안팎, 먼저 볼 출처(위키백과 전황도, West Point Atlas, 공식 전사)를 정해 주고 조사 메모를 공유한다.
- 화면 스크린샷은 최소: 판정표와 미리보기 PNG를 쓰고, 사용자에게 보일 한두 장만 찍는다(이미지는 끝까지 다시 읽힘).
- 반영이 '정해진 지점 몇 곳'이면 생성 스크립트 + 지적 파일만 든 새 작은 에이전트에게. 생성 스크립트·입력은 반드시 인계 폴더에 보관(재현성).
- 외부 요청에 개인정보 금지(W2 사고), 정션 붙은 사본 `rm -rf` 금지.
