# 안내서: 국경 작업 (유럽 권역 생성기)

> 대상: 국경 구현·독립 검토·반영 에이전트와 메인. 이 글 하나로 시작하고, 막히는 곳만 `docs/REGION_GUIDE.md`·`docs/DATA_GUIDE.md` §5·`docs/EUROPE_DRAFT.md`의 해당 절을 연다. 공통 함정은 [common-pitfalls.md](common-pitfalls.md).

## 1. 언제 쓰나, 흐름, 모델

국경 한 단계 = 지도에서 1만 km² 안팎 이상 달라지는 땅을 고치거나, 한 시대의 조각 소유표를 더하거나, 손그림 선을 강·해안에 맞춰 다시 긋는 일. 사건 글만 고치면 [event.md](event.md), 전쟁 보기는 [war.md](war.md).

```
메인: 지시문 작성 (이 안내서 + 이번 단계의 정할 점·되풀이하지 말 것)
  → 구현 (Opus) : 사본에서 europe.mjs 등 수정 → gen:geo → 검사 → 적용 묶음(apply.mjs) + 결과 노트
  → 독립 검토 (Opus) : 새 사본에 묶음 적용, 표본 재계산, 웹으로 사실 대조 → review1.md
  → 반영 : 정해진 지점 몇 곳 고치기면 새 작은 에이전트, 설계를 바꾸는 지적이면 처음 구현 에이전트
  → 재검토 : 처음 검토 에이전트를 이어 불러 고친 곳만 (글·주석만 고쳤으면 생략하고 메인이 grep으로 확인)
  → 메인 적용 : apply.mjs → gen:geo → 검사 → 커밋·푸시 → 배포 확인
```

모델: 국경 구현·검토·재검토·메인 적용은 **Opus**(Sonnet 구현은 세션 A의 FIX3에서 1만 km² 넘는 오류 3건이 나와 2026-10-07에 Opus로 되돌림). 측정: 한 단계 구현 55~75만 토큰·1~1.5시간, 독립 검토 25~30만·20분, 반영 10~40분, 재검토 5~9분. 소규모 손질(세션 I)은 구현 35만·55분.

## 2. 고칠 파일과 진입점

| 무엇 | 어디 |
|---|---|
| 유럽 도형·소유표·버전 | `scripts/geo/areas/europe.mjs` (약 1만 줄, 1.3MB — **통째로 읽지 말고 grep**) |
| 나라 항목(이름·색·기간·근거) | `data/entities/europe.yaml` (+ 동아시아는 `china.yaml`·`korea.yaml` 등 짝 파일) |
| 종속·계승·점령 관계 | `data/relations.yaml` |
| 실제로 떨어져 있던 영토 | `data/exclaves.yaml` |
| 두 권역이 같이 쓰는 선(흑룡강 등) | `scripts/geo/shared.mjs` |
| 권역 등록 | `scripts/geo/area-list.mjs`, 화면 필터 `src/schema/regions.ts` |
| 생성 결과(손대지 않음) | `data/geo/*.geojson` — `npm run gen:geo`가 통째로 다시 씀 |

`europe.mjs`의 구조(위에서 아래로, `grep -n '^const T\|^const makeTable\|^const TABLES\|^const LATER_LIST_SEAMS\|^export const versions\|^export const voids' scripts/geo/areas/europe.mjs`로 줄 번호를 찾는다):
1. **머리 주석**: 작업(E1~I1)마다 한 줄 이상. 새 작업은 여기에 줄을 더한다.
2. **선·도형 상수**: `ring([[경도, 위도], …])`(닫힌 링), `bx(서, 남, 동, 북)`(상자). 이름 붙인 선 하나를 이웃이 함께 쓴다(예: 돈강 `DON_W_800BC`, 테르스키 해안 `TERSKY`). 새 선은 **그 표에서만** 쓴다.
3. **`makeTable(첫 해, 끝 해, renames)`** → `{ whole, split, reuse, own, finish }`. 시대마다 표 하나(`T800BC`, `T264BC`, …, `T1992`). `whole(조각 id…)`은 통째 조각, `split(이름, ids, [[부분, 도형]…], 나머지)`는 선으로 자른 단위, `reuse(앞 표에서 나눈 단위)`는 이웃 표와 같은 단위. 모든 조각을 정확히 한 번 쓰고 모든 단위에 주인을 적지 않으면 멈춘다.
4. **`own(단위들, [[해, 나라|null], …])`**: 그 해부터 다음 해 앞까지 그 나라 땅. `null` = 일부러 비운 땅. 실제 예: `own(whole('RU-VOR'), [[1526, null], [1586, RT]]);` (보로네시주는 1526~1585 비우고 1586 보로네시 요새부터 러시아 차르국).
5. **정할 점 모음 `AN4_OPT` 등**: 운영자가 뒤집을 수 있는 기본값(해·true/false)을 줄 하나로 모아 값만 바꾸면 해당 해·주인만 달라지게 한다. 새 정할 점은 여기에 넣는다.
6. **`TABLES`**(가장 이른 표부터 순서대로) → `LATER_LIST_SEAMS`(땅은 같은데 단위 이름이 달라지는 경계 해를 뒤 표의 목록으로 잇는 이음매)·`SAME_LAND_SEAMS`·`UNIT_MERGES` → `TABLE_ENTITIES`(표에서 버전을 만드는 나라 id) → `export const versions`(나라 id: `[[from, to, 도형, 확실성?]]`, `to`는 미포함) → `voids`(일부러 비운 땅을 생성기의 구멍 메우기에서 지킴) → `gapZones`(빈 땅 검사).

새 나라는 `europe.yaml`에 항목(`id`, `level: polity`, `names`, `from`/`to` 천문 연도, `color`, `summary`, `basis.refs`·`foundingNote`에 지도에 그린 해와 근거)을 넣고, 소유표에서 주인으로 쓰고, 종속이면 `relations.yaml`에 `vassal_of`를 단다. 이름만 바뀐 나라는 `makeTable(…, { 옛id: [해, 새id] })`의 renames와 같은 색.

## 3. 기준 (승인된 원칙만, 출처는 `docs/EUROPE_DRAFT.md` 절)

1. **버전은 1만 km² 안팎 이상 바뀔 때만**, 한 버전 = 그해 말 모습. 연도는 천문 연도(기원전 N년 = 1−N). (1절, REGION_GUIDE §5)
2. **해 정하기**: 조약·매매·유증·상속 계약이 있으면 그 해, 5년 이상 휴전은 조약으로 본다. 조약 없는 정복은 실효 지배가 굳은 해(주요 거점이 떨어지고 되찾기지 않은 첫 해의 말). 나라가 무너지면 그해 말 차지한 쪽. (7.3-⑦·D3-③ 7.8, 8.4 M-①, 9.4 AN-⑨)
3. **원정·약탈·되돌려진 점령은 칠하지 않는다.** 점령은 법적 국경 원칙: 점령 항목(`occupied_by`)으로만. (7.3-⑦, 9.4 AN-⑨)
4. **권역 안의 주권 국가는 비우지 않는다.** 권역 밖(중동·북아프리카·레반트)은 그리지 않고, 걸친 나라는 권역 안 부분만. 유럽 밖 식민지는 그리지 않음. (7.3-③⑤, 8.4 M-⑨, 9.4 AN-②③)
5. **종속 왕국·외교를 따로 한 큰 봉토는 따로 항목 + `vassal_of`**, 병합 전까지. 종속 왕국 땅을 조각이 안 맞는다고 종주국 색으로 칠하지 않는다(새 선을 긋는다). (8.4 M-②, 9.4 AN-④)
6. **부족·세력 채우기는 사료가 그 땅의 부족을 적은 때부터**, 그 전은 비운다. 근거가 약한 북쪽 숲(사미·코미 등)은 실효 지배가 굳은 해까지 비움(운영자 결정 2026-10-07). (8.4 M-③, 8.17 FIX3, 9.4 AN-⑧)
7. **이름만 바뀐 나라는 renames로 잇고 같은 색**, 기존 항목의 `from`은 바꾸지 않는다. (8.4 M-⑧, 9.4 AN-⑩)
8. **단계 경계의 이음**: 새 표는 앞 표의 단위를 `reuse`하고, **경계 해 이후의 도형은 바이트까지 그대로**여야 한다(이음매가 필요하면 `LATER_LIST_SEAMS`, 넣기 전에 대칭차 0 확인). (8.4 M-⑪, 9.4 AN-⑪)
9. **맞닿는 나라끼리 색 차이 ΔE 25 이상.** (8.4 M-⑫, 9.4 AN-⑫)
10. **운영자 결정을 뒤집지 않는다.** 판단이 갈리면 기본값 + 정할 점(`X-①…`)으로 올리고 다른 안을 적는다.

## 4. 되풀이하지 말 것 (검토 지적에서 여러 번 나온 것)

- 권역 안 주권 국가를 비움 / 종속 왕국 땅을 종주국으로 칠함(킬리키아 트라케이아 1.73만, 리카오니아 4.94만 km²) / 실제로 다스리지 않은 땅을 칠함.
- **1만 km² 넘는 차이를 '근사' 목록에 숨김**(로렌 2.35만, 오스트리아 1.29만, 피시디아 1.6만): 근사 줄마다 실제 km²를 계산해 적는다.
- 계획(9.1 등)의 버전 해 누락: 계획 줄을 체크리스트로 결과 노트에 표로 대조.
- 조약·양도 해가 있는 땅에 정복 해를 씀(사보이아). 같은 지역 안에서 기준이 갈림(서포메른만 게르만, 골라세카 롬바르디아는 비우고 티치노는 칠함, 루한스크는 사르마티아인데 이웃 도네츠크는 스키타이).
- 경도·위도로 조각을 묶을 때 선 가까이(중심이 0.2° 안)의 조각을 하나씩 확인하지 않음(부다페스트).
- **생성기 동작에 표를 맞춤**: 둘러싸인 빈 땅은 생성기의 구멍 메우기(`engine.mjs keepHoles`)가 채운다(리카오니아·피시디아 6.5만 km²). 비우려면 `voids`. 생성 결과를 보고 근거를 나중에 붙이지 말 것.
- 손으로 어림한 직선으로 강 경계를 그음(돈강이 보로네시 쪽에서 0.1~0.2° 동쪽, 약 1,642 km²). 강·해안은 실제 줄기(Natural Earth 10m 강, OSM 몇십 점, 허용 2km)에 맞추고 지점 판정으로 양쪽 기슭을 보인다. 강선 위 지점은 실제 좌표를 써서 확인(티르 139.76, 52.93은 선 위라 엉뚱하게 판정됨).
- **천문 연도 변환 실수**: 기원전 189를 −189로, '108년까지 비움'이 실제로는 109년까지, 항목 `to`(포함)와 영토 `to`(미포함)를 섞음. 글의 '~년까지/~년부터'를 표의 해와 하나씩 대조.
- **해를 고친 뒤 옛 해가 글에 남음**: 항목 `foundingNote`, 생성기 주석, EUROPE_DRAFT의 결정 줄, 사건의 '지도는 ~년부터' 문장. 고친 해를 `grep`으로 전수 조사하고 출처 줄에 '(세션 X에서 고침)'을 단다.
- 근거 URL에 그 내용이 없음(고르비차 '발원지'). 근거는 실제로 그 쪽에 있는 문장만.
- 작은 땅(1만 km² 미만)에 새 버전 해를 만들어 규칙이 일관되지 않음(카타나 −262).
- 대략 도형(TIBET·CHINA)의 직선이 실제 국경과 엇갈리면 덮음과 빈 곳이 함께 생긴다(라다크 4,910 km² 덮음 ↔ 응아리 10,217 km² 빔, 세션 L). 한쪽만 재지 말고 이웃 나라 덮음과 빠진 자기 땅을 같은 상자로 함께 잰다.
- 새 항목의 `vassal_of` 누락(라지카), 6절 '다음' 줄에 끝난 단계 문구가 남음, 문서의 버전 해 표기가 실제와 다름.

## 5. 검사 (순서대로, 출력은 파일로 받아 필요한 줄만)

적용 묶음 = `apply.mjs`(기준 HEAD 확인, `--dry-run`, 고칠 파일은 LF 기준 sha256 대조 후 **원래 줄바꿈(CRLF) 유지**, 새 파일은 LF) + `manifest.json` + `files/` + `COMMIT_MSG.txt`(한국어, 마지막 줄 Co-Authored-By). 본보기: 인계 폴더 `apply-template.mjs`. 사본에는 원본 CRLF 파일을 덮어쓰지 말고 clone 그대로 쓴다. `apply.mjs` 출력은 파이프로 자르지 않는다.

```
node apply.mjs <사본> --dry-run  →  node apply.mjs <사본>
npm run gen:geo                     # 60~90초. 뒤의 git status 파일 수 = 묶음 파일 수여야 함
npm run compare:geo                 # 종료 1이 정상(바뀐 파일 목록). 경계 해 이후·한국사 파일은 바이트 같음 확인
npm run check:data                  # 6~18분(캐시 없이 첫 빌드 약 18분). 경고 수는 bash: grep -c '^  경고'  (기준 52)
npm run check:gaps | check:exclaves | typecheck | build | check:generator(약 3.5분)
node ../history-map-handoff/pt-dh.mjs . '<[[이름,경도,위도],…] JSON>' '<[연도,…] 또는 {"from":a,"to":b}>'   # 서울은 바뀌지 않아야
node ../history-map-handoff/tools/lifecycle.mjs <repo 절대경로> 476 2026    # 성립·소멸 미연결
node ../history-map-handoff/tools/versions2.mjs <repo 절대경로> 476 2026 10000   # 1만 km² 넘는 버전 해 미연결
```

### 5.1 지형 테스트 `npm run test:geo`와 부분 빌드

위 `compare:geo`·`check:gaps`·지점 판정·`lifecycle`·`versions2` 확인을 한 명령으로 묶은 것이다. 새 명령 하나가 5분을 넘지 않는다(캐시가 따뜻하면 전체 약 1~2분).

```
npm run test:geo                                       # 전체: 요약 15줄 안, 자세한 것은 .cache/test-geo/report.md
npm run test:geo -- --region europe --years 1500-1600  # 범위를 좁힘 (권역: europe·east-asia 또는 korea 같은 항목 파일 이름)
npm run test:geo -- --only places,lines                # 검사 고르기 (--skip islands, 검사 id 또는 파일 이름 places·shapes·events·lines)
npm run test:geo -- --ci                               # 느린 gen(data/geo가 생성기 결과와 같은가, 약 30초)까지 — 단계 끝에 한 번
npm run test:geo -- --update-baseline <검사 id>        # 기준선을 지금 결과로 다시 씀(범위 인자와 같이 못 씀)
```
여러 에이전트가 동시에 돌리면 `HISTORY_MAP_WORKERS=4`. 종료 코드: 새 실패가 있으면 1, 인자 오류나 검사 예외면 2, 아니면 0.

| 검사 id | 보는 것 | 국경 작업에서 |
|---|---|---|
| `places` | 정답표(`data/tests/places/*.yaml`) 지점의 소속: 평소 지도 273점, 전쟁 보기 1,242점 | 지점 판정(pt-dh)을 대체. 새로 확인한 지점을 정답표에 더한다. 정답표는 지금 지도와 같은 점만 넣은 회귀 시험이다(지도가 맞다는 사실 확인이 아님). `url: 필요`+`legacy: true` 지점은 근거 확인 전이고, 근거 URL은 그 절의 대표 근거일 수 있어 지점마다의 근거가 아닐 수 있다. 지금 지도와 다른 지점은 `_review-needed.yaml`에 있다(러너가 읽지 않음). |
| `gaps` | 덮이지 않은 육지(500km² 초과, `check:gaps`와 같은 칸·캐시), 기준선 734칸(동아시아 4구역)보다 총넓이가 500km² 넘게 늘거나 큰 조각 3개 가운데 기준선에 없는 상자가 나타나면 실패. `--years`를 좁혀도 범위 시작에 이미 효력이 있는 상태(그 전의 가장 늦은 바뀌는 해 칸)를 본다 | 유럽은 기준선 0 — 새 빈 땅은 모두 실패 |
| `overlap` | 영토 겹침(5km² 초과 실패, 0.5~5km² 경고) | `check:data`와 캐시 공유 |
| `strips`·`zero`·`islands` | 폭 1km 미만 가는 띠, 넓이 0 조각, 앞 버전이 덮던 섬이 사라짐 | 옛 빚은 기준선 안, 새로 생기면 실패 |
| `events` | 성립·소멸 ±2년, 1만 km² 넘는 버전 해에 사건이 이어졌는가 | `lifecycle`·`versions2`와 줄 단위로 같은 결과 |
| `lines` | 손그림 선(`// @기준선 강 <키> [허용 N km] [평균 M km]` 꼬리표 단 `L_` 상수)과 Natural Earth 강 사이의 거리. 최대가 허용을 넘거나 평균이 꼬리표의 평균 값을 넘으면 실패(평균은 허용 아래에서 선이 나빠지는 것을 잡으려고 지금 평균을 적어 둔 것, 선을 고쳐 줄면 값도 줄인다) | 새 강 경계 선을 그으면 꼬리표를 단다([DATA_GUIDE](../DATA_GUIDE.md)) |
| `gen` | `data/geo` 519개가 생성기 결과와 바이트까지 같은가 | `--ci`나 `--only gen`일 때만 |

**출력 읽는 법**: 머리 줄(범위·걸린 시간·실패 수) → 검사마다 한 줄(`통과`·`실패`·`건너뜀`·`오류`, 검사한 수, 기준선·알려진 예외 수, 걸린 시간) → `✗` 새 실패 위 5건 → `!` 경고 → 보고서 경로. 건너뜀은 이유가 같은 줄에 있다(검사 파일 없음, `--ci`에서만, 전쟁 도형이 오래됨 등). 검사가 항목을 건너뛰면(결과가 낡은 전쟁 지점) 머리 줄에 `건너뜀 N`이 붙고 places 줄에 `전쟁 건너뜀 N`이 나온다. **`--ci`에서는 건너뜀이 실패다**(건너뛴 채 통과하지 않게).
- 전쟁 지점이 `건너뜀`이면 그 전쟁의 `public/data` 결과가 지금 입력으로 만든 것이 아니다. 판정은 파일 시각이 아니라 내용 해시다: `build:data`가 전쟁마다 입력(전쟁 YAML·손그림 geojson·쓰는 나라의 `data/geo` 파일·`wars.ts`·`geo.ts`·`war-cache.ts`·육지 파일)의 해시와 출력의 해시를 `.cache/build-data-wars/built.json`에 남기고, places가 같은 해시를 다시 계산해 비교한다. `npm run build:data -- --war <id>`로 다시 만든다. `gen:geo`를 돌려도 바이트가 같으면 입력 해시가 그대로라 다시 만들 필요가 없다.
- `lines` 꼬리표를 단 선 가운데 지도 FIX 후보: `L_LIAO`(요하, 최대 21km·평균 10km)·`L_VOLKHOV`(볼호프, 평균 6km)·`L_YALU_TUMEN` 압록강 쪽(평균 6km). 두만강 쪽(최대 8km)과 꼬리표가 없는 선(`L_PRZEMSZA`·`L_CONGRESS_W`·`L_FUYUAN`·`L_VISTULA_UP` 올자강 구간)은 Natural Earth에 강이 없거나 근사라 잴 수 없다.
- `오류`는 검사 자체가 예외를 던진 것(종료 코드 2). 보고서의 스택을 본다.

**실패를 처리하는 세 길** (판단은 사람이: 지도가 틀렸으면 고치고, 일부러 그런 것만 허용)
1. 지도 오류 → `europe.mjs` 등을 고쳐 다시 돌린다.
2. 의도한 예외 → `data/tests/allow/<파일>.yaml`(`places`·`shapes`·`events`·`lines`, 파일 하나가 그 그룹의 모든 검사를 덮음)에 `key`(실패 줄의 열쇠 그대로, 끝에 `*` 하나는 앞부분 일치)·`reason`(이유)·`decided`(누가 언제)를 적는다. 맞는 항목이 없어진 줄은 `낡음` 경고가 뜨니 지운다.
3. 옛 빚 → 기준선(`data/tests/baseline/<검사 id>.txt`, `gaps`·`strips`·`zero`·`islands`). 고쳐서 줄었을 때만 `--update-baseline <검사 id>`로 다시 쓴다(`gaps`는 `--only gaps --update-baseline gaps`). 새 실패를 덮으려고 기준선을 늘리지 않는다.

**부분 빌드**: `check:data` 전체는 6~18분이지만 캐시가 따뜻하면 약 18초다. 줄이는 법은 아래.
```
npm run build:data -- --check --region europe     # 검사만, 겹침·월경지를 그 권역 것만 (europe 약 17초, east-asia 약 7초; 따뜻하면 전체와 차이 작음)
npm run build:data -- --events-only               # 사건·나라 YAML만 고쳤을 때: entities·relations·events.json만 (약 2초)
npm run build:data -- --no-wars                   # 전쟁 빼고 전부 (약 30초). public/data/wars는 그대로 둠
```
전체 `build:data`·`check:data`·`check:generator`는 단계 끝에 한 번만(메인). `compare:geo`는 종료 1이 정상(바뀐 파일 목록)인 옛 절차 그대로 쓴다.

`test:geo`의 `events` 검사(두 도구와 같은 결과, 허용 10건은 `data/tests/allow/events.yaml`)나 lifecycle·versions2를 고치기 전·후 전체(−800~2026)로 돌려 비교하고 **새 미연결이 없어야** 한다(기준: 성립·소멸 2건 초원 부족 935·탐라 1104, 버전 해 2곳 몽골 1509·미국 1848 — 모두 운영자 결정으로 남김). 새로 생긴 1만 km² 넘는 버전 해는 기존 사건의 기간·subjects·글로 잇는다([event.md](event.md) 2절).

지점 판정 표: 고친 해와 그 앞뒤 해, 이웃 땅, 서울. 판정마다 사실/근사/정할 점을 적는다. 문서: `docs/europe/06-progress-table.md` 진행 표 줄 + `docs/europe/06-open-items.md` '다음' 줄, 해당 시대 파일의 정할 점 절, 출처 줄 표시, `europe.mjs` 머리 주석 줄. 해시는 메인이 커밋 뒤 채운다.

## 6. 비용 줄이기 (HANDOFF '토큰 절약 규칙'에서)

- 구현 에이전트 하나의 대화를 20만 안으로: 시대·지역 표 단위로 나누고, 공통 기준은 지시문에 박는다. 이음매는 마지막에 한 번.
- 명령 하나는 5분 안(하위 에이전트 캐시 약 5분). 전체 check:data·build는 단계 끝에 한 번, 가능하면 메인이.
- `docs/EUROPE_DRAFT.md`는 색인(1~5절과 절 번호 → 파일 표)이다. 색인 + `docs/europe/06-open-items.md`(남은 과제·다음) + 이번 시대 계획 파일만 읽고, `europe.mjs`는 grep으로 표 블록만. 이 안내서 + 지시문으로 시작하고 빌드 코드·스키마를 처음부터 뒤지지 않는다.
- 지점 판정은 한 스크립트에 지점 표를 넣어 한 번에(검토가 찾은 오류 지점은 회귀 표에 한 줄씩 보태기).
- 반영: 지점 몇 곳 고치기는 새 작은 에이전트(생성기 + 지적 파일만), 설계 변경만 처음 에이전트. 검토는 표본 감사 — 사실 대조와 의심 지점 재계산에 집중.
- 보고는 10줄 안팎, 자세한 것은 결과 노트 파일.
