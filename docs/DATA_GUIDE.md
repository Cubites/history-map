# 데이터 작업 가이드

역사 데이터를 추가하거나 고치는 방법입니다. 구조와 설계 이유는 [DESIGN.md](DESIGN.md) §4, §5를 참고하세요.

## 0. 작업 흐름 한눈에 보기

1. `data/` 아래 파일을 고친다 (나라·사건·관계는 YAML, 국경은 QGIS로 GeoJSON)
2. `npm run check:data`로 검증한다. 오류가 나면 메시지를 보고 고친다 (§6)
3. `npm run dev`로 화면에서 확인한다
4. 커밋하고 push하면 GitHub Actions가 다시 검증한 뒤 배포한다

```
data/
  entities/*.yaml   나라·지역 (권역별 파일)
  events/*.yaml     사건 (시대별 파일)
  relations.yaml    나라 사이의 관계
  geo/<나라 id>.geojson   영토 폴리곤 (나라 하나당 파일 하나, 기간별 버전을 feature로)
```

> 현재 들어 있는 600~700년 데이터는 기능 확인용 **샘플**입니다. 국경은 대략적인 추정이고 서술과 출처도 검수가 필요합니다. 실제 데이터로 교체해 주세요.

## 1. 연도 적는 법 (가장 중요)

모든 연도는 **천문 연도**로 적습니다. 서기는 그대로, 기원전은 `1 - 기원전 연도`입니다. 서기 0년이 없어서 생기는 계산 오류를 막기 위한 규칙입니다.

| 실제 연도 | 적는 값 |
|-----------|---------|
| 서기 668년 | `668` |
| 서기 1년 | `1` |
| 기원전 1년 | `0` |
| 기원전 57년 (신라 건국) | `-56` |
| 기원전 2333년 (고조선 건국) | `-2332` |

화면에서는 자동으로 "기원전 57년"처럼 표시됩니다.

**기간의 끝을 적는 방식이 두 가지입니다.**

| 대상 | `to`의 의미 | 예 |
|------|-------------|----|
| 나라 (`entities`) | **마지막으로 존재한 해** (포함) | 고구려 `to: 668` → 668년까지 존재 |
| 영토 (`geo`) | **이 국경이 바뀌는 해** (미포함) | `from: 600, to: 668` → 600~667년의 국경. 668년 지도부터는 다음 버전 |
| 관계 (`relations`) | 마지막 해 (포함) | |

`to: null`은 "현재까지"입니다.

## 2. 나라 추가 (`data/entities/*.yaml`)

```yaml
- id: goguryeo            # 소문자·숫자·하이픈. 다른 파일에서 이 id로 가리킴
  level: polity           # 나라는 polity, 지역(도·주)은 region
  names: { ko: 고구려, hanja: 高句麗, en: Goguryeo }
  from: -36               # 기원전 37년
  to: 668
  color: "#c8745a"        # 선택. 없으면 기본 팔레트에서 자동 배정
  summary: 한 줄 설명      # 선택
  basis:                  # 수록 근거 (나라는 필수)
    type: primary_source  # primary_source: 사료로 확인 / national_institution: 그 나라 역사기관이 인정
    refs: ["『삼국사기』 고구려본기"]
    foundingNote: 건국 연대(기원전 37년)는 『삼국사기』의 기록에 따름   # 선택. 패널에 표시됨
```

**수록 기준** (DESIGN.md §11.1): 사료로 존재가 확인되었거나 그 나라 역사기관이 인정한 나라만 추가합니다. `basis.refs`가 비어 있으면 빌드가 실패합니다.

**값에 쉼표(,)가 들어가면 따옴표로 감싸세요.** `{ ... }` 한 줄 형식 안에서는 쉼표가 항목 구분자로 읽힙니다.

```yaml
note: "매소성·기벌포 승리, 당군 축출"   # O
note: 매소성·기벌포 승리, 당군 축출      # X (YAML 오류)
```

## 3. 사건 추가 (`data/events/*.yaml`)

```yaml
- id: silla-tang-alliance-648      # 소문자·숫자·하이픈, 전체에서 유일
  year: 648
  endYear: 676                     # 선택. 전쟁처럼 기간이 있을 때
  title: { ko: 나당 동맹 }
  summary: { ko: 김춘추가 당에 건너가 군사 동맹을 맺었다. }
  subjects: [silla, tang]          # 이 사건이 목록에 나올 나라들
  links:                           # 영향 관계 (화살표). 선택
    - { from: silla, to: tang, note: 김춘추의 외교 }
    - { from: tang, to: silla, note: 군사 동맹 약속 }
  tags: [diplomacy]                # 선택: war, diplomacy, politics, culture ...
  sources: ["『삼국사기』 신라본기 진덕왕 2년"]   # 필수
```

**`links`와 화살표**: 화면에서 선택한 나라를 기준으로 방향이 정해집니다.

| 선택한 나라가 | 화살표 |
|---------------|--------|
| link의 `to` | 들어오는 화살표 (파랑 실선): `from` 나라 → 선택한 나라 |
| link의 `from` | 나가는 화살표 (주황 점선): 선택한 나라 → `to` 나라 |
| 둘 다 아님 | 화살표 없음 (목록에만 회색으로 표시) |

그래서 여러 나라가 얽힌 사건도 **한 번만** 적으면 됩니다. 예를 들어 백강 전투는 왜·당·신라 중 누구를 선택하든 그 나라 기준으로 화살표가 나뉩니다.

**검증 규칙**: `subjects`와 `links`의 나라는 모두 **사건 연도(`year`)에 존재**해야 합니다. 예를 들어 663년 백강 전투에 멸망한 백제(660)를 넣으면 오류입니다. 백제 부흥군처럼 나라가 아닌 세력은 `summary`에 서술합니다.

## 4. 관계 추가 (`data/relations.yaml`)

```yaml
- { type: successor_of, subject: balhae, object: goguryeo, from: 698, to: null }
- { type: occupied_by, subject: ungjin-dodokbu, object: tang, from: 660, to: 676 }
```

**점령지를 표시하려면**: 점령당한 지역을 따로 나라·지역 항목으로 만들고(`level: region`, 색은 옛 나라의 색), 그 지역의 영토를 그린 뒤 `occupied_by` 관계를 추가합니다. 점령한 나라의 영토에는 그 지역을 넣지 않습니다. 예: 웅진도독부(옛 백제 땅, 당이 점령), 안동도호부(옛 고구려 땅, 당이 점령). 일제강점기도 같은 방식입니다.

| type | 뜻 | 화면 |
|------|----|------|
| `successor_of` | subject가 object를 계승 | 사라진 나라를 선택하면 "후계 국가" 링크 |
| `occupied_by` | subject가 object에 점령·강점됨 | subject 색 위에 object 색으로 빗금. 패널에 "○○의 점령지" 표시 |
| `vassal_of` | subject가 object에 종속·간섭을 받음 | subject 테두리를 object 색으로 굵게. 패널에 "○○의 간섭·종속" 표시 |
| `part_of` | 지역이 나라에 속함 | (예정) 지역 단위 보기 |

## 5. 국경 그리기 (QGIS)

[QGIS](https://qgis.org/)(무료)로 `data/geo/*.geojson`을 편집합니다.

### 5.1 처음 한 번 준비

1. **QGIS 설치 후 새 프로젝트**를 만들고 프로젝트 좌표계를 **EPSG:4326 (WGS 84)**로 둡니다 (오른쪽 아래 좌표계 표시).
2. **참고용 배경 지도**: 탐색기 패널 → XYZ Tiles → OpenStreetMap을 더블클릭합니다. 현대 지명과 해안선을 보며 그릴 수 있습니다.
3. **해안선 레이어** (선택): `npm run build:data`를 한 번 실행하면 생기는 `public/data/land-high.topo.json`을 레이어로 끌어다 놓습니다. 빌드에서 국경을 자를 때 쓰는 해안선(Natural Earth 1:50m)과 같은 것입니다.
4. **나라 레이어 열기**: `data/geo/` 안의 `.geojson` 파일들을 QGIS 창으로 끌어다 놓습니다.
5. **스냅 켜기**: 메뉴 프로젝트 → 스냅 옵션(Snapping Options)
   - 스냅 사용, 대상: **모든 레이어**, 종류: **꼭짓점과 선분**, 허용 오차: 10~12 픽셀
   - **위상 편집(Topological editing)** 켜기: 공유 경계의 꼭짓점을 옮기면 이웃 나라 경계도 같이 움직입니다.
   - **추적(Tracing)** 켜기 (단축키 `T`): 이웃 나라 경계를 따라 클릭 몇 번으로 선을 그릴 수 있습니다.

### 5.2 그릴 때 규칙

- **바다 쪽은 대충 그리세요.** 폴리곤을 해안선 바깥 바다까지 넉넉하게 그리면 빌드가 Natural Earth 해안선에 맞춰 자동으로 자릅니다. 신경 쓸 곳은 **육지 위의 국경선**뿐입니다.
- **이웃 나라와는 경계를 공유하세요.** 스냅이나 추적으로 이웃 나라의 경계 꼭짓점을 그대로 따라가면 틈이나 겹침이 생기지 않습니다. 겹침이 5km²를 넘으면 빌드가 실패합니다.
- 섬이 여럿이면 한 feature 안에서 여러 조각(멀티폴리곤)으로 그려도 됩니다.

### 5.3 새 나라의 영토 만들기

1. 기존 파일 하나(예: `baekje.geojson`)를 복사해 `data/geo/<새 id>.geojson`으로 저장하고 QGIS에서 엽니다. 속성 필드가 이미 갖춰져 있어서 새 레이어를 만드는 것보다 간단합니다.
2. 편집 모드를 켜고(연필 아이콘) 기존 feature를 지운 뒤 **폴리곤 추가** 도구로 그립니다.
3. 속성 입력 창에 아래 값을 넣습니다.

| 필드 | 값 | 예 |
|------|----|----|
| `entityId` | 나라 id (파일 이름과 같게) | `goguryeo` |
| `from` | 이 국경이 시작되는 해 | `600` |
| `to` | 이 국경이 바뀌는 해 (미포함). 계속되면 비워 둠(NULL) | `668` |
| `certainty` | `confirmed` / `estimated`(점선) / `disputed`(점선) | `estimated` |
| `source` | 국경의 근거 자료 | `『한국사』 ○권 지도` |

### 5.4 국경이 바뀐 시기 추가 (새 버전)

국경은 **바뀔 때만** 새 버전을 만듭니다. 다음 변화 전까지는 같은 국경이 유지됩니다.

1. 편집 모드에서 이전 버전 feature를 선택하고 **복사(Ctrl+C) → 붙여넣기(Ctrl+V)**합니다.
2. 붙여넣은 feature의 꼭짓점을 **꼭짓점 도구**로 고칩니다.
3. 속성 표에서 **이전 버전의 `to`**와 **새 버전의 `from`**을 같은 해(국경이 바뀐 해)로 맞춥니다.
   - 이전 버전 `from: 600, to: 671` → 새 버전 `from: 671, to: 676`
4. 저장합니다(편집 모드 끄기 → 저장).

### 5.5 저장할 때 주의

- 좌표계는 반드시 **EPSG:4326**이어야 합니다. 다른 좌표계로 저장하면 빌드가 "경위도 범위를 벗어난 좌표" 오류를 냅니다.
- "다른 이름으로 저장"을 쓸 때는 형식 **GeoJSON**, 좌표계 **EPSG:4326**을 고르고, 레이어 옵션 `COORDINATE_PRECISION`을 5 정도로 두면 파일이 작아집니다 (약 1m 정밀도).
- 폴리곤의 감긴 방향(시계/반시계)은 신경 쓰지 않아도 됩니다. 빌드가 알아서 맞춥니다.

## 6. 검증 메시지 읽는 법

`npm run check:data`는 문제가 있으면 **오류**(빌드 실패)와 **경고**(빌드는 됨)를 보여 줍니다.

| 메시지 | 원인 | 해결 |
|--------|------|------|
| `YAML 문법 오류` | 들여쓰기, 따옴표, 한 줄 형식 안의 쉼표 | §2의 쉼표 규칙 확인 |
| `수록 근거(refs)가 비어 있음` | 나라의 `basis.refs` 없음 | 사료나 기관 자료 적기 |
| `'xxx'는 N년에 존재하지 않음` | 사건 연도에 없던 나라를 참조 | 나라의 `from`/`to` 또는 사건 연도 확인 |
| `영토 기간 [...]이 xxx의 존속 기간 ...을 벗어남` | 영토 버전이 나라 존속 기간 밖 | 영토 `to`는 "바뀌는 해"(미포함)라는 점 확인 |
| `영토 기간이 앞 버전과 겹침` | 같은 나라의 두 버전 기간이 겹침 | 이전 버전 `to`와 새 버전 `from`을 같은 해로 |
| `A와 B의 영토가 약 N km² 겹침` | 이웃 나라 폴리곤이 겹침 | QGIS 스냅으로 경계 공유 |
| `경위도 범위를 벗어난 좌표` | 좌표계가 EPSG:4326이 아님 | §5.5 |
| `해안선으로 자르고 나니 육지가 남지 않음` | 폴리곤이 전부 바다 위 | 위치 확인 |
| 경고 `N~M년 영토 없음` | 영토 버전 사이에 빈 기간 | 의도한 것이 아니면 기간 이어 붙이기 |
| 경고 `영토 데이터가 없어 화살표를 그릴 수 없음` | 사건 links의 나라에 영토가 하나도 없음 | 그 나라의 영토 추가 |

## 7. 제보 반영

GitHub Issue의 "역사 데이터 제보" 양식으로 들어온 제보는 다음 순서로 반영합니다 (DESIGN.md §11.2).

1. 제보의 **증거 사료를 직접 확인**합니다. 사료가 없거나 확인되지 않으면 반영하지 않습니다.
2. 제보자의 문장을 복사하지 않고 **직접 새로 작성**합니다. 모든 데이터의 저작권을 운영자 한 명에게 두기 위해서입니다.
3. 사료를 `sources`(사건) 또는 `source`(영토)에 적습니다.
4. 제보자가 원하면 [CREDITS.md](../CREDITS.md)에 기록합니다.
