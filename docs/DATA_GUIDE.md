# 데이터 작업 가이드

역사 데이터를 추가하거나 고치는 방법입니다. 구조와 설계 이유는 [DESIGN.md](DESIGN.md) §4, §5를 참고하세요.

## 0. 작업 흐름 한눈에 보기

1. `data/` 아래 파일을 고친다 (나라·사건·관계는 YAML). 국경은 `data/geo`가 아니라 국경 생성기의 권역 파일(`scripts/geo/areas/`)을 고치고 `npm run gen:geo`로 `data/geo`를 다시 만든다 (§5)
2. `npm run check:data`로 검증한다. 오류가 나면 메시지를 보고 고친다 (§6)
3. `npm run dev`로 화면에서 확인한다
4. 커밋하고 push하면 GitHub Actions가 다시 검증한 뒤 배포한다

```
data/
  entities/*.yaml   나라·지역 (권역별 파일)
  events/*.yaml     사건 (한국사는 시대별 파일 01~08, 다른 권역은 권역 머리글자 파일. 예: eu-01)
  relations.yaml    나라 사이의 관계
  geo/<나라 id>.geojson   영토 폴리곤 (나라 하나당 파일 하나, 기간별 버전을 feature로. 국경 생성기가 만듦)
scripts/
  generate-geo.mjs  국경 생성기 진입 파일 (npm run gen:geo)
  geo/area-list.mjs 권역 목록 AREAS (생성기와 빈 땅 검사가 함께 씀)
  geo/areas/*.mjs   권역 파일: 권역마다 도형과 나라별 기간 영토 (data/entities의 같은 이름 YAML과 짝)
```

> 현재 들어 있는 600~700년 데이터는 기능 확인용 **샘플**입니다. 국경은 대략적인 추정이고 서술과 출처도 검수가 필요합니다. 실제 데이터로 교체해 주세요.

## 1. 연도 적는 법 (가장 중요)

모든 연도는 **천문 연도**로 적습니다. 서기는 그대로, 기원전은 `1 - 기원전 연도`입니다. 서기 0년이 없어서 생기는 계산 오류를 막기 위한 규칙입니다.

| 실제 연도 | 적는 값 |
|-----------|---------|
| 서기 668년 | `668` |
| 서기 1년 | `1` |
| 기원전 1년 | `0` |
| 기원전 57년 (신라 건국) | `-56` |
| 기원전 2333년 (고조선 건국) | `-2332` |

화면에서는 자동으로 "기원전 57년"처럼 표시됩니다.

**기간의 끝을 적는 방식이 두 가지입니다.**

| 대상 | `to`의 의미 | 예 |
|------|-------------|----|
| 나라 (`entities`) | **마지막으로 존재한 해** (포함) | 고구려 `to: 668` → 668년까지 존재 |
| 영토 (`geo`) | **이 국경이 바뀌는 해** (미포함) | `from: 600, to: 668` → 600~667년의 국경. 668년 지도부터는 다음 버전 |
| 관계 (`relations`) | 마지막 해 (포함) | |

`to: null`은 "현재까지"입니다.

## 2. 나라 추가 (`data/entities/*.yaml`)

```yaml
- id: goguryeo            # 소문자·숫자·하이픈. 다른 파일에서 이 id로 가리킴
  level: polity           # 나라는 polity, 지역(도·주)은 region
  names: { ko: 고구려, hanja: 高句麗, en: Goguryeo }
  from: -36               # 기원전 37년
  to: 668
  color: "#c8745a"        # 선택. 없으면 기본 팔레트에서 자동 배정
  summary: 한 줄 설명      # 선택
  basis:                  # 수록 근거 (나라는 필수)
    type: primary_source  # primary_source: 사료로 확인 / national_institution: 그 나라 역사기관이 인정
    refs: ["『삼국사기』 고구려본기"]
    foundingNote: 건국 연대(기원전 37년)는 『삼국사기』의 기록에 따름   # 선택. 패널에 표시됨
```

**원어 표기**: 한자가 아닌 원어 이름은 `names`의 `native`에 적는다(예: `native: Königreich Preußen`). 한자 이름(`hanja`)이 없을 때 그 자리에 보이고 검색에도 쓰인다 (2026-10-02).

**수록 기준** (DESIGN.md §11.1): 사료로 존재가 확인되었거나 그 나라 역사기관이 인정한 나라만 추가합니다. `basis.refs`가 비어 있으면 빌드가 실패합니다.

**값에 쉼표(,)가 들어가면 따옴표로 감싸세요.** `{ ... }` 한 줄 형식 안에서는 쉼표가 항목 구분자로 읽힙니다.

```yaml
note: "매소성·기벌포 승리, 당군 축출"   # O
note: 매소성·기벌포 승리, 당군 축출      # X (YAML 오류)
```

## 3. 사건 추가 (`data/events/*.yaml`)

```yaml
- id: silla-tang-alliance-648      # 소문자·숫자·하이픈, 전체에서 유일
  year: 648
  endYear: 676                     # 선택. 전쟁처럼 기간이 있을 때
  title: { ko: 나당 동맹 }
  summary: { ko: 김춘추가 당에 건너가 군사 동맹을 맺었다. }
  subjects: [silla, tang]          # 이 사건이 목록에 나올 나라들
  links:                           # 영향 관계 (화살표). 선택
    - { from: silla, to: tang, note: 김춘추의 외교 }
    - { from: tang, to: silla, note: 군사 동맹 약속 }
  tags: [diplomacy]                # 선택: war, diplomacy, politics, culture ...
  sources: ["『삼국사기』 신라본기 진덕왕 2년"]   # 필수
  # places: [{ name: 관산성, at: [127.57, 36.3] }]   # 선택: 싸운 곳 (전쟁 보기가 없는 전쟁·전투)
```

**파일 나누기**: 한국사 사건은 시대별 파일(`01-gojoseon.yaml`~`08-contemporary.yaml`)에, 다른 권역의 사건은 `<권역 머리글자>-<번호>-<내용>.yaml`(예: 유럽 `eu-01-revolutions-1789-1914.yaml`)에 둡니다. 빌드는 `data/events`의 YAML을 모두 읽습니다. 파일 이름 앞머리는 그 사건의 권역도 정합니다(`eu-` → 유럽, 두 자리 수로 시작 → 한국사. 화면의 권역 필터에 쓰임, `docs/DESIGN.md` §6.4.2·`src/schema/regions.ts`). 둘 다 아닌 이름(예: `notes.yaml`, 등록하지 않은 `me-01-….yaml`)은 빌드가 멈춥니다. 새 권역의 앞머리를 쓰려면 `regions.ts`의 `STORY_FILE_PREFIXES`에 한 줄을 더합니다. 한국사 파일에 이미 있는 사건(예: 거문도 사건, 삼국 간섭)은 권역 파일에 다시 만들지 말고 서술에서 이름만 언급합니다 (2026-10-04).

**`places`**: 전쟁 보기(`front`)가 없는 전쟁·전투 사건에 싸운 곳을 적으면, 사건 기간의 지도에 작은 전투 표시(⊗)가 나타납니다. 누르면 그 사건이 패널에 열립니다. 전쟁 보기가 있는 사건에는 적지 않습니다. 기간이 긴 사건은 장소마다 `year`(그 장소에서 싸운 해, 기간이면 `[from, to]`)를 적으면 그 해에만 표시가 보입니다(예: `{ name: 젠타, at: [20.08, 45.93], year: 1697 }`). 없으면 사건 기간 내내 보입니다. `year`는 사건 기간 안이어야 하고, 밖이면 빌드가 멈춥니다(2026-10-06).

**`links`와 화살표**: 화면에서 선택한 나라를 기준으로 방향이 정해집니다.

| 선택한 나라가 | 화살표 |
|---------------|--------|
| link의 `to` | 들어오는 화살표 (파랑 실선): `from` 나라 → 선택한 나라 |
| link의 `from` | 나가는 화살표 (주황 점선): 선택한 나라 → `to` 나라 |
| 둘 다 아님 | 화살표 없음 (목록에만 회색으로 표시) |

그래서 여러 나라가 얽힌 사건도 **한 번만** 적으면 됩니다. 예를 들어 백강 전투는 왜·당·신라 중 누구를 선택하든 그 나라 기준으로 화살표가 나뉩니다.

**검증 규칙**: `subjects`와 `links`의 나라는 모두 **사건 기간(`year`~`endYear`, `endYear`가 없으면 `year` 한 해)과 존재 기간이 겹쳐야** 합니다. 예를 들어 663년 백강 전투(한 해 사건)에 멸망한 백제(660)를 넣으면 오류입니다. 백제 부흥군처럼 나라가 아닌 세력은 `summary`에 서술합니다. 기간이 있는 사건에는 그 기간 중에 생기거나 없어진 나라도 넣을 수 있습니다. 예를 들어 에스파냐 왕위 계승 전쟁(1701~1714)에는 1707년에 합쳐진 잉글랜드(~1707)와 영국(1707~)을 함께, 4국 동맹 전쟁(1718~1720)에는 1720년에 생긴 사르데냐 왕국을 넣습니다 (2026-10-06에 '사건 연도에 존재'에서 넓힘, `docs/EUROPE_DRAFT.md` 7.3-⑥). 화면에서 전투 표시(⊗)나 검색 결과를 누르면 그 해에 있던 나라 가운데 첫 주체의 패널이 열리고, 그 해에 있던 주체가 없으면 사건 기간과 그 주체의 존재 기간이 겹치는 구간에서 가장 가까운 해로 옮겨 엽니다(`src/lib/events.ts`의 `focusTarget`). 패널에서 사건이나 앞뒤 사건 단추를 누를 때도 선택한 나라가 있던 해로 맞춰 옮깁니다(`eventYearFor`). 화살표는 사건 연도의 영토, 그 해에 영토가 없으면 시간상 가장 가까운 영토를 기준점으로 씁니다.

**영토 없는 귀속 후보**: 영토가 없는 귀속 후보 항목(예: 코소보 공화국 `kosovo`)은 `subjects`에만 두고, 화살표(`links`)는 그 땅의 지역 항목(예: `kosovo-disputed`)으로 대신합니다. 영토가 없으면 화살표를 그릴 수 없기 때문입니다 (2026-10-04).

## 4. 관계 추가 (`data/relations.yaml`)

```yaml
- { type: successor_of, subject: balhae, object: goguryeo, from: 698, to: null }
- { type: occupied_by, subject: ungjin-dodokbu, object: tang, from: 660, to: 676 }
```

**점령지를 표시하려면**: 점령당한 지역을 따로 나라·지역 항목으로 만들고(`level: region`, 색은 옛 나라의 색), 그 지역의 영토를 그린 뒤 `occupied_by` 관계를 추가합니다. 점령한 나라의 영토에는 그 지역을 넣지 않습니다. 예: 웅진도독부(옛 백제 땅, 당이 점령), 안동도호부(옛 고구려 땅, 당이 점령). 일제강점기도 같은 방식입니다.

| type | 뜻 | 화면 |
|------|----|------|
| `successor_of` | subject가 object를 계승 | 사라진 나라를 선택하면 "후계 국가" 링크 |
| `occupied_by` | subject가 object에 점령·강점됨 | subject 색 위에 object 색으로 빗금. 패널에 "○○의 점령지" 표시 |
| `vassal_of` | subject가 object에 종속·간섭을 받음 | subject 테두리를 object 색으로 굵게. 패널에 "○○의 간섭·종속" 표시 |
| `part_of` | 지역이 나라에 속함 | (예정) 지역 단위 보기 |
| `claimed_by` | 귀속 논쟁: subject 지역을 object의 땅으로 보는 견해가 있음 | 후보 나라 색을 번갈아 빗금으로 칠함. 후보 나라를 고르면 선택 테두리에 이 지역도 포함 |

**귀속이 불확실한 지역을 표시하려면**: 그 지역을 따로 `level: region` 항목으로 만들고(예: `liaodong-disputed`), 영토를 그린 뒤 후보 나라마다 `claimed_by` 관계를 추가합니다. 후보 나라들의 영토에는 그 지역을 넣지 않습니다. 기간마다 후보가 바뀌면 관계의 `from`·`to`를 나눠 적습니다.

```yaml
- { type: claimed_by, subject: liaodong-disputed, object: balhae, from: 756, to: 925 }
- { type: claimed_by, subject: liaodong-disputed, object: tang, from: 756, to: 906 }
- { type: claimed_by, subject: liaodong-disputed, object: liao, from: 916, to: 925 }
```

후보 나라가 하나뿐이면(그 나라 땅인지, 어느 나라에도 속하지 않았는지가 갈리는 경우) 그 나라 색과 주인 없는 땅 색을 번갈아 칠합니다.

지금 있는 논쟁 지역: 압록강~청천강(만번한·패수 위치, 기원전 281~194), 영산강 유역(369~497), 섬진강 유역(475~512), 요동(756~925), 동북 9성 북쪽(1107~1108), 간도(1883~1908), 코소보(2008~), 크림(2014~), 러시아 점령 우크라이나 동부·남부(2022~). 유럽 현대의 분쟁·실효 지배 지역을 귀속 논쟁·점령 가운데 무엇으로 둘지는 `scripts/geo/areas/europe.mjs`의 '1992~현재 조각 소유표' 머리 주석의 기준을 따른다(2026-10-04).

## 5. 국경 그리기 (국경 생성기, QGIS)

> **지금 영토는 모두 국경 생성기가 만듭니다 (2026-09-28, 2026-09-29 권역별 파일로 나눔).** `data/geo/*.geojson`은 권역 파일(`scripts/geo/areas/<권역>.mjs`)의 이름 붙은 경계선을 조립한 결과이고, `npm run gen:geo`를 실행할 때마다 **통째로 지우고 다시 씁니다.** 영토를 고치거나 더할 때는 geojson이 아니라 그 나라가 든 권역 파일을 고친 뒤 `npm run gen:geo`를 실행하세요. 권역 파일은 `data/entities`의 같은 이름 YAML과 짝입니다(`china.mjs`만 `china-early.yaml`·`china.yaml` 두 파일과 짝이고, `korea.yaml`의 간도도 `china.mjs`에 있습니다). 구조와 규칙(층 규칙, 새 권역 더하기)은 [DESIGN.md](DESIGN.md) §5.2 5번에 있습니다.
>
> **생성기가 만들지 않는 geojson이 있으면 아무것도 지우지 않고 멈춥니다.** `data/geo`에 손으로 그린 파일이나 없앤 나라의 옛 파일이 있으면 `gen:geo`가 "data/geo에서 사라질 파일 N개" 오류로 멈춥니다(§6.1). 나라를 일부러 없애거나 id를 바꾼 경우에만 `npm run gen:geo -- --prune`으로 지우세요. **`--prune`은 손으로 그린 파일도 지웁니다.** QGIS로 그린 영토가 있으면 먼저 그 좌표를 권역 파일로 옮겨(§5.3) 생성기가 같은 이름의 파일을 만들게 한 뒤 `gen:geo`를 실행하세요. 그러면 그 파일은 생성기 결과로 덮어써지고 대조에도 걸리지 않습니다.
>
> 생성기에서 경계선을 곧게 그으면 만·반도·해협을 가로질러, 해안선으로 자를 때 선 반대편 해안이 본토와 떨어진 조각(월경지)으로 남습니다. 물을 건너는 선은 바다 쪽 점을 거쳐 돌리고, 이웃 나라끼리는 같은 선(상수)을 함께 쓰세요. 떨어진 조각은 `npm run check:exclaves`로 볼 수 있습니다(§6의 검증 메시지 참고).
>
> 생성기 파일(`scripts/generate-geo.mjs`, `scripts/geo/`)을 고친 뒤에는 `npm run check:generator`(생성기 구조와 안전장치 시험, 약 20초, `data/geo`는 건드리지 않음)도 돌리세요. 기존 나라의 geojson이 바뀌었는데 도형은 같아야 하는 경우(정리·옮기기)는 `npm run compare:geo`가 기간마다 대칭차 면적으로 확인해 줍니다. 유럽처럼 새 권역을 넣을 때의 순서와 행정구역 조각(`npm run check:fragments`)·근현대 국경 대조(`npm run compare:cshapes`)는 `docs/REGION_GUIDE.md`를 보세요.

QGIS([qgis.org](https://qgis.org/), 무료)는 이제 `data/geo`를 직접 고치는 데가 아니라, 새 경계선의 좌표를 따고 생성기 결과를 눈으로 확인하는 데 씁니다.

### 5.1 처음 한 번 준비 (QGIS)

1. **QGIS 설치 후 새 프로젝트**를 만들고 프로젝트 좌표계를 **EPSG:4326 (WGS 84)**로 둡니다 (오른쪽 아래 좌표계 표시).
2. **참고용 배경 지도**: 탐색기 패널 → XYZ Tiles → OpenStreetMap을 더블클릭합니다. 현대 지명과 해안선을 보며 좌표를 딸 수 있습니다.
3. **해안선 레이어** (선택): `npm run build:data`를 한 번 실행하면 생기는 `public/data/land-high.topo.json`을 레이어로 끌어다 놓습니다. 빌드에서 국경을 자를 때 쓰는 해안선(Natural Earth 1:50m)과 같은 것입니다.
4. **나라 레이어 열기**: `data/geo/` 안의 `.geojson` 파일들을 QGIS 창으로 끌어다 놓습니다. 이웃 나라 경계를 보며 새 선의 좌표를 딸 때 씁니다(이 파일들을 고쳐 저장하지는 않습니다).
5. **스냅 켜기** (좌표를 이웃 경계 꼭짓점에 정확히 맞출 때): 메뉴 프로젝트 → 스냅 옵션(Snapping Options)
   - 스냅 사용, 대상: **모든 레이어**, 종류: **꼭짓점과 선분**, 허용 오차: 10~12 픽셀
   - **추적(Tracing)** 켜기 (단축키 `T`): 이웃 나라 경계를 따라 클릭 몇 번으로 선을 그릴 수 있습니다. 그린 선은 임시 레이어에 두고 좌표만 권역 파일로 옮깁니다.

### 5.2 그릴 때 규칙

- **바다 쪽은 대충 그리세요.** 폴리곤을 해안선 바깥 바다까지 넉넉하게 잡으면(바다 쪽 점) 빌드가 Natural Earth 해안선에 맞춰 자동으로 자릅니다. 신경 쓸 곳은 **육지 위의 국경선**뿐입니다.
- **이웃 나라와는 경계를 공유하세요.** 맞닿는 곳은 같은 이름 붙은 선(상수)을 함께 쓰면(`ring(L_LIAO, …)`처럼) 틈이나 겹침이 생기지 않습니다. 좌표를 따로 되풀이해 적으면 한쪽만 고쳤을 때 어긋납니다. 두 권역 이상이 쓰는 선은 아래층에 둡니다: `scripts/geo/shared.mjs`에 두거나, `AREAS`에서 앞에 있는 권역 파일에 두고 export합니다(권역 파일은 앞 권역만 가져올 수 있음). 다른 파일의 좌표를 베껴 적으면 `npm run check:generator`가 '파일 사이 좌표 되풀이'로 실패합니다(바다 쪽 점처럼 맞물리지 않는 점만 허용 목록에 둠, DESIGN.md §5.2). 겹침이 5km²를 넘으면 빌드가 실패합니다.
- 섬이 여럿이면 한 버전의 도형을 여러 조각(멀티폴리곤)으로 만들어도 됩니다(`U([섬1], [섬2])`).

### 5.3 새 나라의 영토 만들기

1. 나라가 속한 권역 파일을 고릅니다. `data/entities`에서 그 나라를 적은 YAML과 짝인 `scripts/geo/areas/<권역>.mjs`입니다. 새 권역이 필요하면 DESIGN.md §5.2 5번 '새 권역 더하기'를 따릅니다.
2. 경계선과 도형을 상수로 둡니다. 이웃 나라와 맞닿는 곳은 이미 있는 이름 붙은 선을 쓰고, 새 선의 좌표는 QGIS에서 배경 지도·해안선·이웃 경계를 보며 땁니다(§5.1). 다른 권역 파일의 도형은 `scripts/geo/area-list.mjs`의 `AREAS`에서 앞에 있는 권역 것만 가져올 수 있습니다(층 규칙).
3. 권역 파일의 `versions`에 `'<새 id>': [[from, to, 도형, 확실성?]]`을 더합니다. 이 값들이 geojson feature의 속성이 됩니다.
4. `npm run gen:geo`를 실행하고 `npm run check:data`로 확인합니다. `git status data/geo`로 새 파일만 늘었는지 봅니다(기존 파일이 바뀌었으면 DESIGN.md §5.2 5번 '새 권역 더하기'의 4단계대로 확인합니다).

| 속성 | 값 | 권역 파일에서 정하는 곳 |
|------|----|----|
| `entityId` | 나라 id (파일 이름과 같음) | `versions`의 키 (예: `goguryeo`) |
| `from` | 이 국경이 시작되는 해 | 튜플의 첫째 값 (예: `600`) |
| `to` | 이 국경이 바뀌는 해 (미포함). 계속되면 `null` | 튜플의 둘째 값 (예: `668`) |
| `certainty` | `confirmed` / `estimated`(점선) / `disputed`(점선) | 튜플의 넷째 값. 없으면 `estimated` |
| `source` | 국경의 근거 자료 | 권역 파일의 `export const source = '…'` (권역마다 하나). 없으면 기본 문구 '중고등학교 한국사 교과서 시대별 지도의 일반적인 경계를 따른 대략적인 추정. 운영자 검수 필요'이고, 지금 권역은 모두 기본 문구 |

### 5.4 국경이 바뀐 시기 추가 (새 버전)

국경은 **바뀔 때만** 새 버전을 만듭니다. 다음 변화 전까지는 같은 국경이 유지됩니다.

1. 바뀐 모양을 도형으로 만듭니다. 이전 도형에서 합집합·차집합(`U`·`D`)으로 만들면 바뀌지 않은 경계가 그대로 이어집니다(예: `GORYEO_994 = U(GORYEO_936, [BAND_994])`).
2. `versions`의 그 나라 배열에서 **이전 버전의 `to`**와 **새 버전의 `from`**을 같은 해(국경이 바뀐 해)로 맞춥니다.
   - `[600, 671, 이전 도형]` → `[600, 671, 이전 도형], [671, 676, 새 도형]`
3. `npm run gen:geo`를 실행합니다.

### 5.5 QGIS에서 좌표를 딸 때 주의

- 좌표계는 반드시 **EPSG:4326**(경도, 위도)이어야 합니다. 다른 좌표계의 값을 옮기면 빌드가 "경위도 범위를 벗어난 좌표" 오류를 냅니다.
- 좌표는 소수 둘째~넷째 자리면 충분합니다. 생성기가 결과를 소수 넷째 자리(약 10m)로 반올림합니다.
- 폴리곤의 감긴 방향(시계/반시계)은 신경 쓰지 않아도 됩니다. 빌드가 알아서 맞춥니다.
- QGIS에서 geojson을 따로 저장해 둘 때는 `data/geo` 밖에 두세요. `data/geo`에 두면 `gen:geo`가 생성기 밖 파일로 보고 멈춥니다(위 안내).

## 5.6 전쟁 추가 (`data/wars/*.yaml`)

연 단위 지도로는 보이지 않는 전쟁 중의 변화를 날짜별로 적습니다. 사용자는 지도의 전쟁 표시나 사건 패널에서 "전쟁 보기"를 열어 봅니다. 예시는 `data/wars/korean-war.yaml`(6·25 전쟁)을 보세요.

```yaml
id: korean-war
name: 6·25 전쟁
factions:                       # 진영: 지도에서 한 색으로 칠하는 편 (둘 이상)
  - { id: north, name: 북한군·중국군, entity: dprk }        # entity: 색·이름표에 쓸 대표 나라
  - { id: south, name: 국군·유엔군, entity: rok, color: "#3e8ab8" }   # color는 선택
participants:                   # 참전국 (편을 바꾼 나라는 기간을 나눠 두 번)
  - { entity: prc, faction: north, from: 1950-10-19 }
sources: ["국방부 군사편찬연구소 『6·25 전쟁사』"]
theaters:                       # 전역: 동시에 여러 곳에서 싸웠으면 나눈다 (예: 유럽, 태평양)
  - id: korea
    name: 한반도
    replaces: [rok, dprk]       # 전쟁 보기에서 영토 대신 점령 지역으로 칠할 나라
    marker: [127.3, 38.0]       # 평소 지도의 전쟁 표시 위치 (선택)
    snapshots:
      - date: 1950-06-25
        title: 북한군 남침
        summary: 설명
        split: { line: [[123.6, 38.0], [130.5, 38.0]], north: north, south: south }
        areas:
          - { faction: north, entities: [some-country] }       # 그 나라의 그 해 영토 전체
          - { faction: south, geojson: korean-war/pusan.geojson } # QGIS로 그린 폴리곤
        arrows:
          - { faction: north, path: [[126.7, 38.2], [126.97, 37.62]], label: 서울 방면 }
```

점령 지역을 적는 방법은 세 가지이고 섞어 써도 됩니다. 뒤에 적은 것이 앞의 것을 덮습니다.
1. **선으로 가르기(`split`)**: 전선 하나가 움직이는 전쟁에 편합니다. 선은 **서쪽 바다에서 시작해 동쪽 바다에서 끝나게** 긋습니다. 선의 북·서쪽이 `north` 진영입니다(남해안에서 시작하는 선도 같은 규칙). 전역의 `replaces` 나라 영토를 나눕니다.
2. **나라 영토(`entities`)**: "그 나라 전체가 점령됨"일 때 씁니다.
3. **직접 그리기(`geojson`)**: 흩어진 점령지를 QGIS에서 폴리곤으로 그려 `data/wars/` 아래에 GeoJSON(EPSG:4326)으로 저장합니다. 바다까지 대충 그려도 빌드가 해안선으로 자릅니다.

**진군 경로·전투·거점** (전역 또는 스냅샷에 추가):

```yaml
theaters:
  - id: korea
    routes:                     # 진군 경로: 날짜가 있는 지점까지를 "지나온 길"로 그림
      - name: 유엔군 서부 진격로
        faction: south
        points:
          - { at: [126.62, 37.47], date: 1950-09-15, label: 인천 상륙 }
          - { at: [125.75, 39.02], date: 1950-10-19, label: 평양 }
    battles:                    # 전투: 그 날짜부터 표시. winner·summary는 선택
      - { name: 인천 상륙 작전, at: [126.62, 37.47], date: 1950-09-15, winner: south, summary: 설명 }
    snapshots:
      - date: ...
        holds:                  # 거점: 그 시점의 도시·요새 소속 (도시 국가 동맹 등)
          - { name: 아테네, at: [23.73, 37.98], faction: delian }
```

관련 사건에 `front: { war: 전쟁 id, theater: 전역 id, date: 날짜 }`를 붙이면 사건에서 그 날짜의 전쟁 보기로 들어갈 수 있습니다(전역이 하나면 theater 생략).

**날짜**: `YYYY-MM-DD`. 기록에 날이 없으면 `00`으로 적습니다(`612-07-00` → "612.7", 달도 없으면 `927-00-00` → "927"). 전근대 전쟁은 사료를 따라 음력으로 적고, 전쟁 이름에 "(날짜는 음력)"을 붙입니다.

검증 메시지:
- `전쟁 ...: ...에 없는 나라 'id'` / `없는 진영 'id'` → 나라 id나 진영 id를 확인하세요.
- `스냅샷이 날짜 순서대로가 아님` → 전역 안의 스냅샷을 날짜 순서로 적으세요.
- `split은 전역의 replaces 나라 영토를 나누므로 replaces가 필요함` → 전역에 `replaces`를 적으세요.
- `점령 지역이 비어 있음` → 그 해에 그 나라 영토가 없거나, GeoJSON이 육지와 겹치지 않습니다.
- `사건 ...: ...에 날짜 스냅샷이 없음` → 사건의 `front.date`가 스냅샷 날짜와 정확히 같아야 합니다.

## 6. 검증 메시지 읽는 법

`npm run check:data`는 문제가 있으면 **오류**(빌드 실패)와 **경고**(빌드는 됨)를 보여 줍니다.

| 메시지 | 원인 | 해결 |
|--------|------|------|
| `YAML 문법 오류` | 들여쓰기, 따옴표, 한 줄 형식 안의 쉼표 | §2의 쉼표 규칙 확인 |
| `쉼표 때문에 글이 잘림` | `{ ... }` 한 줄 형식 안의 따옴표 없는 글에 쉼표가 있어, 쉼표 뒤가 따로 읽힘 (문법 오류는 안 나지만 화면에는 쉼표 앞까지만 나옴. 예: "3,800여 명" → "3") | 그 글 전체를 큰따옴표로 감싸기 |
| `수록 근거(refs)가 비어 있음` | 나라의 `basis.refs` 없음 | 사료나 기관 자료 적기 |
| `'xxx'는 N년에 존재하지 않음`, `'xxx'는 사건 기간 N~M년에 존재하지 않음` | 사건 기간과 존재 기간이 겹치지 않는 나라를 참조 | 나라의 `from`/`to` 또는 사건의 `year`/`endYear` 확인 |
| `영토 기간 [...]이 xxx의 존속 기간 ...을 벗어남` | 영토 버전이 나라 존속 기간 밖 | 영토 `to`는 "바뀌는 해"(미포함)라는 점 확인 |
| `영토 기간이 앞 버전과 겹침` | 같은 나라의 두 버전 기간이 겹침 | 이전 버전 `to`와 새 버전 `from`을 같은 해로 |
| `A와 B의 영토가 약 N km² 겹침` | 이웃 나라 폴리곤이 겹침 | 권역 파일에서 이웃과 같은 이름 붙은 선을 함께 쓰기 (§5.2) |
| `경위도 범위를 벗어난 좌표` | 좌표계가 EPSG:4326이 아님 | §5.5 |
| `해안선으로 자르고 나니 육지가 남지 않음` | 폴리곤이 전부 바다 위 | 위치 확인 |
| 경고 `월경지: … 허용 목록에 없음` | 같은 육지 위에서 본토와 떨어진 영토 조각(30km² 이상) | 대개 생성기의 직선 경계가 만·반도를 가로지른 부산물이므로 생성기 경계를 고친다. 역사적으로 실제 떨어져 있던 영토라면 `data/exclaves.yaml`에 위치와 근거를 적는다 |
| 경고 `data/exclaves.yaml: …에 맞는 떨어진 조각이 없음` | 허용 목록 항목이 가리키는 조각이 사라짐 | 도형이 바뀌었으면 그 항목을 지운다 |
| 경고 `N~M년 영토 없음` | 영토 버전 사이에 빈 기간 | 의도한 것이 아니면 기간 이어 붙이기 |
| 경고 `영토 데이터가 없어 화살표를 그릴 수 없음` | 사건 links의 나라에 영토가 하나도 없음 | 그 나라의 영토 추가 |

### 6.1 `npm run gen:geo`가 멈출 때

국경 생성기는 아래 경우에 `data/geo`를 **지우기 전에** 멈춥니다. 멈췄을 때 `data/geo`는 그대로입니다.

| 메시지 | 원인 | 해결 |
|--------|------|------|
| `data/geo에서 사라질 파일 N개: …` | 이번에 만들지 않는 geojson이 `data/geo`에 있음 (없앤 나라·id를 바꾼 나라의 옛 파일, 손으로 그린 파일, 권역 파일째 빠짐) | 일부러 없앤 나라면 `npm run gen:geo -- --prune`(가운데 `--`를 빠뜨리면 npm이 `--prune`을 가져가 같은 오류가 다시 남). 손으로 그린 파일이면 먼저 권역 파일로 옮김(`--prune`은 그 파일도 지움). 뜻밖이면 권역 파일의 import와 `AREAS` 등록 확인 |

## 7. 제보 반영

GitHub Issue의 "역사 데이터 제보" 양식으로 들어온 제보는 다음 순서로 반영합니다 (DESIGN.md §11.2).

1. 제보의 **증거 사료를 직접 확인**합니다. 사료가 없거나 확인되지 않으면 반영하지 않습니다.
2. 제보자의 문장을 복사하지 않고 **직접 새로 작성**합니다. 모든 데이터의 저작권을 운영자 한 명에게 두기 위해서입니다.
3. 사료를 `sources`(사건) 또는 `source`(영토)에 적습니다.
4. 제보자가 원하면 [CREDITS.md](../CREDITS.md)에 기록합니다.
